uv 0.12.0 默认为新项目启用 uv_build 构建系统

新闻时间: 2026-07-29T04:27:46.872737+00:00 · 来源: github

Python 工具链迎来一次务实升级：uv 0.12.0（发布于 2026 年 7 月 28 日）现在默认为新建项目启用完整的构建系统——使用其原生构建后端 uv_build。这一调整并非临时功能，而是对多年简化策略的主动回归：早期版本曾默认启用构建系统，后因新手困惑而移除；如今 uv_build 已稳定且深度优化，团队重新将其设为标准起点。新项目自动采用 src/ 目录结构、生成含 [build-system] 的 pyproject.toml，并注册可执行脚本入口，使项目开箱即支持安装、导入和 uv run 运行。

此举背后是 uv_build 的正式成熟——今年 4 月已被宣布为稳定版，基准测试显示其构建速度比 hatchling、setuptools 等快 10 至 35 倍。它专为与 uv 的解析器和安装器协同设计，避免重复解析依赖，显著提升端到端效率。尽管标记为“破坏性变更”，但所有已有项目不受影响；若仍需旧式无构建系统布局，只需添加 --no-package 参数即可。

本次更新还强化了安全与规范兼容性。uv 现在严格遵循 PEP 625，仅接受 .tar.gz 格式的源码分发包，拒绝 .tar.bz2 和 .tar.xz；轮子包（wheel）也不再支持 bzip2、LZMA 或 XZ 压缩方式，仅允许未压缩、DEFLATE 或 zstd。这些限制精简了底层压缩依赖，降低了处理不可信包时的安全风险。此外，uv 现在全面拦截所有大小写变体的 python 入口点（如 Python、PYTHON），防止在 macOS 和 Windows 等不区分大小写的文件系统上意外覆盖虚拟环境中的解释器。

整个发布体现成熟工程实践：每个破坏性变更都附带明确迁移指引，绝大多数用户无需修改即可升级，文档详尽且配置建议具体（例如将 pyproject.toml 中的 uv_build 版本上限更新为 <0.13）。没有已知重大行为退化。
