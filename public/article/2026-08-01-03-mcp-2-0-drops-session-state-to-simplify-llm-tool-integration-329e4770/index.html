MCP 2.0取消会话状态，简化大模型工具集成

新闻时间: 2026-08-01T04:33:02.137201+00:00 · 来源: rss

2026年7月31日，知名开发者西蒙·威利森（Simon Willison）宣布“无状态MCP日”，正式推出MCP 2.0——这是自2024年11月Anthropic首次发布Model Context Protocol（模型上下文协议）以来的首个重大升级。新版彻底摒弃了原有需维护会话状态的设计，转而采用纯无状态HTTP接口，显著降低了客户端与服务端的实现复杂度。威利森曾因Anthropic在2025年底推出的替代方案“Skills”而暂时淡出MCP生态；此次更新却让他重新燃起兴趣，并迅速投入实践。

无状态设计直击实际痛点。旧版MCP要求两次HTTP请求：先调用initialize获取Mcp-Session-Id，再携带该ID发起工具调用。这种模式带来运维负担——需服务器端存储会话、限制负载均衡策略、增加分布式部署难度。而MCP 2.0将全部信息压缩进单次请求：通过MCP-Protocol-Version、Mcp-Method等自定义HTTP头传递协议元数据，并将客户端信息（如名称与版本）嵌入JSON-RPC体内的_meta字段中。

这一精简已快速落地为真实工具。威利森在规范发布后数日内即构建了三个MCP 2.0实现，包括命令行工具mcp-explorer（用于交互式探测MCP服务端）和datasette-mcp（将Datasette数据库界面封装为MCP工具）。这些项目印证了新协议的易用性：开发者无需管理会话、持久化状态或协调后端集群，即可安全暴露工具能力。

此次演进也呼应了行业对AI代理安全性的再思考。威利森指出，赋予代理无约束的终端与网络访问权限虽曾被视为更灵活的替代方案，但存在严重风险——尤其当模型能力有限或部署环境受限时。相较之下，MCP工具边界清晰、行为可审计、调用可预测，更适合笔记本电脑本地运行或合规敏感场景。MCP 2.0并未堆砌新功能，而是通过删减冗余，让协议真正迈向可用、可扩、可管的生产级基础设施。
