Celld让Cloudflare风格的持久对象可在本地部署

新闻时间: 2026-08-06T04:28:17.718402+00:00 · 来源: hackernews

Celld 是 Deno 团队推出的一个全新开源项目，它让开发者无需依赖 Cloudflare 基础设施，即可在自有环境中运行“持久对象”（Durable Objects）——一种将计算与存储深度整合的强状态化无服务器抽象。与 Cloudflare Workers 的 Durable Objects 不同，后者深度绑定于 Cloudflare 全球边缘网络和专有运行时，Celld 则提供了一种可自托管、可分布式部署的替代方案。它支持标准基础设施：可通过 Docker 运行、用一键脚本安装，或集成进企业自有 K8s 或裸机集群。每个 Celld 节点内嵌 V8 引擎，原生执行 Wrangler 编译后的代码包；整个节点集群则通过你自主控制的 S3 兼容对象存储（如 MinIO 或 AWS S3）协同管理部署包、对象状态及轻量级归属记录。

持久对象本身是单实例、带状态的服务单元，将计算逻辑与数据存储封装为一个按名称寻址的独立实体。可将其理解为轻量级的“持久化 Actor”：每个对象拥有专属隔离状态（例如内置 SQLite 数据库），通过唯一名称标识，并以串行方式处理请求，天然规避并发冲突。Cloudflare 首创该模型，用于支撑实时协作、聊天后端、游戏会话等高一致性场景。但此前，这一强大范式始终被锁定在 Cloudflare 的封闭平台中。

Celld 打破了这一限制。它将持久对象的编程模型从 Cloudflare 基础设施中解耦，使企业得以在私有云、离线环境、混合云乃至去中心化网络中部署该范式。开发者可复用现有 Workers 和 Durable Objects 代码（几乎无需修改），同时完全掌控数据位置与运行时生命周期。其架构刻意精简：不引入新语言、不定义新 API，仅用通用组件忠实还原核心 DO 协议语义。

社区反响热烈。开发者普遍赞赏其设计清晰与落地价值：有人已用它重构了原先基于 Cloudflare 的芒果品鉴活动应用；另一些人指出，它为跨去中心化节点构建可靠状态提供了关键基础设施。值得注意的是，项目维护者主动关闭了 GitHub PR 功能——并非排斥贡献，而是为保障代码质量：要求提交者深入理解代码、保持补丁聚焦，并以 git format-patch 方式发送带完整上下文的补丁，尊重维护者评审时间。这种工程自律性，在早期基础设施项目中尤为难得。
