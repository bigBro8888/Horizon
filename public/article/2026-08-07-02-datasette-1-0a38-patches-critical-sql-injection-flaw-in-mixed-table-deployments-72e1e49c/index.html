Datasette 1.0a38 修复混合公私表部署中的关键SQL注入漏洞

新闻时间: 2026-08-07T04:02:59.276479+00:00 · 来源: rss

开源数据探索工具 Datasette 已发布 1.0a38 版本，紧急修复一个关键安全漏洞。该漏洞允许任何拥有公共表访问权限的用户，绕过权限控制，读取同一 SQLite 数据库中本应受保护的私有表数据——即使管理员已明确禁用了 execute-sql 权限。

这一漏洞源于 Datasette 在处理多表环境下的 SQL 查询时，对表名的校验机制存在缺陷。当一个数据库文件中同时包含公表和私表，并依赖 Datasette 内置权限系统进行访问控制时，攻击者可通过构造恶意 SQL 查询（例如 SELECT * FROM private_table）绕过校验，直接访问未授权的私有数据。

本次修复强化了 SQL 解析阶段的输入验证逻辑，确保原始 SQL 查询中引用的表名必须属于当前用户被明确授权访问的范围。值得注意的是，该补丁也同步回溯至稳定分支，以 Datasette 0.65.3 版本发布，方便尚未升级到 1.0 alpha 系列的用户及时修复风险。对于采用混合访问模式的部署方，尤其是依赖原生权限模型且未叠加额外认证插件的场景，强烈建议立即升级。

尽管将公私表共存于单个数据库并启用权限控制的配置在现实中较为少见，但一旦存在，便可能危及内部数据看板或混合型数据门户的安全。项目作者 Simon Willison 表示，他本人尚未在实际部署中发现此类用例，但仍强调该漏洞利用门槛极低：仅需对任意一张公共表具备基础读取权限即可触发。

对绝大多数用户而言——无论是完全公开、完全私有，还是通过 datasette-auth-passwords 等插件增强认证的部署——此漏洞影响有限。但此次事件再次提醒我们：在强调易用性与快速上线的工具中，权限逻辑的细微偏差，可能带来远超预期的安全后果。
