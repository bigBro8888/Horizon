DuckDB v2.0预览版发布：Quack查询引擎与高效VARIANT类型上线

新闻时间: 2026-08-18T02:20:11.644320+00:00 · 来源: hackernews

DuckDB v2.0 不只是一次常规升级，而是对嵌入式分析数据库能力边界的系统性拓展。8月17日发布的预览版带来了三项核心改进：Quack 查询引擎、深度优化的 VARIANT 半结构化数据类型，以及显著增强的内存外（out-of-core）扩展能力。这三者共同作用，让 DuckDB 在保持轻量嵌入特性的同时，开始承担起传统云数仓级别的分析任务。

Quack 是本次更新中最具突破性的组件。它并非简单叠加的客户端-服务器层，而是一个基于 HTTP 的轻量远程协议——关键在于，每个 Quack 客户端本身就是一个完整 DuckDB 引擎。这意味着一条 SQL 查询能原生跨本地文件与远程 DuckLake 表进行联合规划与执行，支持真正的多写入者并发访问。已有用户用它实现 Jupyter 笔记本间查询转发，甚至让浏览器标签页直连 DuckDB 服务端执行分析。

VARIANT 类型早在 v1.5 中就已引入，v2.0 对其进行了根本性优化。它现在能自动识别杂乱 JSON 数据（如日志、API 响应）中的重复结构模式，并将字段“解构”为列式存储，像原生类型一样高效压缩和检索。相比纯文本 JSON，它避免了空间浪费与解析开销，同时完整保留时间戳、地理空间对象、嵌套数组等所有 DuckDB 原生类型语义。实际用户反馈，在混合 Schema 的 Parquet 文件中，存储体积可减少达 5 倍。

更值得关注的是 v2.0 对生产环境的支持强化。多家公司的工程师已将其用于实时分析流水线、dbt 模型转换和流处理后端——甚至直接运行在消费级笔记本上。这得益于新版本对大中间结果的智能磁盘溢出（spill-to-disk）能力，既不崩溃也不明显降速。正如一位开发者所言：“它不再只是探索工具，而是我的运行时数据库。”这种转变印证了一个趋势：分析引擎正朝着统一、可嵌入、可扩展的方向融合，而 DuckDB 正站在这一演进的前沿。
