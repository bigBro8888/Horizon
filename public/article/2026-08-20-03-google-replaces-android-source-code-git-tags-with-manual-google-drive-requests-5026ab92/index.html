谷歌用人工表单+网盘链接取代Android源码Git标签

新闻时间: 2026-08-20T02:21:36.684463+00:00 · 来源: hackernews

谷歌已悄然更改部分Android开源组件的获取方式：不再发布标准化、自动化的Git标签——这是业界标记和检索特定软件版本的通用方法，而是要求用户提交谷歌表单，并等待人工发送一个谷歌网盘链接。这一变动影响了Android开源项目（AOSP）中部分采用GPLv2许可证的代码，例如此前通过公共Git仓库发布的内核模块和固件二进制文件。

该变更严重削弱了开源许可的核心原则。根据GPLv2条款，任何分发GPL许可软件的实体，都必须以与目标代码同等便利的方式提供对应源代码——即源码须可即时获取、可复现、可机器处理。Git标签正满足这一要求：它支持确定性、可脚本化、可验证地获取精确的源码快照。而人工表单加邮件分发的方式则引入延迟、不一致、不可审计，且无法保证及时或完整交付。

这并非谷歌首次偏离开源规范。长期以来，AOSP本就仅是“有限开放”：核心框架虽公开，但关键驱动、固件及硬件抽象层往往闭源或设限。然而，Git标签机制曾是少数可靠、自动化的GPLv2合规通道之一，尤其对GrapheneOS等下游操作系统项目、安全研究人员及合规审计方至关重要。以不透明、中心化、不可扩展的流程取而代之，引发了关于合规意图的严肃质疑。

批评者指出，新流程已在实践中失效：已有报告称响应迟缓、回复不一致，且无公开服务等级协议（SLA）或进度追踪。正如一位评论者调侃：“再过几年，他们大概会把源码打印出来寄给你。”尽管谷歌未公开说明变更原因，业内猜测可能涉及内部工具迁移、工程资源缩减或加强分发管控——但这些理由均不能豁免GPLv2合规义务。对整个生态而言，此举损害了企业开源治理的公信力，并为其他厂商开了危险先例。

归根结底，这不仅关乎便利性，更关乎‘开源’是否仍意味着法律上可强制执行的访问权。一旦源码分发从自动变为随意，copyleft许可的承诺便名存实亡。
