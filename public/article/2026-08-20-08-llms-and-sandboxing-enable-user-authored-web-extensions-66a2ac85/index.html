大语言模型与沙箱技术让普通用户也能安全开发网页扩展

新闻时间: 2026-08-20T02:21:36.402141+00:00 · 来源: rss

杰里米·莫雷尔（Jeremy Morrell）近期撰文提出一个极具启发性的构想：可扩展的网页应用不应再局限于开发者编写的插件，而应成为一种由用户驱动、AI辅助、且建立在坚实安全基础之上的新范式。其核心观点简洁却深刻：当前大语言模型（LLM）极大降低了编写可用代码的门槛；与此同时，浏览器与服务端沙箱技术——如 WebAssembly 模块、SES（Secure EcmaScript）以及 Linux 的 seccomp——已能为代码提供严格、可预测的执行边界。二者结合，催生了一种新型软件架构：一个精简、可审计的应用核心，搭配用户自主生成、受控运行的扩展功能。

这远不止是便利性提升，更是对用户自主权的重新定义。过去，扩展软件意味着用特定语言编码、编译、通过安全审核，并等待厂商发布。如今，用户只需用自然语言描述需求——例如“高亮日历视图中的所有截止日期”——LLM 即可生成一段轻量级、沙箱隔离的扩展脚本，仅在其个人会话中运行，无法访问密码或其他标签页。主应用保持稳定与可追溯，用户获得灵活性，安全却不打折扣。

支撑这一愿景的技术正快速走向成熟。浏览器已支持更精细的执行环境控制，包括 iframe 的 sandbox 属性、权限受限的 Web Workers，以及实验性特性如 Trusted Types 和 Policy Containers。服务端方面，Figma 等平台已将服务端沙箱用于隔离不可信代码执行。此外，基于 Rust 的沙箱方案（如利用 seccomp 和 Landlock 进行系统调用过滤）也证明，即使是原生二进制程序亦可被细粒度约束。这些并非纸上谈兵，而是已被主流平台投入实际使用的安全原语。

莫雷尔构想之所以切中当下要害，在于它直面真实困境：用户渴望定制化，却担忧第三方扩展的隐蔽风险；开发者追求灵活性，又畏惧复杂性与安全责任。通过将可信核心与生成式外围解耦，该模式走出一条中间道路——可扩展性不再以牺牲安全性或可维护性为代价。它并非取代开发者，而是赋予用户按自身工作流重塑工具的能力。
