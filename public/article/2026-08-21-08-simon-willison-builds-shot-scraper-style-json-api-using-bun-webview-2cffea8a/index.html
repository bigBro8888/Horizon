Simon Willison 用 Bun.WebView 实现类似 shot-scraper 的 JSON API

新闻时间: 2026-08-21T02:36:16.449288+00:00 · 来源: rss

Simon Willison 发布了一个可运行的原型：一个轻量级 Web JSON API，能加载网页并在浏览器环境中执行任意 JavaScript — 全部基于 Bun 1.4 新稳定发布的 Bun.WebView API。该项目托管于他的研究仓库中，功能上直接复刻了他广受欢迎的命令行工具 shot-scraper — 后者传统上通过无头浏览器截屏或执行 JS 提取数据 — 但这次被重构为具备清晰 JSON 输入/输出的 HTTP 服务。

这不仅是个概念验证：Willison 在真实场景下部署并压力测试了该服务，使用 Linux 的 cgroups 工具精确测量内存占用。结果显示，当驱动完整 Chromium 实例渲染和交互复杂现代网页时，服务内存消耗稳定在 192 MB 至 256 MB 之间 — 这一数据为开发者评估 Bun.WebView 的生产可用性提供了关键参考。值得一提的是，他借助 Claude Code 辅助生成了初始 TypeScript 实现，印证了 AI 编程正加速推动对新型运行时特性的探索。

Bun 1.4 的发布是一次重要里程碑：这是 Bun 从 Zig 重写为 Rust 后首个稳定版本 — 尽管官方更新日志淡化了这一转变，但 Willison 此前已详细报道过此事。虽然更新日志强调了超 2900 个缺陷修复及显著性能提升（Linux 下空闲 CPU 降低 5 倍、内存减少最多 35%、启动快 50%），但 Bun.WebView 无疑是其中最具变革性的新 API。它提供原生跨平台浏览器自动化能力：macOS 使用系统 WKWebView，Linux 和 Windows 则通过 Chrome DevTools 协议控制本地 Chromium — 无需安装额外依赖或 Docker 层。

与依赖 Puppeteer 或 Playwright 的传统爬虫工具不同，这种 Bun 原生方案消除了进程启动开销，大幅简化部署。开发者现在可将浏览器自动化能力直接嵌入 Bun 服务器 — 特别适合动态渲染、客户端 JS 执行或实时 DOM 分析等场景。Willison 的 API 设计直面实际约束：接收 URL 和可选 JS 代码，以 JSON 返回序列化的 DOM 状态或脚本结果，并避免持久化会话以确保内存可控 — 这使其在 Serverless 或容器化环境中尤为实用。
