repo2nb 0.2.0发布：支持依赖解析、反向重建与增量同步

新闻时间: 2026-08-22T02:20:09.072287+00:00 · 来源: reddit

repo2nb 0.2.0 是一款开源命令行工具的重要更新，专为打通 GitHub 代码仓库与 Kaggle、Google Colab 等交互式笔记本环境而设计。当复现他人发表的机器学习论文代码、教程或实验时，手动复制文件、安装依赖、调整目录结构往往既耗时又容易出错；而该工具现在能全自动完成整个转换流程：遍历仓库文件树、智能解析依赖关系，并生成可直接运行的笔记本，其中包含清晰的环境配置单元格和可执行代码。

0.2.0 版本引入三项关键能力：智能依赖解析、反向重建模式与单向增量同步。依赖解析器按优先级依次尝试 Poetry 的导出功能、uv 工具、requirements.txt 文件，最后回退到基于抽象语法树（AST）的静态导入扫描——前提是仓库中没有提供任何锁文件或清单文件。重要的是，无论采用哪条路径，最终输出始终是标准的 %pip install 单元格：这意味着 Poetry 或 uv 仅在本地生成笔记本时需要，Kaggle 或 Colab 运行时完全无需它们，从而保障了笔记本的可移植性与环境无关性。

新增的反向模式（repo2nb reverse <notebook>）支持从生成的笔记本还原原始代码仓库。每个代码单元格都嵌入了元数据，包括原始文件路径与内容哈希值，使 repo2nb 能精准重建目录结构与全部源码。安全机制也已强化：默认禁止向非空目录写入，除非显式指定 --force 参数。而增量同步（repo2nb sync <repo>）则支持轻量级更新——新增文件自动转为新单元格，修改过的文件原位更新，删除的文件则从笔记本中移除；所有变更均可通过 --dry-run 预览。

此外，新版还增加了对 Colab 的专属支持，内置使用 google.colab.userdata.get 的认证单元格，不再复用 Kaggle 的密钥管理流程。安装方式保持简洁：pip install repo2nb。项目托管于 GitHub，开发者特别欢迎用户反馈——尤其是当前依赖解析的回退顺序是否贴合真实项目中的常见配置。
