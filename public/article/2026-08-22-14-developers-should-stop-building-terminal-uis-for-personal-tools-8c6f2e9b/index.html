开发者该停止为个人工具开发终端界面了

新闻时间: 2026-08-22T02:20:08.251277+00:00 · 来源: rss

西蒙·威利森（Simon Willison）在2026年8月发布的博客文章《停止开发终端界面》呼应了开发者工具圈内日益增强的一种共识：曾作为快速个人命令行工具默认选择的终端用户界面（TUI），如今已不再是务实之选。他援引托马斯·普塔切克（Thomas Ptacek）早先的文章指出，得益于 SwiftUI 等现代原生框架以及 AI 编程助手能力的飞速提升，构建一个轻量、可用的原生图形界面（GUI）所需的时间和精力已近乎为零。

威利森以自身实践佐证这一观点。今年3月，他用 SwiftUI 开发了两款 macOS 菜单栏小应用：一个实时监控 GPU 使用率，另一个以“氛围编码”（vibe-coding）为概念追踪编程专注状态。两者功能单一，却完全原生运行，无缝支持深色模式、菜单栏弹窗等系统级交互，并已融入他的日常开发流。关键在于，他并未依赖深厚的 macOS 开发经验或数月工期，而是借助 AI 辅助迭代与 SwiftUI 的声明式语法，快速交付了真正可用的界面。

这一主张并非否定 TUI 在所有场景的价值——远程运维、服务器工具或无图形环境仍离不开它。其真正针对的是“个人本地工具”：那些你本打算写成 Bash 或 Python 脚本、在终端里串接使用的轻量工具。普塔切克强调，对这类工具，直接跳过 TUI、构建原生 GUI 反而能消除自我使用障碍，带来即开即用的可发现性、可视化反馈、拖放操作及开箱即用的无障碍支持。正如威利森所言：“我尚未习惯为其他项目 routinely 构建真实 UI，但我的借口正迅速耗尽！”

这一转向背后，是开发者工具链的整体演进。SwiftUI（macOS/iOS）、Tauri（跨平台桌面）等框架大幅降低了原生 GUI 开发门槛；而大语言模型驱动的编程助手则填补知识断层——自动生成模板、排查布局问题、推荐平台规范。最终产出的并非企业级精雕细琢的应用，而是“够用就好”的原生界面：它们响应迅速、体验一致，并自然地存在于你的 Dock 栏中，而非蜷缩在某个终端标签页里。
