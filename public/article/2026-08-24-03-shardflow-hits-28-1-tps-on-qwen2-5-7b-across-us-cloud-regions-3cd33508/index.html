ShardFlow跨美国云区域实现Qwen2.5-7B 28.1 TPS

新闻时间: 2026-08-24T02:36:12.545704+00:00 · 来源: reddit

一款名为 ShardFlow 的新开源框架，在广域网（WAN）高延迟环境下实现了分布式大语言模型（LLM）推理的突破性性能。在最近一次基准测试中，它在 Qwen2.5-7B 模型上跨两个地理分离的 Google Cloud Platform（GCP）区域（爱荷华州与俄勒冈州）达成峰值 28.10 tokens per second（TPS）吞吐量。两地间通信经由位于俄亥俄州的 AWS EC2 TCP 中继节点走公网传输，实测往返时延（RTT）达 86 毫秒——这正模拟了真实多云或边缘-云协同部署中无法使用专用低延迟网络的典型场景。

该成果的核心在于神经推测解码（neural speculative decoding）与 CUDA Graphs 的深度协同。推测解码让一个轻量“起草模型”预先生成 K=8 个候选词元，主模型再批量验证。相比传统逐词等待模式（每个词元都受 86ms RTT 拖累），系统将网络延迟摊薄至每轮（draft-and-verify round）一次，从而将吞吐量提升超五倍——远超非推测式基线的 4.92 TPS。

CUDA Graphs 带来了另一项关键加速，尤其对起草模型效果显著。早期分析发现：Python 循环驱动的内核调用严重拖慢 GPU 利用率——每轮触发约 1500 个 CUDA 内核，单次启动耗时 2–5 微秒，加上 Python 层 8–10 微秒开销，GPU 高达 65% 时间处于空闲。通过将整个 5 亿参数前向传播过程封装为单一静态 CUDA Graph，并以一次驱动调用重放，起草延迟从 112ms 锐减至 25ms。其他优化还包括零拷贝 Rust TCP 中继、支持图兼容的 StaticCache 与原地 KV 缓存回滚、以及元设备模型切片（避免将 15GB 模型全量加载至 CPU 内存）。

ShardFlow 同样适用于更大模型：在相同双节点 WAN 架构下，Qwen2.5-14B 经 NF4 4 位量化后仍稳定输出 14.43 TPS 平均吞吐。项目完全开源，代码与详细基准已发布于 GitHub。其设计直面真实生产约束，而非理想化实验室条件，为构建全球分布式 LLM 服务的工程师提供了稀缺且极具参考价值的实践范本。
