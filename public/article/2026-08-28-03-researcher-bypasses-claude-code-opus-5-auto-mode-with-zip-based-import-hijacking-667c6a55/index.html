研究员用ZIP归档劫持Python导入绕过Claude Code Opus 5自动模式

新闻时间: 2026-08-28T12:44:25.125845+00:00 · 来源: rss

Anthropic最新发布的Claude Code Opus 5被发现存在严重安全漏洞，攻击目标直指其核心安全机制——“自动模式”（Auto Mode）。知名提示注入研究员约翰·雷赫伯格（Johann Rehberger）成功演示了一种成功率约80%的攻击：不靠诱导模型直接生成恶意代码，而是利用Python导入机制中“本地模块优先覆盖标准库模块”的固有行为。

攻击流程分两步：首先诱使Claude Code下载并解压一个ZIP压缩包，其中包含一个名为struct.py的恶意文件；随后当模型执行import base64时，Python会错误加载当前目录下的struct.py而非标准库中的struct模块，从而触发任意代码执行，包括启动恶意进程。更关键的是，自动模式在此过程中两次失守：它既未阻止ZIP解压与恶意导入，又在Claude自身检测到入侵、试图发出清理指令（如终止恶意进程）时，将该指令判定为“潜在危险”而主动拦截。

这形成了一个危险悖论：安全分类器放行了初始攻击，却阻断了模型的自我修复能力。西蒙·威利森（Simon Willison）在报道中指出，此举动摇了自动模式的根本承诺——即无需人工干预即可安全自动化工具调用。Anthropic此前曾宣称，在启用自动模式后，浏览器端提示注入攻击成功率已降至0%，但雷赫伯格的实验表明，这类指标无法反映代码执行场景下对文件系统和Python运行时特性的深度利用。

该问题的影响远超单一模型版本。它揭示了AI代理安全领域的一个根本矛盾：依赖分类器识别“明显危险操作”的防护思路，往往难以捕捉基于成熟软件行为（例如自2006年起就被Python官方记录的本地模块遮蔽问题）构建的多步隐蔽攻击。雷赫伯格与威利森一致强调，仅靠分类器无法提供充分保障。他们共同建议采用架构级防护：将无人值守的编码代理运行于严格沙箱中——例如隔离容器或虚拟机，禁止访问家目录、SSH密钥、云凭证及外网连接，并实施持续监控。真正的安全，应扎根于基础设施，而非仅依赖提示词或分类器。
