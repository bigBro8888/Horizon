uv 0.12.10 发布：支持发布后自动撤销 PyPI 令牌

新闻时间: 2026-09-05T05:42:59.628446+00:00 · 来源: github

Rust 编写的 Python 包管理器 uv 正式发布 0.12.10 版本，带来安全性、可用性与性能三方面的实质性改进。该版本于 2026 年 9 月 4 日发布，延续了 uv 以极速和高可靠性著称的特点，为开发者提供比传统工具（如 pip 和 pip-tools）更轻量、更安全的替代方案。当前，随着越来越多团队采用 PyPI 的“可信发布”（Trusted Publishing）机制——基于 OpenID Connect（OIDC）颁发短期令牌——自动化、安全的包发布流程正变得愈发关键。

最值得关注的安全增强是：uv publish 执行完毕后（包括失败场景），将自动尝试撤销所用的 PyPI 可信发布令牌。这一改进填补了一个隐蔽但真实的安全隐患：过去，令牌可能在发布流程结束后仍处于有效状态，无意中扩大了攻击面；现在 uv 主动使其失效，无需手动清理或修改 CI 脚本，即符合零信任安全理念。

在可用性方面，uv tree --invert 命令新增终端级依赖环可视化能力，可直接在命令行输出中清晰标出导致循环引用的终端节点，帮助开发者快速定位可能引发构建失败或运行时异常的依赖闭环。锁文件（uv.lock）行为也更稳健：当 exclude-newer-package 设置仅影响未参与当前解析的包时，--locked 模式不再报错；uv lock --check 现在也能在绝对时间或包级 exclude-newer 截止时间向后调整或禁用时，复用已有锁文件。这些修复显著提升了大型多包项目中锁文件驱动工作流的稳定性。

性能优化直击实际痛点：针对存在冲突 extras 的大型工作区，uv 现在通过排除无关依赖组来简化冲突分析，加快锁定速度；uv publish 则通过单次阻塞式哈希任务与跨读取缓冲区复用，显著提升制品（artifact）签名效率。配合 uv.lock 中 exclude-newer 条目的确定性写入顺序，这些改进进一步夯实了 uv 作为现代 Python 工程化基础设施核心组件的地位。
