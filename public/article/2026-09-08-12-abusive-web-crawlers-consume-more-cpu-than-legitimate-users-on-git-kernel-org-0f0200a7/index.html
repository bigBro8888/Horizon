恶意网络爬虫占用内核网站CPU资源超合法用户

新闻时间: 2026-09-08T05:55:48.592596+00:00 · 来源: rss

Linux内核官方Git托管服务发出了一则严峻的基础设施警报：恶意网络爬虫当前消耗的服务器CPU资源，已超过所有合法用户活动（包括Git克隆操作）的总和。Linux内核基础设施核心维护者康斯坦丁·里亚比采夫（Konstantin Ryabitsev）披露，在五个地理分散的服务器节点上，有14个CPU核心持续满负荷运转——唯一任务就是为爬虫渲染Git提交页面的HTML版本。这并非偶发流量，而是长期、稳定、高强度的负载，远超开发者通过标准工具获取代码或浏览仓库所产生的请求量。

这一问题揭示了现代Web基础设施中日益加剧的不对称性：那些本为人类可读性与API式探索而设计的服务（如git.kernel.org的提交查看器，或Datasette的数据浏览器），在无意中成了激进、行为失当爬虫的温床。与高效且可认证的Git协议访问不同，HTML页面渲染计算开销巨大，每次请求都需执行完整页面生成、语法高亮、差异解析及模板渲染。而由于这些页面完全公开、缺乏严格限速或机器人验证机制，便成了批量爬取、AI训练数据采集及SEO农场眼中的“低垂果实”。

Datasette创始人西蒙·威利森（Simon Willison）对此深表忧虑。Datasette是一款轻量级开源工具，专为将结构化数据发布为交互式网站和配套API而设计，其默认即提供大量可爬取的HTML与JSON端点，因此面临类似风险。连Linux内核这样高度优化、高流量的基础设施都难以承受此负载，那么运行在普通硬件上的小型开源项目，将直面真实可持续性危机：托管成本上升、响应变慢，甚至在爬虫高峰期间出现服务降级。

这不仅关乎性能，更关乎运维公平性与基础设施伦理责任。目前尚无强制性的爬虫行为通用标准，仅依赖robots.txt等自愿规范，而许多爬虫完全无视这些规则。限速、IP信誉评分或选择性JavaScript渲染等防护手段，在开源托管环境中仍属小众实践——因为这类环境往往优先追求简洁与透明，而非复杂的防御机制。随着AI数据采集加速扩张，成本负担正越来越多地转嫁给服务维护者，而非爬虫运营方。
