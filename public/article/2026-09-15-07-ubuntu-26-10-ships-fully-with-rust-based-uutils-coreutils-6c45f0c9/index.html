Ubuntu 26.10 全面启用 Rust 编写的 uutils 核心工具

新闻时间: 2026-09-15T06:08:50.109744+00:00 · 来源: hackernews

Ubuntu 26.10 已正式在所有默认安装中，将 GNU coreutils 全面替换为 uutils —— 一个跨平台、用 Rust 编写的替代实现。这是首个默认使用 uutils 0.10.0 版本提供 ls、cp、rm、mv 等基础 Unix 工具的 Ubuntu 发行版。此举是 Canonical 多年来推动系统关键组件内存安全战略的关键一步，旨在利用 Rust 编译时对缓冲区溢出、释放后使用和空指针解引用等漏洞的天然防护能力。

但这一切换并非一帆风顺。用户已迅速发现严重稳定性问题：一个被广泛复现的测试用例显示，rm -rf 在删除深度嵌套目录时会触发段错误（segmentation fault）—— 这一崩溃不仅导致命令失败，更使目标文件残留，破坏了基本的文件系统操作可靠性。在容器化的 Ubuntu 26.10 环境中，该问题即使在执行完整系统更新后依然存在；而旧版 GNU 的 gnurm 命令则能无误完成相同操作。这表明 uutils 当前的递归删除逻辑，在真实路径深度或边界条件下仍缺乏足够鲁棒性。

该问题绝非纸上谈兵。它直接影响构建链：由于 build-essential 包现在依赖 coreutils-from-uutils，用户无法简单降级回 GNU coreutils，否则将破坏包依赖关系。虽然可通过手动安装 coreutils-from-gnu 等变通方式绕过，但这类操作易引发依赖冲突。与此同时，uutils 官方文档也坦承：“部分选项可能缺失，或行为与 GNU 版本不同”。

这一里程碑折射出整个行业向内存安全系统编程演进的大趋势——微软亦已为 Windows 发布基于 uutils 的工具集，Rust 也在 Linux 内核模块和初始化系统中加速落地。然而，Ubuntu 在稳定版中默认启用尚未修复已知正确性缺陷的 uutils，凸显了技术创新与生产就绪之间的张力。对开发者和系统管理员而言，这意味着必须重新验证自动化脚本中的文件操作行为，而不能默认假设其与 POSIX 兼容。归根结底，Ubuntu 26.10 不仅是一次版本更新，更是 Rust 承担 Unix 基础设施重任的一场真实压力测试。
