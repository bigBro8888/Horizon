uv 0.12.17 发布：新增 libc 版本约束与锁文件完整性校验

新闻时间: 2026-09-19T05:49:42.185309+00:00 · 来源: github

Rust 编写的 Python 包管理器 uv 正式发布 0.12.17 版本，这是一次以稳定性与可靠性为重点的补丁更新。该版本于 2026 年 9 月 18 日发布，修复了因锁文件中存在不支持的 Git 归档路径而导致的程序崩溃问题，转而抛出清晰、可操作的错误提示。同时，它引入两项预览功能：其一强制校验 pylock.toml 中轮子（wheel）文件名是否严格匹配声明的包名与版本；其二支持通过 minimum-libc-version 字段指定通用解析必须兼容的最低 glibc 或 musl 版本，提升跨 Linux 发行版部署的安全性。

性能方面也有显著优化：当项目包含大量构建排除规则时，uv 不再采用低效的平方级去重逻辑，大幅加快构建速度；依赖解析器在处理重复的包与分发请求时也减少了内存分配，降低开销。另一项关键修复是防止 macOS 环境误选需更高 Darwin 版本的轮子——确保所选二进制与项目配置的最低系统版本兼容，避免运行时报错。

工作区元数据访问策略也更严谨：uv workspace metadata 默认设为只读，仅在显式传入 --sync 参数时才允许写入；同时 uv check 的锁模式现在会统一应用于元数据获取流程。文档方面，本次更新还澄清了 0.12.14 和 0.12.15 版本的变更说明，帮助用户理清演进脉络。

作为 pip 和 pip-tools 的高性能替代方案，uv 正持续强化其在确定性构建、平台约束和开发者体验方面的表现。这些改进呼应了 Python 社区对 PEP 751 锁文件标准日益增长的采纳需求，也为大规模、多平台 CI/CD 流水线提供了更坚实的基础。所有预编译二进制均覆盖 Apple Silicon、x86/ARM64 Windows、主流 Linux 架构（含 PPC64LE），并附带完整 SHA256 校验值，确保安装过程安全可控。
