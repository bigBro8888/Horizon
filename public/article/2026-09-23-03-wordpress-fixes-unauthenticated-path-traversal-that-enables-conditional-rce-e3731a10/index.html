WordPress修复未认证路径遍历漏洞，可导致条件性远程代码执行

新闻时间: 2026-09-23T05:56:01.492113+00:00 · 来源: hackernews

WordPress 已发布 7.1.2 版本，修复一个严重安全漏洞（CVE-2026-87902 / GHSA-7hp8-65ch-5whp），该漏洞允许未认证攻击者通过路径遍历读取服务器本地任意 PHP 文件，进而可能触发条件性远程代码执行（RCE）。问题根源在于 get_page_template() 函数的页面模板解析逻辑：当用户输入未经严格校验时，攻击者可构造恶意路径（如 ../../../wp-config.php），绕过主题目录限制，加载服务器上其他可读文件。

需注意的是，该漏洞本身属于本地文件包含（LFI），其升级为 RCE 并非必然，而是依赖特定条件——例如被包含的文件中存在可控序列化数据（如缓存插件生成的 .php 缓存）、或与不安全反序列化、第三方插件等组合利用。在真实环境中，大量使用缓存插件、自定义主题或老旧扩展的站点，实际风险远高于理论评估。

修复方案（提交号 9c4e85）强制约束模板路径必须位于当前主题或父主题目录内，并明确拒绝含 .. 或绝对路径的输入。更值得肯定的是，WordPress 将该补丁向后移植至所有受支持分支，最早覆盖到 4.7 版本——此举意义重大，因为社区估算目前仍有约三分之一的活跃 WordPress 站点尚未升级至 7.x 主线版本。

该漏洞曝光时间紧邻 GitLab 的 CVE-2026-85706（CVSS 10.0 路径遍历漏洞），凸显路径处理缺陷的普遍性。多位安全研究者指出，根本症结在于主流语言标准库长期缺乏“作用域化文件访问”抽象——仍依赖易出错的字符串拼接路径。为此，libpathrs 等新工具正推动以文件描述符替代全局路径操作。对网站管理员而言，立即升级仍是唯一可靠缓解措施；而转向 Hugo 等静态站点生成器，正成为部分团队主动规避此类动态服务风险的务实选择。
