FoxPro 以 Rust 和 WebAssembly 形式开源复活

新闻时间: 2026-09-23T05:56:01.492020+00:00 · 来源: hackernews

微软于2007年正式终止 Visual FoxPro 9 后，这款语言沉寂了十五年以上。如今它意外回归——不是出于怀旧，而是源于现实工程需求。新开源项目 FoxScript 使用 Rust 重写 FoxPro 运行时，并编译为 WebAssembly，同时严格比对原始 vfp9.exe 的行为以确保一致性。它的目标并非取代旧系统，而是延长其生命周期：仍在运行数十年 FoxPro 应用的企业（常依赖老旧的 32 位 Windows 环境）现在可无缝添加现代能力，无需推倒重来。

这不仅是精神上的复刻。项目保持深度兼容：原有 .DBC 数据库容器、.DBF 表文件，甚至 32 位 .FLL 插件库均可原样加载与执行。与此同时，它移除了硬性限制——数据表不再受限于 2 GB 容量——并新增原版从未具备的功能：原生 lambda 表达式、JSON 支持和嵌入式 HTTP 服务器。这些并非外部封装，而是深度集成至语言执行模型中，使开发者能直接从 FoxPro 逻辑中暴露轻量级 Web API 或构建数据导出流水线。

其驱动力来自真实世界的惯性。正如一位用户所言，某细分行业在 2026 年仍依赖 FoxPro，年营收超 4 亿美元——因为重写一个核心业务系统意味着巨大风险、成本与停机代价。对许多中小型企业，尤其是医疗、房地产估价或制造业等保守或强监管领域而言，“没坏就别修”不是懒惰，而是运营生存法则。FoxScript 正是迎向这一现实：不强迫迁移，而是升级已有系统的底层基础。

当然，这次复兴也伴随注意事项。当前构建版本未签名，报表功能尚未完成，且安全隐忧依然存在——尤其是 DBC 缺乏访问控制机制，以及存储过程以明文形式存于“备注字段”中。不过，MIT 开源协议与透明设计鼓励社区审查与协作。在热衷全新框架的时代，FoxScript 是少有的尊重历史、技术扎实的遗产守护范例：现代工具服务于延续性，而非淘汰。
