uv 0.12.20 发布：优化锁文件复用并新增 pylock.toml 预览功能

新闻时间: 2026-09-29T06:51:53.370522+00:00 · 来源: github

Astral 团队（Ruff 的开发者，uv 的维护者）于 2026 年 9 月 28 日发布了 uv 0.12.20 版本。作为一款用 Rust 编写的高性能 Python 包管理器，uv 旨在替代 pip、pip-tools 和 virtualenv，速度可达其 10–100 倍，同时完全兼容现有工作流。本次更新虽为小版本维护发布，却在可靠性、一致性和工程体验上做了多项务实改进。

最实用的增强是锁文件复用逻辑升级：uv 现在能识别语义等价但写法不同的依赖声明（例如 requests>=2.28 与 requests>=2.28.0），自动复用已有锁文件，避免重复解析和网络请求——这对持续集成（CI）环境尤为关键。另一项关键修复涉及 Windows 和混合换行符场景下的 wheel 脚本：uv 现在能正确保留 shebang 后第二行的编码声明（如 # -*- coding: utf-8 -*-），防止因编码丢失导致脚本执行失败。

多个预览功能体现了 uv 对 PEP 751 标准化锁文件格式 pylock.toml 的积极支持。包括：输出标准化依赖声明（减少无意义 diff）、支持合成默认分组（简化工作区安装）、将本地路径解析为相对于锁文件的位置——这些都让锁文件更可移植、更可预测。此外，uv 现在确保同一包即使在多个 tool-install-locks 中重复出现，也只安装一次，兼顾效率与确定性。

底层性能方面，uv 恢复了旧版 HTTP 缓存写入调度策略，以规避在 ext4 文件系统上出现的严重缓存验证卡顿问题。Bug 修复覆盖广泛：在 --require-hashes 模式下对重复依赖严格校验哈希；安全处理仅含 BOM 的 UTF-16 需求文件；优雅跳过未知 Python 实现目录而非崩溃；并阻止因空白字符或无效约束引发的 panic。整体来看，uv 正坚定走向成熟：不追求炫技，而专注把「正确」和「稳定」做到极致。
