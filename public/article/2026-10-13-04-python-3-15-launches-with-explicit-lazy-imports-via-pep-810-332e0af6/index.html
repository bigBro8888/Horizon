Python 3.15正式发布，引入显式懒加载导入机制

新闻时间: 2026-10-13T07:40:20.491351+00:00 · 来源: rss

Python 3.15 正式发布，标志着该语言演进的重要一步——开发者首次能通过清晰、显式的语法启用模块懒加载。此次发布由广受尊敬的 Python 开发者 Simon Willison 宣布，并由版本维护者 Hugo van Kemenade 主导整理。它终止了对 Python 3.10 的支持，全面拥抱 3.11 及后续版本的新特性。对于像 Willison 的 LLM 命令行工具这类需兼容多个 Python 版本的开源项目维护者而言，这意味着可立即卸下旧版兼容包袱，转而采用以性能为导向的新功能。

最引人注目的新特性是 PEP 810 提出的“显式懒加载导入”。与 2022 年被 Python 指导委员会否决的 PEP 690（全局隐式懒加载）不同，PEP 810 采用明确选择、细粒度控制的方式。开发者只需写下 lazy import json 或 lazy from pathlib import Path，模块便只在代码中首次访问其符号时才真正加载并执行。这有效避免了 sentence_transformers 等重型依赖在启动时就被急切初始化，显著缓解了命令行工具、测试套件和插件系统长期面临的启动延迟问题。

另一项实用更新是“推导式中的解包”（PEP 798），让列表、集合和字典推导式支持更简洁的扁平化写法。例如，[ *L for L in lists ] 可直接替代嵌套推导式 [x for L in lists for x in L]。这一特性延续自 Python 3.5 的 PEP 448 解包泛化，属于渐进式增强，而非范式颠覆，为数据处理密集型代码带来切实的可读性提升。

Python 3.15 的真正价值在于创新与务实的平衡：它不强求全局懒加载（易引发隐蔽 Bug 和调试困难），而是将控制权交还给开发者，精准优化启动耗时与内存占用。且每个 lazy import 的懒加载行为仅限于该语句本身，不会自动传递至间接依赖——这种可预测性，正是生产级工具与框架广泛采用的关键前提。
