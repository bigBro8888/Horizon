uv 0.13.1 支持 CPython 3.16.0a1 和 Linux SPARC 平台

新闻时间: 2026-10-14T06:06:20.201051+00:00 · 来源: github

Rust 编写的 Python 包管理器 uv 正式发布 0.13.1 版本，标志着其作为 pip 和 venv 高性能替代方案的持续演进。该版本于 2026 年 10 月 14 日发布，在平台兼容性、错误诊断和新兴标准支持等方面均有实质性提升。对于需要在多样化环境中开发、或构建下一代 Python 工具链的开发者而言，此次更新显著增强了可靠性、可移植性与可维护性。

最值得关注的前瞻性改进之一是原生支持 CPython 3.16.0a1 —— Python 3.16 的首个 alpha 版本。这体现了 uv 主动跟进 Python 开发节奏的决心，使早期采用者和 CI 系统能在稳定版发布前就验证新语言特性与运行时变更。同样重要的是新增对 Linux SPARC 架构的支持：通过在无法使用文件系统克隆或细粒度缓存统计时自动降级，uv 以务实方式拓展至传统及小众硬件平台，同时不牺牲正确性。

本次发布还引入两项具有长期影响的预览功能：启用 tool-install-locks 后，uv tool upgrade 可升级已安装工具；并初步支持解析 PEP 825 定义的 wheel 变体标签。PEP 825 标准化了如何将构建配置（如 ABI 变体、优化标志）编码进 wheel 文件名与元数据中，是实现更精准、可复现、架构感知型依赖解析的关键基础。尽管目前仍属实验性功能，但此举已为 uv 未来无缝对接基于变体的打包工作流铺平道路。

除新增能力外，0.13.1 还大幅强化了并发操作的健壮性：避免缓存清理、环境创建与工具卸载过程中的竞态条件；修复硬链接、设备文件及符号链接解释器等边缘场景问题；并优化 pip 兼容行为——例如 uv pip check 不再严格校验 Requires-Python 的上界约束，更贴近真实世界的解析逻辑。性能方面，二进制体积进一步缩减，Simple API 与包元数据解析速度也得到提升，这对大规模自动化和命令行响应体验尤为关键。

对于正在生产环境中评估 uv 的团队，此版本增强了对其成熟度的信心：缺失可信哈希时提供更清晰的报错信息、更强的隔离机制防止误删文件、Windows ARM64 模拟解释器的文档说明也更加完善。虽然官方发布说明未附社区讨论，但近期 Reddit 上的广泛反馈显示，用户普遍认可 uv 的稳定性与速度，许多人已将其设为默认的 Python 项目与工具管理器。
