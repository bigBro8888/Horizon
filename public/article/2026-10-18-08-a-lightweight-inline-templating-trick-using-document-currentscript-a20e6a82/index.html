用 document.currentScript 实现轻量级内联模板渲染

新闻时间: 2026-10-18T05:50:46.328958+00:00 · 来源: rss

一种巧妙、零依赖的 JavaScript 技巧正在网页开发中悄然流行：它允许在 HTML 中直接嵌入动态内容，无需框架、构建工具或外部模板。该技巧的核心是 document.currentScript —— 一个存在已久却常被忽视的 DOM API，它会返回当前正在执行的 <script> 元素。由于该属性仅在脚本运行期间可用（且仅适用于传统脚本，不适用于 ES 模块），因此天然支持“自替换”行为：内联脚本可以精准定位自身，并用计算结果原地替换整个 <script> 标签。

其原理极其简洁。比如这段直接写在 HTML 中的代码：

今年是 <script>
document.currentScript.replaceWith(new Date().getFullYear())
</script>

浏览器解析并执行时，该脚本会把自己替换成当前年份的纯文本 —— 不需要容器元素、不依赖事件监听器、甚至在 DOMContentLoaded 触发前就已完成。

为提升可读性，开发者可定义一行辅助函数，例如 $=(...n)=>document.currentScript.replaceWith(...n)，从而将这一模式变成极简的内联模板语言。此时上面的例子就简化为 <script>$(new Date().getFullYear())</script>。你可以在其中写表达式、调用函数，甚至嵌入简单条件逻辑，全部在 HTML 解析阶段即时求值并原地替换。

这当然不是现代模板引擎或组件系统的替代方案。它的适用场景非常明确：适合静态页面中少量、低交互性的动态需求，比如页脚版权年份、环境标识、调试信息等。它的价值恰恰在于“不做之事”：无需打包器、无运行时开销、也不引入额外依赖。但需注意，严格的 CSP（内容安全策略）通常默认禁止所有内联脚本 —— 因此实际使用前，必须确认站点是否允许 'unsafe-inline' 或已配置有效的 nonce。

归根结底，这是一种兼具教学意义与微优化价值的实践。它提醒我们：Web 平台本身早已内置了足够优雅的原生能力，只待开发者发现与善用。
