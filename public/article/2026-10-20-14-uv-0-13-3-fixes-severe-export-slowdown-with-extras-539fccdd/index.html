uv 0.13.3 修复带 extras 的依赖导出性能问题

新闻时间: 2026-10-20T05:59:17.059789+00:00 · 来源: github

Rust 编写的 Python 包管理器 uv 正式发布 0.13.3 版本，专门修复了 uv export 命令在处理含“extras”（可选依赖）的复杂依赖图时出现的严重性能退化问题。此前，当项目依赖中包含类似 requests[security] 或 django[argon2] 这类声明了额外功能组件的包时，uv export 执行时间会异常延长，有时甚至呈指数级增长，直接削弱了 uv 最核心的优势——极致速度。

uv 是由 Astral 团队（Ruff 的开发者）打造的高性能 pip 替代品，被广泛用于替代 pip、pip-tools、virtualenv 和 pipx 等传统工具。它基于 PubGrub 解析器，利用 Rust 实现原生性能，并通过全局缓存、智能重用等机制，实现比 pip 快 10–100 倍的依赖解析与安装体验。uv export 命令的作用是将已解析的依赖图（例如由 uv lock 生成的锁文件）导出为标准格式（如 requirements.txt），常用于 CI/CD 流水线、容器镜像构建或跨环境部署。

该性能问题源于 extras 在导出阶段的重复遍历与约束重计算：当多个包声明相同 extras 或存在深度嵌套依赖时，旧逻辑会反复验证兼容性，导致算法复杂度失控。0.13.3 通过重构 extras 的遍历路径与去重策略，使导出时间恢复至接近线性的合理水平，大幅缩短大型项目（尤其是含大量可选依赖的框架型项目）的构建耗时。

本次更新属于纯修复性补丁，不新增功能、不变更命令行接口。官方为 13 种平台提供了预编译二进制文件，覆盖 Apple Silicon 与 Intel macOS、x86_64 / ARM64 / RISC-V / s390x / PPC64LE Linux、以及 x86 / x64 / ARM64 Windows，还支持 musl 构建环境。用户仍可通过一行 curl 或 PowerShell 脚本完成安装，延续 uv “零依赖、单二进制、开箱即用”的设计理念。对依赖自动化导出的工程团队而言，升级到 0.13.3 可立即获得显著提速，且无需修改现有工作流。
