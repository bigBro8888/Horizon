PHP上传进度功能存在严重堆内存释放后使用漏洞

新闻时间: 2026-10-21T05:59:49.235106+00:00 · 来源: hackernews

PHP 的 session.upload_progress 功能被曝出一个严重的堆内存释放后使用（UAF）漏洞，编号为 CVE-2026-109618 和 CVE-2026-109619。该漏洞存在于启用上传进度跟踪时对 multipart/form-data POST 请求的处理逻辑中，尤其在内部上传状态结构的内存重分配与清理阶段发生错误。攻击者可通过构造恶意文件上传请求触发此漏洞，进而实现远程代码执行，对共享主机环境或接受用户上传的 Web 应用构成高危威胁。

该漏洞并非理论风险：多名安全研究人员已确认正在积极调查并部署缓解措施。有研究者表示已将生产流量镜像至检测系统，以捕获真实利用尝试；另有开发者指出，该问题与近期 PHP 核心维护者提及的“尚在保密期”的另一个漏洞无关——根据一位 PHP 维护者的公开说明，这是独立发现、性质不同的新漏洞，需立即响应。

缓解方案因实际场景而异。最直接的方法是在 php.ini 中设置 session.upload_progress.enabled = Off 彻底禁用该功能——但前提是应用不依赖上传进度反馈。若必须保留上传功能，则启用 SELinux 或 AppArmor 强制访问控制策略已成为社区广泛推荐的临时手段，可有效限制漏洞利用后的破坏范围。也有管理员询问能否在 Web 服务器层（如 Nginx 或 Apache）完全屏蔽 multipart 处理，但需注意：PHP 解析器仍会在拒绝请求体前读取头部，因此单靠服务器配置无法根除风险，需多层协同防护。

该漏洞之所以尤为紧迫，在于它影响的是默认启用、开销极低的核心功能。不同于冷门扩展，session.upload_progress 内置于 PHP 会话子系统，常被各类框架和 CMS 默认启用却极少被审查。截至最新公开信息，官方尚未发布补丁，防御方只能依赖配置加固、运行时保护及行为检测——这再次印证：再基础的功能，一旦缺乏严格的内存安全设计，都可能成为关键攻击面。
