uv 0.13.5 移除受信证书库中的 eMudhra 根证书

新闻时间: 2026-10-22T06:05:40.662294+00:00 · 来源: github

uv 团队发布了 0.13.5 版本，这是一次关键的安全维护更新，主动从所有托管的 Python 解释器构建及配套工具中移除了已被吊销的 eMudhra/emSign 根证书。该版本于 2026 年 10 月 21 日发布，将 uv 预编译的 CPython 发行版（包括新发布的安全补丁版本 3.13.17、3.14.9 和 3.15.1）升级至 python-build-standalone 20261021 构建。新版内置 pip 26.2.2 和 certifi 2026.10.19，确保无论是解释器内嵌的 pip，还是通过 python -m venv 安装的 pip，其 SSL/TLS 证书验证均不再信任已被撤销的 eMudhra 中间证书。

此次更新延续了 uv 0.13.4 的工作——该版本已率先从 uv 自身的证书存储中移除了该根证书。而 0.13.5 将修复进一步下沉至 Python 运行时层：所有通过 uv python install 或 uv venv 新建的虚拟环境，默认继承这一安全配置。用户在升级 uv 后，需手动运行 uv python upgrade 才能获取最新修补的 Python 解释器。值得注意的是，已有虚拟环境不会自动切换——它们仍使用原始 Python 二进制文件和证书包，除非用户显式执行升级操作。

除安全修复外，uv 0.13.5 还带来多项性能优化：多环境依赖解析时峰值内存降低、含复杂可选依赖（extras）的导出速度提升，以及通过精简错误格式化逻辑缩小了二进制体积。一项预览功能 wheel-variants 开始支持 PEP 850 定义的静态提供者，以在平台特定场景下更精准地筛选轮子（wheel）。此外还修复了若干问题，例如正确锁定仅提供 Android 轮子的包，以及改进跨不兼容环境路径激活的可选依赖导出逻辑。

该版本也明确传递了生命周期终止信号：uv 将停止为 Python 3.9 和 3.10 发布 Docker 镜像——这两个版本因上游 pip 仍捆绑受信的 eMudhra 证书而持续存在风险。团队强烈建议用户迁移到受支持的 Python 版本。对于依赖 uv 高速与可靠性的开发者和运维人员而言，本次更新不仅是推荐操作，更是保障 HTTPS 包安装与索引通信可信性的必要举措。
