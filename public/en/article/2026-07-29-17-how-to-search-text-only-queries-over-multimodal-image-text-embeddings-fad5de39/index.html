How to search text-only queries over multimodal image-text embeddings

News time: 2026-07-29T04:27:46.818774+00:00 · Source: reddit

A practitioner on Reddit recently posed a deceptively simple but increasingly common challenge: how to perform effective text-only vector search over a dataset where each item consists of both an image and descriptive text—like product photos with captions or social media posts with images and alt-text. Their goal is to move beyond traditional keyword-based retrieval (e.g., BM25) and leverage modern multimodal embedding models, but they’re caught in a design dilemma: should each image and its caption be embedded separately—or fused into a single joint representation?

The core issue lies in alignment. Models like CLIP produce separate text and image encoders that map inputs into a shared embedding space—meaning a sentence about a 'red sports car' and a photo of that same car end up close together in vector space. But when users only type text queries, retrieving the best-matching items requires deciding how to represent those items for indexing. Storing two vectors per item (one for text, one for image) risks diluting relevance: a strong text match might be buried if the image vector is weak or irrelevant. Conversely, fusing text and image into one vector risks losing nuance—especially if captions are sparse or noisy.

Practical solutions discussed in related literature include using CLIP’s text encoder alone to embed captions (and ignoring image vectors entirely), or applying late fusion—e.g., averaging or weighted concatenation of text and image embeddings before indexing. Some newer approaches, like Jina’s CLIP v1, emphasize unified inference pipelines that output a single multimodal embedding per item by design. Others suggest adapter-based alignment: fine-tuning lightweight modules to project heterogeneous embeddings into a more balanced shared space.

Crucially, this isn’t just a modeling choice—it affects database architecture. Vector databases don’t inherently understand modality; they only compare distances. So whether you index one vector or two per item determines query routing, filtering logic, and even latency. For pure text queries, indexing only caption embeddings (via CLIP’s text tower) often yields higher precision—and avoids bias toward visually dominant but semantically mismatched results. Yet for richer use cases—like searching for 'a rainy street at night' where neither caption nor image alone suffices—joint representations become essential. The right answer depends on data quality, user intent, and downstream flexibility.
