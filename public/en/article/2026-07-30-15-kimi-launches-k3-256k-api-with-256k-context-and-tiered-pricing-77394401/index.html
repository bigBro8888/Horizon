Kimi launches K3-256k API with 256k context and tiered pricing

News time: 2026-07-30T04:17:07.064014+00:00 · Source: hackernews

Kimi, the large language model developed by Moonshot AI, has launched a new API variant called K3-256k — a version of its flagship K3 model optimized for long-context workloads up to 256,000 tokens. Unlike the original K3 model, which supports up to 1 million tokens in context, K3-256k introduces a hard cap at 256k and pairs it with a revised pricing structure: users pay half the per-token cost of the full K3 model — but only as long as their input stays within that 256k limit. Once exceeded, the system triggers automatic context compression on the client side (e.g., via Kimi Code CLI or Claude Code tools), effectively downgrading the session to fit within the window.

This move reflects a growing industry trend toward pragmatic tradeoffs between context length, inference cost, and hardware feasibility. As noted in community discussions, running native 256k-context inference demands extraordinary GPU memory — reportedly up to 1.5 TB of VRAM — far beyond consumer or even most enterprise hardware. Even optimized 1-bit quantized versions require ~570 GB, placing them near the upper limits of Apple’s Mac Studio M3 Ultra configuration. That stark hardware reality underscores why Kimi chose an API-level boundary rather than pushing raw model capability alone.

The pricing model itself mirrors OpenAI’s recent approach at 272k (2^18), where longer contexts incur higher per-token compute and memory costs. But Kimi’s implementation is more abrupt: a binary switch instead of a smooth gradient. This design choice prioritizes predictability and simplicity for developers — though some argue it may disincentivize thoughtful context management, especially since many users reportedly lack awareness of how context length affects performance and cost.

What makes K3-256k notable isn’t just its scale, but its positioning: it targets the 90% of real-world use cases that fit within 256k — from large codebases to multi-document analysis — while sidestepping the extreme infrastructure overhead of full 1M-context deployment. For developers building agentic or coding assistants, this offers a compelling balance of capability, affordability, and deployability.
