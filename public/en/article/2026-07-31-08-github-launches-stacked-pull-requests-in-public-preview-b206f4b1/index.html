GitHub launches stacked pull requests in public preview

News time: 2026-07-31T04:36:00.263492+00:00 · Source: hackernews

GitHub has officially rolled out Stacked Pull Requests (Stacked PRs) to all repositories in public preview—a major evolution in how developers manage, review, and merge interdependent code changes. Instead of cramming large features into a single monolithic PR, teams can now break work into smaller, logically ordered PRs that build on one another. Each PR remains independently reviewable and testable, while GitHub visually links them into a cohesive stack—showing dependencies, merge order, and overall progress at a glance.

This feature directly addresses long-standing pain points in collaborative development: oversized PRs that slow down reviews, conflicting changes across branches, and the difficulty of landing partial work without breaking functionality. By enabling incremental development with clear lineage, Stacked PRs support workflows long used by engineers at companies like Meta and Google—where tools like Phabricator’s Differential or Google’s internal Piper system have made stacked changes standard practice. GitHub’s implementation integrates deeply with its existing ecosystem, including GitHub Actions, branch protections, and the CLI.

To use Stacked PRs, developers install the gh stack extension for the GitHub CLI, then create dependent branches and PRs in sequence. The UI surfaces the stack as a unified view—highlighting which PRs are ready, which need rebase, and which depend on others. Merge queue support is rolling out gradually, and squash-and-merge behavior currently requires re-approval for each PR in the stack when review policies are enforced—a known limitation noted by early adopters.

Community response has been enthusiastic but grounded in real-world experience. Some users report broken merge behavior in edge cases, while others critique the default framing of stacks as siloed ‘component’ changes—like database, API, and frontend layers—arguing this risks fragmenting holistic feature review. Still, many see it as one of GitHub’s most consequential updates in years, potentially reshaping how thousands of teams approach code quality, velocity, and collaboration. As the GitHub team states, this launch touches nearly every service in their infrastructure—an unmistakable signal of strategic priority.
