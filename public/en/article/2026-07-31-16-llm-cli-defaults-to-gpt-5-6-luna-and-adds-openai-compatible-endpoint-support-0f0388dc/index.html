llm CLI defaults to GPT-5.6 Luna and adds OpenAI-compatible endpoint support

News time: 2026-07-31T04:35:59.064156+00:00 · Source: rss

The popular open-source CLI tool llm, created by Simon Willison, has released version 0.32rc2 — a meaningful update that shifts the default large language model for new users from GPT-4o mini to the newly launched GPT-5.6 Luna. This change reflects both technical progress and pragmatic trade-offs: Luna delivers stronger reasoning, better tool use, and improved multimodal capabilities, but at a modest cost increase — $0.20 per million input tokens and $1.20 per million output tokens, compared to $0.15/$0.60 for GPT-4o mini. For developers sensitive to budget or latency, the release also introduces GPT-5 nano as an even leaner alternative ($0.05/$0.40), optimized for high-volume API calls and sub-agent workflows.

Beyond model defaults, 0.32rc2 adds a powerful new command: llm openai endpoint. This lets users send prompts, run chats, or list models against any OpenAI-compatible API — including local servers like LM Studio or Ollama — without pre-registering a model configuration. Crucially, these requests are not logged, preserving privacy during experimentation. The feature is designed for rapid iteration: you can even invoke it without installing llm at all, using uvx — a lightweight Python package runner — to execute one-liners directly against local endpoints.

A concrete example shows its utility: a single uvx command sends a prompt with tool-calling enabled (-T llm_time --td) to a locally running Gemma-4-31b model via LM Studio’s HTTP interface. This bridges the gap between local LLM experimentation and production-ready CLI tooling — something previously missing in the ecosystem. The addition responds directly to developer frustration around fragmented tooling for testing against diverse backends.

Taken together, these updates make llm more versatile, future-proof, and accessible. It’s no longer just a wrapper for OpenAI’s official models; it’s becoming a universal interface for interacting with any Chat Completions–style LLM service — whether cloud-hosted, self-hosted, or experimental. That flexibility, combined with thoughtful defaults and transparent pricing signals, strengthens its role as a foundational tool in the modern LLM workflow stack.
