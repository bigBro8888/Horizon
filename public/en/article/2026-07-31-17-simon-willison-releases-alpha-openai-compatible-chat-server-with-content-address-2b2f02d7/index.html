Simon Willison releases alpha OpenAI-compatible chat server with content-addressable state

News time: 2026-07-31T04:35:59.064252+00:00 · Source: rss

Simon Willison has launched llm-chat-completions-server 0.1a0 — a lightweight, locally runnable server that exposes installed LLM models via an OpenAI-style /v1/chat/completions API endpoint. Unlike typical chat APIs where clients must manage and resend full conversation histories for every request, this server leverages the newly introduced content-addressable log design in LLM 0.32rc1 to store and deduplicate messages by cryptographic hash. Each user or assistant message is hashed independently, enabling efficient reuse across conversations and supporting forked or branching dialogues without redundant storage.

The architecture reflects a deliberate shift toward state-aware local LLM tooling. Instead of treating each chat completion as a stateless request, the server builds on LLM’s updated database schema — where message IDs are derived from their content rather than sequential integers. This means identical prompts or responses generate identical IDs, automatically eliminating duplication and enabling structural representation of conversation trees. Willison built the server specifically to validate whether this new schema could robustly support real-world OpenAI-compatible interaction patterns.

Setup is intentionally minimal: users install it as an LLM plugin using uv tool install llm --pre, then run llm install llm-chat-completions-server followed by llm chat-completions-server -p 9001. Once running, the server serves all locally available models (including those added via other LLM plugins) on port 9001. The example curl command shows how clients send multi-turn messages — including prior assistant replies — just like with OpenAI’s API, but with backend de-duplication happening transparently.

Notably, Willison credits GPT-5.6 Sol — an internal model — for writing the entire implementation, highlighting how modern LLMs can now reliably generate production-ready code for well-specified API contracts. While still an alpha release (denoted by the 0.1a0 version), the project signals growing maturity in local-first LLM infrastructure: prioritizing interoperability, storage efficiency, and developer ergonomics over cloud dependency. It’s a small tool with architectural ambition — one that treats conversation history not as transient payload, but as structured, shareable, and compressible data.
