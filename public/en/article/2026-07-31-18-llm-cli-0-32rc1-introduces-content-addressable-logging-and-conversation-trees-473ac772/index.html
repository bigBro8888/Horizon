LLM CLI 0.32rc1 introduces content-addressable logging and conversation trees

News time: 2026-07-31T04:35:59.064280+00:00 · Source: rss

Simon Willison has released LLM 0.32rc1, a major release candidate for the popular open-source LLM command-line interface tool. This version completes foundational work begun in the earlier 0.32a0 pre-release and delivers a redesigned internal logging architecture — one that significantly improves fidelity when capturing prompts, responses, and metadata from modern large language models, including newly supported variants like gpt-5.6-sol, gpt-5.6-terra, and gpt-5.6-luna.

The centerpiece of this update is a shift to content-addressable storage for message records. Instead of assigning arbitrary sequential IDs, each stored message is now hashed using its full content — prompt, model parameters, system instructions, and response — to generate a unique, deterministic ID. This means identical interactions produce identical IDs, enabling automatic deduplication across logs. More importantly, it allows the database to natively represent forked conversations: when a user branches from an earlier message (e.g., to try alternative replies or explore different reasoning paths), the new messages retain explicit parent-child relationships, forming a tree rather than a flat list.

This schema change is non-destructive: only new tables are added, and existing log data remains fully intact and readable. Still, because it alters how future logs are written and indexed, the author strongly recommends backing up your current logs.db before upgrading. A simple command — llm logs backup logs-backup.db — handles this safely and is documented directly in the release notes.

For developers and power users who rely on LLM for reproducible experimentation, debugging, or audit trails, these changes are transformative. Content addressability ensures that every logged interaction is uniquely identifiable and tamper-evident — if the content changes, the hash changes. Conversation trees support richer analysis, versioning, and navigation of exploratory dialogues, moving beyond linear chat history toward structured, traceable reasoning workflows. As conversational AI tools increasingly emphasize transparency and repeatability, LLM’s move reflects a broader industry shift toward treating interactions as first-class, versioned artifacts — not just ephemeral text.
