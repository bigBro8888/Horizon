Kimi K3 runs locally at 0.50 tokens per second using just 29 GB RAM

News time: 2026-08-01T04:33:02.670142+00:00 · Source: hackernews

A new open-source project called 'waste'—hosted on GitHub by sqliteai—demonstrates a surprisingly lean local inference setup for Kimi K3, the latest large language model from Moonshot AI. Unlike typical high-memory LLM deployments, this implementation achieves 0.50 tokens per second while consuming only 29 GB of RAM. That’s notably lower than many quantized Llama or Qwen models running at similar speeds, and far below the hundreds of gigabytes often assumed necessary for trillion-parameter models. The project leverages SQLite as an unconventional memory layer, sidestepping traditional tensor loading patterns in favor of on-demand data access via mmap-like mechanisms.

The technical approach has sparked debate among systems-aware developers. Some argue that standard llama.cpp already handles memory efficiently via mmap-backed GGUF loading—keeping only hot model segments resident in RAM while relying on kernel page caching. Others point out that 'waste' avoids full model deserialization, potentially reducing startup latency and memory fragmentation. Still, skeptics question whether the gains justify the added complexity—or whether the performance is truly competitive once I/O bottlenecks and context-switching overhead are accounted for.

Beyond engineering tradeoffs, the discussion quickly expanded to practical concerns. One commenter estimated the electricity cost at roughly $5 per million tokens—based on 42W sustained draw and a 20¢/kWh utility rate—highlighting how even modest local inference carries nontrivial operational expense. Another noted that for many real-world tasks (e.g., summarizing short documents), waiting several minutes for 0.50 tok/s output may be acceptable if the result is concise and reliable. Licensing also emerged as a red flag: sqliteai previously used restrictive licenses like the Elastic License, raising caution—even though 'waste' itself currently ships under an open license.

Ultimately, 'waste' isn’t positioned as a production-ready inference engine but as a provocation: a proof that aggressive memory optimization can unlock frontier models on consumer hardware. It challenges assumptions about what ‘usable’ local LLM performance means—not just raw speed, but cost, licensing transparency, and architectural simplicity.
