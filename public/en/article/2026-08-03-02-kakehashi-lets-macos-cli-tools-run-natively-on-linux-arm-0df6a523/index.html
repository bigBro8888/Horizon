Kakehashi lets macOS CLI tools run natively on Linux ARM

News time: 2026-08-03T04:44:33.719998+00:00 · Source: hackernews

A new open-source project called Kakehashi is pushing the boundaries of cross-platform compatibility by enabling macOS command-line binaries to run directly on Linux ARM64 systems—without emulation or virtualization. Developed by vlad_kalinkin and hosted under the WIE Project, Kakehashi operates entirely in userspace as a translation layer: it loads Darwin Mach-O binaries, maps a minimal freestanding libSystem, translates BSD-style syscalls to Linux equivalents, and executes them on native aarch64 hardware. Unlike full-system emulators or kernel modules, Kakehashi avoids JIT compilation and doesn’t require macOS kernel components—making it lightweight, portable, and legally safer than approaches relying on Apple’s proprietary code.

The project is still experimental but already demonstrates tangible progress. Working prototypes include 7-Zip (7zz), curl, and core Xcode Git tools—all verified on real Linux ARM64 environments including Docker/Colima and UTM. Performance benchmarks show 7-Zip running at roughly 5.2× slower than its native Linux counterpart, but the developer has outlined concrete optimization paths—including syscall batching and improved thread-scheduling logic—to close that gap significantly. Curl passes over 200 command-line combinations in automated tests, confirming robust handling of networking, TLS, and file I/O abstractions.

Kakehashi deliberately focuses on CLI-first compatibility—not GUI apps or frameworks like AppKit or Cocoa—setting it apart from broader efforts like Darling, which aims to support macOS GUI applications on Linux via a full Darwin userland reimplementation. While Darling targets x86_64 and is now exploring ARM64 support, Kakehashi embraces ARM64 from day one and prioritizes correctness and simplicity over completeness. Its design avoids shipping rewritten Apple libraries; instead, it builds just enough Darwin ABI surface to satisfy common CLI tool dependencies—such as libdispatch, libsystem_network, and basic Mach task/port primitives.

This approach resonates with developers frustrated by macOS-only toolchains in CI/CD pipelines or ARM-based development workflows. For example, teams using M1/M2 Macs for build scripting but deploying on Linux ARM servers could soon avoid maintaining dual toolchains. Though far from production-ready, Kakehashi signals growing momentum behind Linux ARM as a serious development platform—and hints at a future where macOS CLI utilities become first-class citizens across heterogeneous infrastructure.
