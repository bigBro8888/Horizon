Simon Willison releases condense-json 1.0 for JSON string deduplication

News time: 2026-08-03T04:44:33.535978+00:00 · Source: rss

Simon Willison has officially released version 1.0 of condense-json, a lightweight Python library designed to reduce JSON payload size by replacing repeated substrings with compact, reference-based syntax. The tool doesn’t compress bytes or encode data—it works at the semantic level, identifying recurring string fragments (like common phrases or identifiers) and substituting them using a custom $r notation tied to a user-provided replacements map. This approach preserves full JSON validity while enabling predictable, reversible space savings—especially valuable when storing many similar JSON documents, such as logs or LLM interaction traces.

The release marks a milestone for a project that’s been in active use for over a year and a half. Willison notes he’s become more confident about declaring 1.0 versions for stable, well-tested utilities—even modest ones. The library is already integrated into his LLM command-line tool, where it shrinks SQLite log entries generated during AI model interactions. A recent pull request (#1586) shows how condense-json cuts storage overhead without altering application logic or query patterns.

Usage is straightforward: pass a JSON object and a dictionary mapping keys (e.g., "1") to substring values (e.g., "with foxes in it"). The condense_json() function scans strings recursively, replaces matches with structured references like {"$r": ["This is a string ", {"$": "1"}]}, and returns valid JSON. Its counterpart, uncondense_json(), fully restores the original structure using the same replacements map—no data loss, no ambiguity. Unlike general-purpose compression (e.g., gzip), this method remains human-readable and diff-friendly, making it ideal for versioned logs or debugging scenarios.

While not a breakthrough in algorithmic compression, condense-json fills a pragmatic niche: developers who need deterministic, inspectable, and reversible JSON size reduction—without introducing binary formats or external dependencies. It complements existing techniques like string interning (which operates at the Python interpreter level) or JVM string deduplication (a GC feature), but does so portably across environments and languages via its explicit, declarative replacement model.
