Reviewer calls for desk rejection of ML papers without runnable code

News time: 2026-08-04T04:28:36.366004+00:00 · Source: reddit

As the NeurIPS review cycle concludes, a seasoned reviewer has sounded the alarm about a deepening crisis in machine learning research: reproducibility. Having reviewed 12 papers across three major conferences this year—including NeurIPS—the reviewer found only one paper provided fully executable code that reproduced the entire training pipeline, from raw data input to final AUROC metric output. Four others shared partial code—fragments or snippets—but no end-to-end runnable implementation. The remaining seven offered no code at all.

What’s more alarming is what happened when code was present: of the five papers with any code, three contained obvious, critical bugs—such as incorrect loss computation or flawed data shuffling—that completely invalidated their reported results. These aren’t subtle numerical instabilities; they’re logic errors that would have gone unnoticed without execution. As the reviewer notes, ML systems are highly sensitive: a misplaced line in preprocessing or gradient computation can flip conclusions entirely.

The root cause isn’t technical incapacity—it’s misaligned incentives. Submitting code currently increases the risk of rejection, since reviewers may uncover flaws during execution. There’s no penalty for omitting it, and little reward for sharing it early. This asymmetry encourages opacity rather than transparency. The reviewer argues that voluntary code sharing has failed—and that only a structural intervention can shift behavior: mandatory, executable code as a hard requirement for review eligibility, enforced via desk rejection.

This proposal isn’t about perfectionism. It’s about basic scientific hygiene. Reproducibility isn’t a ‘nice-to-have’ in empirical disciplines—it’s the foundation of trust. Without runnable code, claims about model performance (like AUROC scores) remain unverifiable assertions, not evidence-based findings. While some worry about implementation burden or proprietary constraints, the reviewer stresses that minimal viable reproducibility—e.g., a single script with pinned dependencies and clear instructions—is achievable for nearly all academic work. The cost of not acting, they warn, is eroded credibility, wasted researcher time, and slower collective progress.
