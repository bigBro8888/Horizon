C-Kermit releases first new version in 15 years for its 45th anniversary

News time: 2026-08-04T04:28:35.934998+00:00 · Source: hackernews

After a 15-year silence, the venerable C-Kermit file transfer software has received its first official release update — marking both the 45th anniversary of the Kermit protocol and a quiet triumph of legacy code maintenance. Developed originally at Columbia University in 1977, Kermit was designed to solve a fundamental problem of early computing: moving files reliably across wildly incompatible systems — from IBM mainframes and DEC VAX minicomputers to CP/M microcomputers and early Unix workstations. Its secret wasn’t speed or novelty, but portability: Kermit’s architecture abstracted away hardware quirks, terminal behaviors, and OS idiosyncrasies so thoroughly that it ran on over 300 platforms by the early 1990s.

C-Kermit, the flagship C-language implementation launched in the mid-1980s, became the de facto standard for cross-platform file transfer long before TCP/IP was ubiquitous. Unlike FTP or ZMODEM, Kermit handled text-file line-ending conversion automatically and supported scripting, terminal emulation, and error recovery on low-bandwidth, noisy serial links — features essential for dial-up modems and terminal concentrators. Its source code is legendary among systems veterans: one commenter recalls encountering more #ifdef directives than in any other project they’d seen, spanning AIX, VMS, CGOS, and dozens of obscure OS variants.

The new release — built and tested on modern Linux, macOS, and Windows (via Cygwin/MSYS2) — doesn’t overhaul Kermit’s design. Instead, it modernizes build tooling, fixes longstanding bugs in UTF-8 handling and serial port detection, and restores compatibility with contemporary terminal emulators and SSH-based serial gateways. Crucially, it preserves the original philosophy: no external dependencies, minimal assumptions about the host system, and full backward compatibility with decades-old Kermit servers and clients.

What makes this release remarkable isn’t technical ambition, but continuity. In an era of rapid obsolescence, Kermit endures not as nostalgia, but as functional infrastructure — still used today by embedded developers, museum curators restoring vintage systems, and engineers maintaining industrial control equipment. As one gray-beard contributor notes: 'I still use Kermit regularly for embedded development. It’s very handy.' That quiet utility — unchanged in spirit, renewed in practice — is the real milestone.
