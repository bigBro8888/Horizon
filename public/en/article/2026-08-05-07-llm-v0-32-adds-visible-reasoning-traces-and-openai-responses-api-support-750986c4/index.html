LLM v0.32 adds visible reasoning traces and OpenAI Responses API support

News time: 2026-08-05T04:26:40.718603+00:00 · Source: rss

Simon Willison, creator of the popular open-source LLM CLI tool, released version 0.32 — the most significant update since the project’s launch. This release transforms how developers interact with reasoning-capable models by making their internal thought processes visible in real time. When users run prompts against models like GPT-5.6 Luna or Claude Sonnet-5, LLM now prints step-by-step reasoning traces to standard error (stderr), keeping them separate from the final output sent to stdout — a design that preserves pipeline compatibility while enabling deep inspection.

The update also integrates OpenAI’s newly launched Responses API, introduced in March 2025 as a more capable successor to the Chat Completions API. This enables stateful, multi-turn interactions with built-in tools like WebSearch and CodeInterpreter — all accessible directly from the command line. For example, llm --tool CodeInterpreter 'Show current python and SQLite versions' executes code remotely via OpenAI’s sandboxed environment, returning results without requiring local setup.

Server-side tooling extends beyond OpenAI: the updated llm-anthropic plugin now supports WebSearch, WebFetch, CodeExecution, and AnthropicMCP — a protocol allowing models to call external services like Datasette’s MCP endpoint. One striking demo shows Claude querying a live database table (blog_blogmark) over HTTP using a single CLI command, blurring the line between prompt and API client.

Logging has been overhauled with a redesigned content-addressable SQLite backend — ensuring deterministic storage and faster lookups — while the new llm openai endpoint command lets users send prompts to any OpenAI-compatible server (e.g., Ollama, LM Studio) without configuration. Though not logged by default, this one-liner bridges LLM’s ecosystem with the broader landscape of local and self-hosted models.
