Celld brings Cloudflare-style durable objects to self-hosted infrastructure

News time: 2026-08-06T04:28:17.718402+00:00 · Source: hackernews

Celld is a new open-source project from Deno that lets developers run Durable Objects — a powerful stateful serverless abstraction — entirely outside Cloudflare’s ecosystem. Unlike Cloudflare Workers’ Durable Objects, which are tightly coupled to Cloudflare’s global edge network and proprietary runtime, Celld provides a self-hosted, distributed alternative. It runs on standard infrastructure: you can deploy it via Docker, install it with a shell script, or integrate it into your own infrastructure stack. Each Celld node embeds V8 and executes Wrangler-compiled bundles natively, while the fleet coordinates state using an S3-compatible object store you control — for deployments, object state, and lightweight ownership records.

Durable Objects themselves are single-instance, stateful entities that combine compute and storage in one addressable unit. Think of them as lightweight, persistent actors: each has its own isolated state (like an embedded SQLite database), lives at a unique name-based ID, and handles requests serially — eliminating concurrency complexity. Cloudflare pioneered this model to power real-time coordination, chat backends, game sessions, and collaborative editing at global scale. But until now, it was locked behind Cloudflare’s vendor-specific platform.

Celld changes that. By decoupling the Durable Object programming model from Cloudflare’s infrastructure, it opens the door to on-premises deployments, air-gapped environments, hybrid cloud setups, and decentralized applications where data sovereignty and infrastructure control matter. Developers can reuse existing Workers and Durable Objects code — with minimal or no changes — while running everything on their own servers or Kubernetes clusters. The architecture is intentionally minimal: no custom language, no new APIs, just a faithful reimplementation of the core DO contract using widely available components.

Community response has been enthusiastic. Developers praised its architectural clarity and practical utility — one used it to power a mango-tasting event app previously built on Cloudflare, while others highlighted how it enables reliable state management across decentralized nodes. Notably, the maintainers have disabled GitHub pull requests not out of gatekeeping, but to prioritize deep understanding and focused contributions — asking instead for git format-patch submissions with clear context and respect for review time. This signals mature engineering discipline, rare in early-stage infrastructure projects.
