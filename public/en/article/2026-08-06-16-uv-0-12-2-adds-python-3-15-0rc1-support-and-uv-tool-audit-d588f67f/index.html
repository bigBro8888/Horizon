uv 0.12.2 adds Python 3.15.0rc1 support and `uv tool audit`

News time: 2026-08-06T04:28:18.428526+00:00 · Source: github

Astral-sh has released uv 0.12.2, the latest patch of its blazing-fast Rust-based Python package manager. Released on August 5, 2026, this version delivers tangible improvements across compatibility, diagnostics, performance, and configuration—without breaking changes. It’s a focused update that strengthens uv’s role as a production-ready alternative to pip and Poetry, especially for teams prioritizing speed and reproducibility.

The most forward-looking addition is native support for CPython 3.15.0rc1—the first release candidate for Python’s next major version—as well as the stable maintenance release CPython 3.14.7. This early adoption helps developers test their projects against upcoming Python features and catch compatibility issues before final release. Equally notable is the debut of uv tool audit, a preview command that scans installed tools (like black or ruff) for known vulnerabilities in their dependency trees—functionally mirroring pip-audit but integrated directly into uv’s toolchain.

Performance gains are quietly substantial: parsing of uv.lock files—critical for deterministic builds—has been accelerated for both wheel and source distribution entries, and filename extraction from distribution URLs is now faster. Under the hood, uv reduces redundant filesystem metadata lookups during bytecode compilation and reuses file metadata when building source distributions. These optimizations collectively shave milliseconds off repeated operations, which compound meaningfully in CI pipelines or large monorepos.

New configuration options add operational flexibility: the UV_RUN_RLIMIT_NOFILE environment variable lets users raise the open-file limit for processes launched via uv run, addressing resource constraints in high-concurrency environments. A new cache-physical-space preview feature also reports actual disk space reclaimed during cache cleanup—useful for observability and automation. Minor fixes improve backward compatibility with older cached artifacts and tighten workspace dependency group handling. Documentation updates clarify GitHub Actions workflows and Docker integration, lowering onboarding friction for new adopters.
