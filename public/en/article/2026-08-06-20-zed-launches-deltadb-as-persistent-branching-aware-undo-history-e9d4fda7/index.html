Zed launches DeltaDB as persistent branching-aware undo history

News time: 2026-08-06T04:28:17.718197+00:00 · Source: hackernews

Zed, the open-source, real-time collaborative code editor, has unveiled DeltaDB—an experimental internal version control system designed not as a Git replacement, but as a persistent, branching-aware 'undo history.' Announced via its blog and landing page in June 2026, DeltaDB records edits incrementally as they happen, linking each change to the context that produced it—such as a chat message or agent instruction. Unlike traditional snapshot-based VCS like Git, DeltaDB uses operation-based conflict-free replicated data types (CRDTs) to support concurrent editing across machines and agents without merge conflicts.

The system is built to interoperate with Git rather than replace it: DeltaDB tracks fine-grained edits locally and can export them as conventional commits when needed. Its branching model reflects how developers actually work—keeping track of divergent editing paths (e.g., feature branches or AI-assisted refactors) while preserving causal relationships between edits and their motivations. As Zed’s team explains, 'software is made between commits,' and DeltaDB aims to capture that intermediate, conversational layer of development.

Yet despite its technical ambition, DeltaDB has drawn muted enthusiasm from users. In the announcement thread on Zed’s forum and Hacker News, over 180 comments reveal widespread frustration—not with DeltaDB itself, but with unresolved foundational issues: WSL file visibility failures, Wayland clipboard instability, UI responsiveness problems, and crashes triggered by large files. Many developers argue that investing engineering effort into a novel VCS before stabilizing core editor functionality feels misaligned with user needs.

Some commenters question DeltaDB’s practical scope: one notes it’s not self-hostable, another points out that existing tools like jj or Git with better UI integrations already solve many of the same problems. A few express cautious interest—especially in CRDT-backed real-time collaboration—but emphasize that adoption hinges on reliability first. Ultimately, DeltaDB represents an intriguing architectural experiment—but one whose reception underscores a broader tension in developer tooling: innovation must coexist with stability, not precede it.
