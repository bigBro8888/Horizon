Datasette 1.0a38 patches critical SQL injection flaw in mixed-table deployments

News time: 2026-08-07T04:02:59.276479+00:00 · Source: rss

Datasette, the open-source tool for exploring and publishing data from SQLite databases, has released version 1.0a38 to address a critical security vulnerability. The flaw allowed attackers with access to any public table in a Datasette instance to bypass permission controls and read data from private tables residing in the same SQLite database — even when the execute-sql permission was explicitly disabled for those users.

This vulnerability exploited how Datasette’s SQL query execution layer handled table name sanitization in multi-table environments. When public and private tables coexisted in one database file and were governed by Datasette’s built-in permissions system, a crafted SQL query could inject table names that evaded validation checks. As a result, users authorized only for public tables could construct queries like SELECT * FROM private_table, effectively sidestepping access restrictions.

The fix tightens input validation during SQL parsing, ensuring table identifiers referenced in raw queries are strictly limited to those the user is permitted to access. Importantly, the patch also ships in Datasette 0.65.3 — a stable backport for users not yet ready to adopt the alpha 1.0 series. Site administrators running mixed-access configurations are strongly advised to upgrade immediately, especially if they rely on Datasette’s native permission model without additional authentication layers.

While the affected configuration — hosting both public and private tables in a single database under permission-based access control — is uncommon in practice, its existence poses real risk for organizations using Datasette for internal dashboards or hybrid public/private data portals. Simon Willison, Datasette’s creator, notes he hasn’t personally observed this setup in the wild, but stresses that the exploit was technically straightforward and required no elevated privileges beyond basic read access to a public table.

For most users deploying Datasette with either fully public or fully private databases — or using external auth plugins like datasette-auth-passwords — the risk is minimal. Still, this incident underscores how subtle logic flaws in permission enforcement can undermine otherwise robust security models — especially in tools designed for simplicity and rapid deployment.
