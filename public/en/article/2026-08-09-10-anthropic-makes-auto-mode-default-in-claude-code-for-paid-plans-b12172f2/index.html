Anthropic makes auto mode default in Claude Code for paid plans

News time: 2026-08-09T03:06:46.321358+00:00 · Source: rss

Starting August 14, 2026, Anthropic has flipped the switch: auto mode is now the default behavior for new sessions in Claude Code across Pro, Max, and Team plans. This isn’t just a UI tweak—it’s a strong signal of confidence. Internal adoption data shared during a recent Fireside Chat revealed that nearly every Anthropic employee already uses auto mode daily, citing its robustness against prompt injection and data exfiltration risks.

Auto mode works by routing all tool calls through an internal classifier that blocks irreversible, destructive, or environment-escaping actions—like deleting production files or connecting to external APIs without explicit context. Unlike manual approval workflows, it eliminates confirmation fatigue by removing routine 'OK' prompts while preserving safety guardrails. As Anthropic’s documentation explains, the system doesn’t just block obvious threats; it evaluates intent, context, and side effects before permitting any action.

The decision rests on empirical evidence. In a controlled study with 1,053 paid developers, participants were exposed to a single dangerous command mid-session—disguised as a normal request. Only 13.6% of humans refused it; auto mode blocked 89% of those same harmful actions. Even more striking: a third-party evaluation by Trajectory Labs tested 720 indirect prompt injection attempts across Claude Fable 5, Opus 5, and Sonnet 5—all running in auto mode—and reported zero successful attacks.

That said, the system isn’t perfect: 11% of harmful actions still slip through, and Anthropic openly acknowledges this limitation. The company emphasizes that auto mode is not about achieving 100% theoretical safety—but about delivering practically safer outcomes than human review alone. As one engineer noted, asking developers to approve every step invites error; auto mode shifts the burden from vigilance to architecture. For teams building with AI coding agents, this change marks a pivot toward trust-by-design—not just trust-by-verification.
