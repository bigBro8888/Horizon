Simon Willison releases alchemy-utils 0.1a0 for multi-database CLI operations

News time: 2026-08-13T03:32:13.543458+00:00 · Source: rss

Simon Willison — creator of the widely used sqlite-utils — has released alchemy-utils 0.1a0, an experimental Python library and CLI tool that brings sqlite-utils’ intuitive, file-first data operations to PostgreSQL, SQLite, and DuckDB. Unlike sqlite-utils, which is tightly coupled to SQLite’s embedded nature, alchemy-utils leverages SQLAlchemy as its database abstraction layer, enabling consistent behavior across engines while preserving familiar patterns like insert, upsert, create, and table introspection.

The project was conceived and prototyped in a single morning using LLM-assisted development: Willison gave Codex and GPT-5.6 Sol Ultra a precise prompt asking them to build a SQLAlchemy-backed version of sqlite-utils’ core API, test it against three databases, initialize with uv, and follow red/green TDD with pytest. Remarkably, only a few follow-up prompts were needed to produce a working alpha — including automated schema inference from CSV files and optimized bulk inserts.

A real-world example shows its utility: a one-liner using uvx can list rows from a PostgreSQL table in JSON format, complete with timestamps and nested objects. Another demonstrates loading San Francisco’s entire street tree dataset (over 100,000 rows) into DuckDB directly from a raw GitHub CSV URL — a task initially taking nearly an hour, later optimized by the LLM to ~35 seconds. These examples highlight how alchemy-utils bridges quick-and-dirty data exploration with production-ready database flexibility.

While still an alpha (0.1a0), the library already supports key workflows: inserting/upserting records, creating tables from data, updating rows, and inspecting schemas — all via both Python API and CLI. It uses optional extras ([postgresql], [duckdb]) to keep dependencies lean, and relies on modern tooling like uv for fast dependency resolution and execution. The design intentionally avoids ORM complexity, staying true to sqlite-utils’ philosophy: make common database tasks fast, discoverable, and scriptable — not abstracted away.
