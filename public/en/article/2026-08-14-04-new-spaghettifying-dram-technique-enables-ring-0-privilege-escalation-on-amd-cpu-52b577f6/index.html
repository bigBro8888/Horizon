New 'spaghettifying DRAM' technique enables ring-0 privilege escalation on AMD CPUs

News time: 2026-08-14T03:28:57.429642+00:00 · Source: hackernews

A groundbreaking hardware security technique dubbed 'spaghettifying DRAM'—introduced by veteran researcher Christopher Domas—demonstrates how subtle, undocumented behaviors in DRAM controllers can be weaponized to achieve full ring-0 (kernel-level) control on consumer-grade AMD processors. Unlike classic memory attacks such as Row Hammer—which relies on electrical disturbance between adjacent DRAM rows—this method exploits the timing and sequencing of DRAM controller register accesses, effectively turning memory timing parameters into programmable levers for control flow manipulation.

The core idea is deceptively simple: physical memory addresses are not rigidly enforced at the hardware level. By carefully crafting sequences of memory-mapped I/O (MMIO) writes to DRAM controller registers—particularly those governing refresh intervals, bank activation, and address mapping—the technique induces unpredictable but controllable side effects. One documented example flips a bit in a microcode patch location via xor dword [0xf80c2094], 0x00400000, bypassing traditional privilege checks entirely. This allows direct modification of firmware-resident code, including PSP (Platform Security Processor), SMM (System Management Mode), and even CPU microcode.

The proof-of-concept implementation, named skitter-creek-bath-salts, targets AMD’s Jaguar architecture (2013) and notes partial compatibility with Zen 3—though with different memory controller register base addresses. Crucially, it does not require software vulnerabilities, kernel bugs, or user-mode exploits: it operates purely through precise, low-level hardware interaction during early boot or from ring-0 context. As one commenter observed, this blurs the line between ‘memory access’ and ‘CPU configuration’, revealing how deeply intertwined modern DRAM controllers are with processor trust boundaries.

What makes this especially consequential is its implications beyond desktops. Consoles like PlayStation and Xbox rely heavily on custom AMD SoCs with tightly locked-down firmware—and yet, if their DRAM controllers expose similar MMIO surfaces, they may be vulnerable to privilege escalation that unlocks everything from hypervisor isolation to secure enclaves. The technique also highlights a broader trend: as memory subsystems grow more complex (e.g., UMC replacing DTC in Zen), their attack surface expands faster than documentation or mitigation efforts can keep up. For systems engineers, it’s a sobering reminder that ‘physical address’ is increasingly a fiction enforced only by software convention—not hardware guarantee.
