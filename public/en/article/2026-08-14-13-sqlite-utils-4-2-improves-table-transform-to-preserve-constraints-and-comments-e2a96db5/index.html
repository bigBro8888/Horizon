sqlite-utils 4.2 improves table transform to preserve constraints and comments

News time: 2026-08-14T03:28:57.121166+00:00 · Source: rss

sqlite-utils 4.2, released in August 2026, delivers a major upgrade to its table.transform() method—the library’s core mechanism for safely altering SQLite table schemas. Unlike SQLite’s native ALTER TABLE, which supports only limited changes (like renaming columns or adding new ones), table.transform() works by creating a new table with the desired schema, copying data over, and replacing the old table. This approach enables complex transformations such as column type changes, reordering, or dropping columns—but historically, it often lost fine-grained schema elements like CHECK constraints, UNIQUE constraints, and column comments.

The 4.2 release fixes that gap decisively. Now, when you call transform(), it preserves not just primary keys and indexes, but also check expressions (e.g., age > 0), unique constraints across multiple columns, and even SQL comments attached to columns via COMMENT ON COLUMN. This makes migrations far more reliable for production applications where data integrity rules are defined at the database level—not just in application code.

Equally important are the new introspection APIs introduced in this version. Developers can now programmatically inspect existing CHECK constraints using properties like table.checks, which returns a list of parsed constraint definitions—including the original SQL expression and affected columns. This fills a longstanding gap: prior to 4.2, retrieving CHECK constraints required parsing raw CREATE TABLE DDL output, a fragile and error-prone process.

The release also reflects strong community involvement, with contributions from five developers across features, tests, and documentation. Notably, the team quickly responded to a critical crash bug discovered shortly after launch—releasing 4.2.1 within days to resolve issue #842. That rapid iteration underscores sqlite-utils’ role as a mature, production-ready tool rather than just a convenience script. For Python developers managing SQLite-backed tools, notebooks, or lightweight apps, this update means safer, more transparent, and more maintainable schema evolution.
