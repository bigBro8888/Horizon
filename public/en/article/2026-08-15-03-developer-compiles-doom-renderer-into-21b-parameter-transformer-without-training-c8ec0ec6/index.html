Developer compiles Doom renderer into 21B-parameter transformer without training

News time: 2026-08-15T02:18:21.768058+00:00 · Source: reddit

In a striking demonstration of neural architecture as raw compute substrate, a developer has compiled the classic 1993 game Doom’s deterministic renderer — down to its precise ray-casting logic and texture mapping — directly into the fixed weights of a 21-billion-parameter transformer. Crucially, no gradient-based training was involved. Instead, the project uses a custom compiler called Torchwright that translates high-level computation graphs — written in Python and representing Doom’s rendering pipeline — into analytically derived transformer weights. The resulting model is a standard Hugging Face-compatible checkpoint: it loads with trust_remote_code=False, runs inference via autoregressive token generation, and outputs a sequence of low-level drawing commands (e.g., 'move cursor', 'draw pixel') rather than pixels directly.

The host program that orchestrates this is just 43 lines of Python: it feeds scene state (player position, angle, level geometry) as a 3,614-token prompt, then decodes 53,747 tokens over ~40 minutes on an NVIDIA B200 GPU. Parsing those tokens mechanically reconstructs the iconic E1M1 frame — pixel-perfect, deterministic, and fully reproducible. This isn’t emulation or approximation; it’s compilation: the same algorithm that ran on a 486 CPU in 1993 now executes inside transformer attention and feed-forward layers, albeit at 35 frames per day instead of 35 frames per second.

The technical foundation rests on treating transformers not as statistical pattern recognizers, but as programmable state machines. Torchwright maps each operation in Doom’s renderer — integer arithmetic, memory indexing, conditional branching — onto transformer submodules using analytical weight construction: attention heads encode control flow, MLPs implement arithmetic, and positional encoding carries iteration state. No learned inductive bias is leveraged; every weight is derived from symbolic constraints. The result challenges a foundational assumption in deep learning: that large language models must be trained to become useful. Here, usefulness emerges from correct compilation — like writing assembly for a neural CPU.

While impractical for real-time gaming, the experiment opens new conceptual ground. It bridges program synthesis, mechanistic interpretability, and neural compilation — showing that transformers can serve as executable specifications, not just statistical surrogates. As one commenter noted, this reframes the question from 'What can transformers learn?' to 'What can they compute — if we treat them as hardware?' The full write-up, weights, and source code are publicly available, inviting replication and extension to other deterministic algorithms.
