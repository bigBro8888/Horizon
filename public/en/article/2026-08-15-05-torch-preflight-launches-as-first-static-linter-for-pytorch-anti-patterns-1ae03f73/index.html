torch-preflight launches as first static linter for PyTorch anti-patterns

News time: 2026-08-15T02:18:21.768488+00:00 · Source: reddit

A new open-source tool called torch-preflight is making waves among PyTorch developers — not by speeding up training or adding new layers, but by preventing costly mistakes before a single line of code runs. Built as a static linter, it scans Python source files without importing or executing them, meaning no GPU, no PyTorch installation, and zero runtime overhead. Its core mission is to catch subtle but widespread coding errors that silently inflate GPU memory usage, cause training crashes, or lead to incorrect gradients — problems that often waste hours or even days of compute time.

The tool currently enforces 13 rules targeting PyTorch-specific pitfalls. These include forgetting optimizer.zero_grad() inside training loops (causing gradient accumulation across iterations), appending un-detached loss tensors to lists (which retains the entire autograd graph), misusing gradient accumulation without scaling the loss, and configuring DistributedDataParallel (DDP) without a DistributedSampler — a classic mistake where all processes train on identical data batches instead of sharded subsets. Each detection comes with actionable feedback, not just warnings.

Beyond bug detection, torch-preflight includes an experimental VRAM estimator. Given a training script and target GPU model (e.g., T4, A100), it predicts peak memory consumption and suggests concrete code changes — like reducing batch size or disabling gradient checkpointing — along with the GiB saved per change. The author reports estimates within 4% of measured peaks across four models on a T4, though notes this is early validation.

Unlike general-purpose Python linters or even prior PyTorch-focused tools like torchfix (which focuses on API deprecations and basic device mismatches) or torchlint (a minimal device/size checker), torch-preflight uniquely targets training-loop logic and distributed setup correctness. It fills a critical gap: while PyTorch’s flexibility empowers researchers, it also enables silent failures — bugs that don’t crash immediately but corrupt results or exhaust memory after hundreds of steps. As one developer put it, ‘My work went into dump because of some mistake I made in the code’ — a sentiment many ML engineers recognize all too well.
