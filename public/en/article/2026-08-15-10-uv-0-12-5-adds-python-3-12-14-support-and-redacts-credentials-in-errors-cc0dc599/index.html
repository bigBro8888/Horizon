uv 0.12.5 adds Python 3.12.14 support and redacts credentials in errors

News time: 2026-08-15T02:18:21.705255+00:00 · Source: github

Astral-sh’s uv — the blazing-fast, Rust-powered Python package manager — has shipped version 0.12.5, released on August 14, 2026. This patch release delivers practical improvements across interpreter management, security hygiene, and software supply chain tooling. While not a major version bump, it reflects uv’s rapid iteration cycle and growing maturity as a production-ready alternative to pip and virtualenv.

The update expands Python version support with official compatibility for CPython 3.10.21, 3.11.16, and 3.12.14 — ensuring developers can adopt the latest stable patch releases without waiting for tooling lag. More subtly, uv now prefers newer and standard Python variants when multiple interpreters are equally viable — a small but meaningful refinement to its automatic interpreter selection logic. This helps avoid outdated or non-standard builds (e.g., freethreaded or debug variants) unless explicitly requested.

Security receives focused attention: uv now redacts credentials (like usernames and passwords) embedded in private index URLs when displaying error messages. Previously, such sensitive data could leak into logs or terminal output during failed installs — a real risk in CI environments or shared terminals. The change applies to invalid editable requirements too, where clearer, simplified error hints help diagnose malformed PEP 508 dependency strings.

Two preview features stand out for advanced users. First, named index selection — enabled via the index-by-name preview flag — lets teams configure indexes by alias (e.g., --index internal-pypi) instead of full URLs, improving readability and maintainability in large-scale Python deployments. Second, CycloneDX SBOM exports now include artifact URLs and cryptographic hashes by default, enriching software bills of materials for compliance and vulnerability scanning. A minor but useful fix also ensures relative index paths in PEP 723 inline scripts resolve correctly against the script’s directory — closing a long-standing edge-case bug.
