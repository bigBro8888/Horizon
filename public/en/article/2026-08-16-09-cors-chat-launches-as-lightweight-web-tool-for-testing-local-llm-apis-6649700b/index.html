CORS Chat launches as lightweight web tool for testing local LLM APIs

News time: 2026-08-16T02:33:37.403968+00:00 · Source: rss

CORS Chat is a new open web tool designed to simplify local development and debugging of large language model (LLM) chat endpoints—especially those running on personal machines via tools like LM Studio. Built by developer Simon Willison in a single day, it provides a clean, no-install browser interface that communicates directly with OpenAI-compatible API endpoints, bypassing common cross-origin restrictions that normally block such requests from frontend code.

The tool’s core value lies in its practical handling of CORS (Cross-Origin Resource Sharing), a security mechanism enforced by browsers. When developers run an LLM locally—say, Qwen 3.8 27B in LM Studio—they often need to enable the --cors flag to allow web apps to talk to it. CORS Chat assumes that configuration is already in place and focuses instead on usability: letting users send messages, view streaming responses, and persist conversations in browser storage without backend dependencies.

One standout feature is real-time SVG rendering. As models generate SVG code token-by-token during streaming, CORS Chat detects <svg> tags mid-response and renders the image incrementally—even before the full message completes. This is especially useful for multimodal or code-generation workflows where visual feedback matters early. A screenshot shows five overlapping, semi-transparent colored squares rotating around a center, rendered live from a prompt asking simply to "render an svg of five intersecting squares."

CORS Chat works with any OpenAI-compatible endpoint—including LM Studio (with --cors), OpenRouter, and other inference servers like vLLM or Cloudflare Workers AI. Conversations are saved locally in the browser and can be exported as JSON for sharing or replay. There’s no sign-up, no telemetry, and no server component: it’s pure client-side JavaScript, making it fast, private, and easy to self-host or extend. For frontend developers building LLM-powered UIs—or researchers prototyping local models—it fills a small but persistent gap between local inference and browser-based interaction.
