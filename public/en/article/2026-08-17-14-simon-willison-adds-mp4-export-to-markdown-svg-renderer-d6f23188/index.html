Simon Willison adds MP4 export to Markdown SVG renderer

News time: 2026-08-17T02:33:18.655109+00:00 · Source: rss

Simon Willison has upgraded his open-source markdown-svg-renderer tool with a notable new capability: converting animated SVGs embedded in Markdown documents directly into downloadable MP4 videos — all inside the browser. The tool, originally launched in May 2026, began as a simple utility for rendering Markdown that includes raw SVG code blocks. But it has since evolved into a versatile documentation and visual storytelling aid — especially useful for developers and technical writers who want to embed rich, interactive graphics without leaving the Markdown ecosystem.

The workflow is refreshingly lightweight. Users can either paste Markdown directly into the web interface or load it from an external URL — such as a GitHub Gist — by appending a #url= fragment to the tool’s address. This makes rendered pages fully bookmarkable and shareable. For example, a Gist containing an animated SVG of a rotating compass circle becomes an instantly viewable, tabbed interface where users can toggle between ‘Rendered’, ‘PNG’, ‘JPEG’, ‘MP4’, and ‘Code’ views.

The real innovation lies in the MP4 tab, introduced in a recent commit. When activated, the tool analyzes the SVG for animation elements (e.g., <animate> tags or CSS @keyframes), estimates loop duration, renders dozens of frames using Canvas, then loads ffmpeg.wasm — a full WebAssembly port of FFmpeg — to stitch those frames into a video. Despite the heavy lifting, everything happens client-side: no server upload, no backend processing, and no data leaves the user’s browser.

This approach solves a persistent friction point: many platforms (like Slack, Twitter/X, or static site generators) don’t support animated SVGs natively. Converting them to MP4 preserves motion while ensuring broad compatibility. And because the tool supports CORS-friendly sources like GitHub Gists (which serve raw content with appropriate headers), it works reliably across domains without requiring proxy workarounds. While niche in scope, the upgrade reflects a growing trend in client-side tooling — leveraging modern browser capabilities like WebAssembly to shift complex media tasks from servers to users’ machines.
