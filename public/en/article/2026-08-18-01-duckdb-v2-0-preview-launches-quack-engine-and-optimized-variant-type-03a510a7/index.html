DuckDB v2.0 preview launches Quack engine and optimized VARIANT type

News time: 2026-08-18T02:20:11.644320+00:00 · Source: hackernews

DuckDB v2.0 is not just an incremental upgrade — it’s a strategic expansion of what an embedded analytical database can do. The preview release, announced on August 17, 2026, introduces three foundational innovations: the Quack query engine, a reimagined VARIANT type for semi-structured data, and significantly improved out-of-core scalability. Together, these changes blur the line between embedded analytics and cloud-scale data processing — without sacrificing DuckDB’s signature speed or simplicity.

Quack is perhaps the most consequential addition. Unlike traditional client-server layers bolted onto embedded engines, Quack is a lightweight, HTTP-based remote protocol where every client is also a full DuckDB instance. This means queries can natively federate across local files and remote DuckLake tables, plan joins across endpoints, and support true multi-writer concurrency — something long cited as DuckDB’s biggest architectural limitation. Early adopters are already using Quack to power notebook-to-notebook workflows and browser-based analytics dashboards that talk directly to a DuckDB server.

The VARIANT type — first introduced in v1.5 — has been deeply optimized for v2.0. It now automatically detects recurring schema patterns in heterogeneous JSON-like data (e.g., logs, API payloads), then ‘shreds’ and compresses them column-wise like native DuckDB types. This avoids the space bloat and slow parsing of text-based JSON while preserving full type fidelity — including timestamps, geospatial objects, and nested arrays. Users report up to 5× storage reduction over raw JSON in Parquet files with mixed schemas.

Beyond performance, v2.0 strengthens DuckDB’s role in production pipelines. Engineers at multiple companies now run real-time analytics, dbt transformations, and stream-processing backends on DuckDB — even on consumer laptops — thanks to its new ability to spill large intermediate results to disk without crashing or slowing down. As one developer put it: 'It’s no longer just for exploration — it’s my runtime database.' That shift signals a broader trend: analytical engines are converging toward unified, embeddable, and scalable primitives — and DuckDB is leading that evolution.
