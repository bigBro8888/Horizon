Google replaces Android source code Git tags with manual Google Drive requests

News time: 2026-08-20T02:21:36.684463+00:00 · Source: hackernews

Google has quietly changed how developers and auditors can obtain certain Android open-source components: instead of publishing standardized, automated Git tags — the industry-standard method for marking and retrieving specific software versions — Google now requires users to submit a Google Form and wait for a human to email a Google Drive link. This shift affects parts of the Android Open Source Project (AOSP) that include GPLv2-licensed code, such as kernel modules and firmware blobs previously distributed via public Git repositories.

The change undermines core expectations of open-source licensing. Under GPLv2, anyone who distributes GPL-covered software must make the corresponding source code 'as available as the object code' — meaning it must be readily accessible, reproducible, and machine-processable. Git tags fulfill this by enabling deterministic, scriptable, and verifiable retrieval of exact source snapshots. In contrast, a manual form-and-email workflow introduces delays, inconsistency, lack of auditability, and no guarantee of timely or complete delivery.

This isn’t Google’s first step away from open-source norms. Historically, AOSP has been only partially open: while core frameworks are public, critical drivers, firmware, and hardware abstraction layers often remain proprietary or gated. Still, the Git tag mechanism was one of the few reliable, automated compliance channels for GPLv2 obligations — especially for security researchers, downstream OS projects like GrapheneOS, and compliance auditors. Replacing it with an opaque, centralized, non-scalable process raises serious questions about intent and adherence.

Critics point out that the new process is already failing in practice: reports indicate long delays, inconsistent responses, and no public SLA or status tracking. As one commenter noted, it’s so cumbersome that ‘in a few years they’ll mail you a printed copy.’ While Google hasn’t publicly justified the change, speculation includes internal tooling shifts, reduced engineering bandwidth, or tighter control over distribution — none of which excuse GPLv2 noncompliance. For the broader ecosystem, this erodes trust in corporate open-source stewardship and sets a dangerous precedent for other vendors.

Ultimately, this isn’t just about convenience — it’s about whether ‘open source’ still means legally enforceable access. If source code distribution becomes discretionary rather than automatic, the license’s copyleft promise collapses.
