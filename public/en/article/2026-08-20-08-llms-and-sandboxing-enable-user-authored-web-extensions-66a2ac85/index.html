LLMs and sandboxing enable user-authored web extensions

News time: 2026-08-20T02:21:36.402141+00:00 · Source: rss

Jeremy Morrell’s recent essay proposes a compelling shift in how we think about extensible web applications—not as developer-only plugins, but as user-empowered, AI-assisted capabilities built on secure foundations. His core idea is simple yet transformative: modern large language models (LLMs) dramatically reduce the effort required to write functional code, while advances in browser and server-side sandboxing—like WebAssembly modules, SES (Secure EcmaScript), and Linux seccomp—now allow that code to run with strict, predictable boundaries. Together, they unlock a new kind of software architecture: a minimal, auditable application core paired with user-generated extensions that operate safely alongside it.

This isn’t just about convenience—it’s about redefining agency. Historically, extending software meant writing code in a specific language, compiling it, passing security reviews, and waiting for vendor approval. Today, a user could describe a desired behavior in plain English—‘highlight all deadlines in my calendar view’—and an LLM could generate a lightweight, sandboxed extension that runs only within their own session, with no access to credentials or other tabs. The app remains stable and accountable; the user gains flexibility without compromising safety.

The technical enablers are maturing rapidly. Browser vendors now support tighter execution contexts via iframe sandbox attributes, Web Workers with limited APIs, and experimental features like Trusted Types and Policy Containers. On the server side, tools like Figma’s server-side sandboxing isolate untrusted code execution from sensitive infrastructure. Meanwhile, Rust-based sandboxes using seccomp and Landlock (as demonstrated in recent guides) show how even native binaries can be constrained with fine-grained system call filtering. These aren’t theoretical—they’re production-ready primitives being adopted by major platforms.

What makes Morrell’s vision especially timely is its alignment with real-world pain points: users want customization but distrust opaque third-party extensions; developers want flexibility but fear complexity and liability. By decoupling the trusted core from the generative periphery, this model offers a middle path—one where extensibility doesn’t mean sacrificing security or maintainability. It’s not about replacing developers, but amplifying users’ ability to shape tools around their unique workflows.
