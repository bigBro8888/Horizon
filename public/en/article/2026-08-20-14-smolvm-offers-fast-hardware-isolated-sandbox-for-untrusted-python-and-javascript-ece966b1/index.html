smolvm offers fast hardware-isolated sandbox for untrusted Python and JavaScript

News time: 2026-08-20T02:21:36.402100+00:00 · Source: rss

Simon Willison recently published a hands-on research report exploring smolvm — a portable, lightweight virtual machine designed specifically for secure, resource-constrained execution of untrusted code. His goal was practical: evaluate whether smolvm could serve as a production-ready sandbox for user-provided data transformation scripts written in Python or JavaScript. Such a capability is increasingly vital for platforms that accept arbitrary code — from AI-powered workflow tools to no-code data processors — where safety hinges on strict CPU time limits, memory caps, zero network access, and tightly controlled filesystem permissions.

Willison’s investigation began inside Claude Code for web, an LLM-powered coding environment. But he quickly hit a hard technical wall: the underlying Firecracker VM lacks nested virtualization support (no /dev/kvm, no vmx/svm CPU flags), making it impossible to run smolvm — which relies on hardware-assisted virtualization for isolation. Rather than abandoning the test, Willison’s AI assistant, Claude Fable 5, devised ‘Plan B’: shift the evaluation to GitHub Actions Ubuntu runners, which do expose /dev/kvm. There, smolvm was installed and rigorously tested using custom shell scripts — validating its ability to boot rapidly, enforce resource limits, and isolate untrusted workloads.

According to public documentation and benchmarks, smolvm boots in ~125ms and adds only ~5MB memory overhead — performance metrics that rival AWS Lambda’s internal micro-VM infrastructure. It supports Firecracker, QEMU, and libkrun under a unified API, and unlike traditional hypervisors, it ships as a single, daemonless binary. Crucially, it delivers true hardware isolation — not just process-level sandboxing — meaning malicious or buggy code cannot escape its VM boundary, even if it attempts infinite loops or memory exhaustion.

The broader context is clear: existing WebAssembly-based sandboxes (e.g., WAMR + Zephyr) offer strong memory isolation but lack full language runtime compatibility — especially for Python’s C extensions or Node.js native modules. smolvm bridges that gap by running real OS environments (Linux guests) with full language support, while retaining micro-VM efficiency. For developers building safe code-execution services — like E2B, Vercel Sandbox, or custom AI agent runtimes — smolvm represents a compelling middle ground between heavyweight VMs and insufficiently isolated containers or Wasm runtimes.
