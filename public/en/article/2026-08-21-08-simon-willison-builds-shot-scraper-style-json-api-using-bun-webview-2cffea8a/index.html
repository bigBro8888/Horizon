Simon Willison builds shot-scraper-style JSON API using Bun.WebView

News time: 2026-08-21T02:36:16.449288+00:00 · Source: rss

Simon Willison has released a working prototype of a lightweight, web-based JSON API that loads pages and executes arbitrary JavaScript in a browser context — all powered by Bun 1.4’s newly stabilized Bun.WebView API. The project, documented in his research repository, directly mirrors the behavior of his popular shot-scraper CLI tool — which traditionally captures screenshots or extracts data by running JavaScript in headless browsers — but reimagines it as an HTTP service with clean JSON input and output.

This isn’t just a proof-of-concept: Willison deployed and stress-tested the server under realistic conditions, measuring memory usage via cgroups on Linux. His findings show the service consumes between 192 MB and 256 MB of RAM when driving a full Chromium instance to render and interact with complex, modern websites — a meaningful benchmark for developers evaluating Bun.WebView’s production readiness. Notably, he used Claude Code to help scaffold the initial TypeScript implementation, highlighting how AI-assisted development is accelerating experimentation with new runtime features.

The release of Bun 1.4 marks a major milestone: it’s the first stable version since Bun’s controversial rewrite from Zig to Rust — a shift downplayed in official release notes but confirmed in Willison’s earlier reporting. While the changelog touts over 2,900 bug fixes and dramatic performance gains (5× lower idle CPU, up to 35% less memory, 50% faster startup on Linux), Bun.WebView stands out as one of the most consequential new APIs. It offers native, cross-platform browser automation: WKWebView on macOS, and Chrome DevTools Protocol–driven Chromium on Linux and Windows — no external dependencies or Docker layers required.

Unlike traditional scraping tools that rely on Puppeteer or Playwright, this Bun-native approach eliminates process spawning overhead and simplifies deployment. Developers can now embed browser automation directly into their Bun servers — ideal for dynamic rendering, client-side JS evaluation, or real-time DOM analysis. Willison’s API design reflects practical constraints: it accepts a URL and optional JavaScript code, returns serialized DOM state or script results as JSON, and avoids persistent sessions to keep memory predictable. This makes it especially relevant for serverless or containerized environments where resource efficiency matters.
