Telling LLMs to be concise cuts API costs by up to 3x without hurting accuracy

News time: 2026-08-22T02:20:09.071384+00:00 · Source: reddit

A new empirical study has quantified a widely suspected but rarely measured intuition: asking large language models to produce shorter outputs meaningfully reduces API costs—by up to 3× in some cases—while preserving answer accuracy. Researchers tested this across nine diverse models, including GPT-4o, Claude Sonnet 4.6, Qwen2.5-VL-7B, DeepSeek-R1-Distill, and Kimi-K2.6, using five short-answer benchmarks and an eleven-language evaluation (English, German, Spanish, French, Swahili, Chinese, Japanese, Russian, Bengali, Thai, Telugu), plus a longer summarization task.

The experiment compared two strategies: compressing the input prompt (e.g., truncating or simplifying instructions) versus adding explicit output constraints like "be concise" or using Anthropic’s new built-in concise output style in Claude Code. Results were unambiguous: output-directed concision consistently reduced token usage—and thus cost—without degrading performance. On average, models became ~1.5× cheaper to run; for GPT-4o and Claude Haiku, savings reached 3×. Crucially, this held across all eleven languages tested, suggesting robustness beyond English-centric settings.

In stark contrast, shortening input prompts backfired. In many cases, models responded with longer, less accurate answers—likely attempting to compensate for missing context—increasing cost by up to 96% on certain benchmarks. The paper explains this as a side effect of how LLMs allocate attention and reasoning effort: when input is stripped, they often over-generate to fill perceived gaps. Meanwhile, constraining output directly targets the most expensive part of inference—output tokens—which typically cost more per token than input tokens, especially on modern APIs.

The study also uncovered a subtle but important nuance: when concise outputs were correct, roughly half the time the actual text no longer matched the model’s unconstrained reasoning path. That is, the model arrived at the right answer—but via a different internal route. For most production use cases where only the final answer matters (e.g., classification, fact extraction, code generation), this trade-off is acceptable—and beneficial. With providers now baking concise modes into tools like Claude Code, the findings empower developers to optimize cost/quality balance deliberately, not just intuitively.
