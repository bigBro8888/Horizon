Cobalt brings native app support to Kobo e-readers

News time: 2026-08-22T02:20:08.619237+00:00 · Source: hackernews

Kobo e-readers have long been beloved by tinkerers for their open firmware and Linux roots — but until now, running third-party software meant patching Nickel (Kobo’s native UI) or installing full alternative OSes like PostmarketOS. That changes with Cobalt, a new open-source application platform designed specifically for Kobos. Announced via BandarLabs’ GitHub and documentation site, Cobalt provides a secure, capability-isolated runtime, a Rust-based SDK, a signed app store, and a lightweight launcher — all installable with a single USB connection. After setup, users can download and update apps over Wi-Fi, turning their e-ink device into a modest but purpose-built Linux-adjacent appliance.

Unlike earlier hacks that inject code into Nickel or replace the entire system, Cobalt operates as a parallel environment: it doesn’t modify Nickel itself, nor does it require booting a different kernel or distribution. Instead, it leverages Kobo’s existing embedded Linux base — a stripped-down BusyBox-based system — and adds a sandboxed userspace layer where apps run with strict permissions (e.g., no direct hardware access unless explicitly granted). The framework currently supports dual-core Kobo models like the Clara Colour and Libra 2, but notably excludes single-core devices such as the Clara BW due to memory and performance constraints.

The implications go beyond novelty. For developers, Cobalt lowers the barrier to building useful tools — think highlight searchers, note syncers, or even lightweight web readers — without deep firmware expertise. For power users, it offers a middle path between NickelMenu’s menu-driven extensions and full OS replacements like PostmarketOS, which demand more technical overhead and sacrifice battery life and e-ink responsiveness. One Hacker News commenter noted they’d finally be able to build an app to review and search their saved quotes — a common pain point in long-form reading workflows.

Still, Cobalt isn’t for everyone. As several commenters pointed out, many readers deliberately choose e-readers for their minimalism and distraction-free design. Adding games, browsers, or notifications runs counter to that ethos — and Cobalt doesn’t enforce usage boundaries. Its success will depend less on technical ambition and more on whether the community coalesces around thoughtful, reading-centric apps rather than feature bloat. For now, it represents not a revolution, but a meaningful evolution: one more step toward making open e-readers truly programmable.
