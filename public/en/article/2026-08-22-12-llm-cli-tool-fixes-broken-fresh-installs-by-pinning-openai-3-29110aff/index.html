LLM CLI tool fixes broken fresh installs by pinning OpenAI <3

News time: 2026-08-22T02:20:08.251209+00:00 · Source: rss

The LLM command-line tool — a popular open-source utility for interacting with large language models directly from the terminal — has released version 0.32.1 to resolve an urgent dependency breakage. Users attempting fresh installations over the past few days found the tool failing to start or configure properly. The root cause was traced to the official OpenAI Python library’s recent v3.0 release, which dropped support for the httpx HTTP client entirely. Since LLM had relied on httpx indirectly — via transitive dependencies pulled in by older versions of openai — the removal left LLM without a working HTTP client, breaking core functionality like API calls to OpenAI and compatible endpoints.

This patch is intentionally minimal and pragmatic: instead of rewriting integration logic immediately, the maintainers pinned the openai dependency to <3, ensuring compatibility with the last version that still bundled httpx. It’s a classic stopgap — fast, low-risk, and effective for users right now. Meanwhile, the team has already prepared the next step: version 0.33, scheduled for imminent release, will migrate LLM’s HTTP layer to httpx2, the newly stewardship-led successor to httpx maintained by Pydantic Services.

httpx2 isn’t just a rename — it’s a modernized, actively developed HTTP client built for Python 3.10+, with improved async ergonomics, stricter type safety (leveraging Pydantic’s validation), and better observability. Its adoption signals LLM’s commitment to sustainable, forward-looking infrastructure — especially important as more local and open-weight models rely on custom or self-hosted OpenAI-compatible APIs. Unlike many CLI tools that treat dependencies as black boxes, LLM’s transparent handling of this breakage reflects strong maintenance discipline.

For developers and power users who depend on LLM for scripting, automation, or local AI workflows (e.g., with Ollama or LM Studio), this fix restores reliability overnight. It also serves as a quiet reminder of how fragile the modern Python ecosystem can be when critical libraries drop backward compatibility without clear deprecation paths — and how vital it is for downstream tools to own their HTTP stack rather than inherit it indirectly.
