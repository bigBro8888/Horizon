Developers should stop building terminal UIs for personal tools

News time: 2026-08-22T02:20:08.251277+00:00 · Source: rss

Simon Willison’s August 2026 blog post ‘Stop Making TUIs’ amplifies a growing sentiment in the developer tooling community: that terminal-based user interfaces (TUIs) — once the default for quick, personal CLI utilities — are no longer the pragmatic choice. He credits Thomas Ptacek’s earlier essay with crystallizing the argument: thanks to modern native frameworks like SwiftUI and the accelerating capabilities of AI coding agents, building a lightweight, functional GUI is now faster and less costly than maintaining even a polished TUI.

Willison points to his own experience as evidence. Earlier this year, he built two macOS menu bar apps — one monitoring GPU usage and another tracking coding ‘vibe’ (a playful proxy for focus or flow state) — using SwiftUI. Both are small, single-purpose tools, yet they run natively, integrate smoothly with macOS system UI conventions (like dark mode and menu bar popovers), and have become part of his daily workflow. Crucially, he didn’t need deep macOS expertise or months of development time; instead, he leaned on AI-assisted iteration and SwiftUI’s declarative syntax to ship usable interfaces rapidly.

The core claim isn’t that TUIs are obsolete in all contexts — they remain essential for remote administration, server-side tooling, and environments where graphical stacks aren’t available. Rather, the argument targets personal, local-first tools: scripts you’d otherwise write as bash/Python CLIs and pipe together in a terminal. For those, Ptacek insists, skipping straight to a native GUI removes friction for yourself and others — offering discoverability, visual feedback, drag-and-drop, and accessibility features out of the box. As Willison puts it: “I’m not habitually knocking out real UIs for my other projects yet, but I’m running out of excuses!”

This shift reflects broader changes in the developer toolchain. Frameworks like SwiftUI (for macOS/iOS) and Tauri (for cross-platform desktop apps) lower the barrier to native GUI development, while LLM-powered coding assistants help bridge knowledge gaps — generating boilerplate, debugging layout issues, or suggesting platform-specific patterns. The result isn’t pixel-perfect enterprise software, but ‘usable-enough’ interfaces that feel native, load instantly, and live alongside your other apps — not buried in a terminal tab.
