llm 0.33 adds per-call API keys for embeddings and upgrades to httpx2

News time: 2026-08-23T02:36:19.354790+00:00 · Source: rss

The llm command-line tool — a popular open-source utility for interacting with large language models from the terminal — has released version 0.33, delivering several practical enhancements for developers working with embeddings, model configuration, and HTTP infrastructure.

Most notably, the llm embed and llm embed-multi commands now accept a --key flag, allowing users to specify an API key for individual embedding calls without altering global or model-level settings. This change mirrors how LLM models already handle keys, bringing consistency across the tool’s architecture. Under the hood, the Python APIs (EmbeddingModel.embed(), Collection.embed(), etc.) also support a key= parameter, passing the value directly to plugins while preserving backward compatibility: existing plugins that read self.key continue to function via a fallback mechanism.

The release also modernizes the underlying HTTP stack by upgrading the OpenAI Python library to version 3.x and replacing the httpx dependency with httpx2 — a Pydantic-maintained successor offering improved performance, full HTTP/2 support, and both synchronous and asynchronous APIs. This switch addresses long-standing issues around connection reuse and streaming reliability, especially important for high-throughput embedding workloads.

Additional improvements include template composition: the -t or --template flag in llm prompt can now be repeated to layer multiple templates — for example, combining a model preset (e.g., gpt-5.6-luna with reasoning_effort high) with a task-specific prompt (e.g., "Generate an SVG of a pelican riding a bicycle"). This enables reusable, composable configurations without duplicating flags. Finally, reasoning-capable models using the OpenAI Responses API now support a reasoning_summary option (auto, concise, or detailed), giving fine-grained control over output verbosity when testing alternative implementations.

While not a groundbreaking release, llm 0.33 reflects thoughtful evolution — tightening abstractions, improving interoperability, and reducing friction for real-world CLI workflows. It’s a quiet but meaningful step toward more robust, maintainable, and developer-friendly LLM tooling.
