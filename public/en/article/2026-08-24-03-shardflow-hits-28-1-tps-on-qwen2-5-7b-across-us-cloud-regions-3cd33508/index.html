ShardFlow hits 28.1 TPS on Qwen2.5-7B across US cloud regions

News time: 2026-08-24T02:36:12.545704+00:00 · Source: reddit

A new open-source framework called ShardFlow has demonstrated unprecedented performance for distributed large language model (LLM) inference over high-latency public networks. In a recent benchmark, it achieved 28.10 tokens per second (TPS) peak throughput on the Qwen2.5-7B model — running across two physically distant Google Cloud Platform (GCP) regions: Iowa and Oregon. Communication between them occurred over the public internet, with an 86ms round-trip time (RTT), routed through an AWS EC2 TCP relay in Ohio. This setup mirrors real-world multi-cloud or edge-to-cloud deployments where low-latency interconnects are unavailable.

The breakthrough hinges on two tightly integrated techniques: neural speculative decoding and CUDA Graphs. Speculative decoding lets a smaller 'drafter' model rapidly generate K=8 candidate tokens ahead of the main 'target' model. Instead of waiting for each token one-by-one — a latency bottleneck over WAN — the system amortizes the 86ms RTT across a full draft-and-verify round. That transforms what was once a per-token penalty into a per-round cost, effectively boosting throughput by more than fivefold compared to the non-speculative baseline of just 4.92 TPS.

CUDA Graphs delivered another massive win — especially for the drafter. Early profiling revealed that Python-driven kernel launches were starving the GPU: ~1500 CUDA kernels per round, each taking 2–5 microseconds to launch, plus 8–10 microseconds of Python overhead. The GPU sat idle 65% of the time. By capturing the entire 0.5-billion-parameter forward pass as a single static CUDA Graph and replaying it with one driver call, draft latency plummeted from 112ms to 25ms. Additional optimizations include a zero-copy Rust-based TCP relay, StaticCache with in-place KV cache rewinding for graph compatibility, and meta-device model slicing to avoid loading the full 15GB model into CPU RAM.

ShardFlow also scales to larger models: on Qwen2.5-14B with NF4 4-bit quantization, it sustained 14.43 TPS average across the same two-node WAN setup. The project is fully open source, with implementation details and benchmarks published on GitHub. Its design explicitly targets production constraints — not synthetic lab conditions — making it a rare and valuable reference for engineers building globally distributed LLM services.
