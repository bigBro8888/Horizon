llm-anthropic 0.27 updates plugin for Anthropic’s new Python SDK

News time: 2026-08-25T02:22:44.623900+00:00 · Source: rss

The llm-anthropic plugin — a lightweight extension that lets the LLM command-line tool interface with Anthropic’s Claude models — has released version 0.27. This update ensures full compatibility with Anthropic’s newly launched v1.0.0 Python SDK, which marks a major internal shift: the library has replaced its HTTP client from httpx to the next-generation httpx2. The change mirrors a similar move by OpenAI, whose Python SDK also migrated to httpx2 in its v3.0.0 release just two weeks earlier.

This isn’t a feature-driven release but a necessary maintenance update. Developers using llm with Anthropic models — for tasks like prompting Claude Sonnet via CLI commands or integrating into local AI workflows — would encounter import errors or runtime failures without this upgrade. The maintainer, Simon Willison, used Claude Code (powered by Fable 5) to automate much of the migration work, feeding it Anthropic’s official MIGRATION.md guide and asking it to adapt the plugin’s code and tests. The resulting pull request (#84) reflects a pragmatic, tool-assisted approach to keeping open-source integrations current.

Behind the scenes, httpx2 represents more than just a rename: it’s a reimagined, Pydantic-led evolution of the popular httpx library — designed for better type safety, async ergonomics, and tighter integration with modern Python tooling like Pydantic V2. While end users won’t notice visual changes, the upgrade strengthens reliability, improves error messaging, and aligns the plugin with broader ecosystem trends toward stricter typing and composability.

For developers, the takeaway is straightforward: if you rely on llm-anthropic, upgrading to 0.27 is now required to use Anthropic’s latest SDK. It’s a small but critical link in the chain — ensuring that CLI-based LLM experimentation remains frictionless even as underlying libraries mature. In an ecosystem where SDKs evolve rapidly, such timely, low-friction updates are what keep developer tools alive.
