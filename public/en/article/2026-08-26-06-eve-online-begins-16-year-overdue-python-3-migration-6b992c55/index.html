EVE Online begins 16-year overdue Python 3 migration

News time: 2026-08-26T02:38:27.551754+00:00 · Source: rss

After nearly two decades of reliance on a highly customized Python runtime, CCP Games has officially begun migrating EVE Online’s core backend from Stackless Python 2.7 to modern Python 3. This isn’t just another version bump—it’s the largest and most consequential Python migration in gaming history. Launched in 2003, EVE Online was built around Stackless Python to power its massively concurrent universe: thousands of players interacting in real time across a single persistent server cluster. That architecture depended critically on Stackless’s microthreads (tasklets), lightweight coroutines, and cooperative scheduling—features absent in standard CPython.

The migration kicks off with the futurize tool, which will automatically transform 2.4 million lines of legacy Python code into syntactically valid Python 3. But automation only goes so far: engineers must manually audit roughly 20,000 locations where Python 2 and 3 behave differently—notably integer division (1 / 2 yields 0 in Python 2 but 0.5 in Python 3), string handling, exception syntax, and iterator behavior. These subtle behavioral shifts could break game logic, economy calculations, or AI routines if left unexamined.

Crucially, this move also marks the end of Stackless as a runtime dependency. While the announcement doesn’t detail how Stackless functionality will be replaced in EVE Online’s older Tranquility server, CCP has already solved this problem elsewhere: for their newer title EVE Frontier, they open-sourced the carbonengine/scheduler library—a custom coroutine scheduler that replicates Stackless’s tasklet model without relying on forked Python binaries. That same scheduler is expected to underpin the new EVE Online backend.

The stakes are exceptionally high. Unlike web apps or internal tools, EVE Online’s backend cannot afford downtime, race conditions, or silent correctness errors—its virtual economy, player-owned structures, and real-time combat depend on deterministic, auditable behavior. A failed migration could disrupt live gameplay for over 300,000 concurrent players. Yet success sets a powerful precedent: if a 20-year-old, mission-critical, massively concurrent system can modernize its Python stack, so can other long-lived infrastructure projects across finance, telecom, and scientific computing.
