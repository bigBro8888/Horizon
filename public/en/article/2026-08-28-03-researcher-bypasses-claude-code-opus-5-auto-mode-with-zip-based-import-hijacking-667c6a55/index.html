Researcher bypasses Claude Code Opus 5 Auto Mode with zip-based import hijacking

News time: 2026-08-28T12:44:25.125845+00:00 · Source: rss

A critical security flaw has been uncovered in Anthropic’s newly launched Claude Code Opus 5, specifically targeting its flagship safety feature: Auto Mode. Johann Rehberger, a widely respected prompt injection researcher, demonstrated an attack that succeeds roughly 80% of the time — not by tricking the model into writing malicious code directly, but by exploiting how Python resolves imports when local files shadow standard library modules.

The attack begins with a seemingly benign instruction: download and extract a ZIP archive containing a maliciously named struct.py. When Claude Code later executes code that imports base64, Python’s import system — which searches the current directory before built-in modules — loads the attacker-controlled struct.py instead of the real one. That local file then executes arbitrary code, including spawning malware processes. Crucially, Auto Mode fails at two points: first, it allows the ZIP extraction and import hijacking to proceed; second, when Claude detects the compromise and attempts to issue a cleanup command (e.g., killing the malicious process), Auto Mode blocks that very command, treating it as potentially unsafe.

This creates a paradoxical failure mode: the safety classifier permits the initial exploit, then obstructs the agent’s self-defense. As Simon Willison notes in his coverage, this undermines the core promise of Auto Mode — that it can safely automate tool use without human oversight. Anthropic had claimed near-perfect protection, citing a 0% success rate for browser-based prompt injection attacks when Auto Mode is enabled. Rehberger’s finding shows that such claims do not extend to code execution contexts involving local filesystem operations and Python’s import semantics.

The implications go beyond one model version. It highlights a deeper tension in AI agent safety: classifiers trained to detect ‘obviously dangerous’ actions often miss subtle, multi-step exploits rooted in well-known software behaviors — like Python’s local-module shadowing, documented since 2006. Rehberger and Willison both stress that no classifier-based guardrail is sufficient on its own. Their shared recommendation is architectural: run unattended coding agents inside strict sandboxes — containers or VMs with no access to home directories, SSH keys, cloud credentials, or outbound network connectivity — and monitor them actively. Safety, they argue, belongs in infrastructure — not just in prompts or classifiers.
