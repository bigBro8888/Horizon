py-evoFE v0.3.0 launches automated evolutionary feature engineering for tabular data

News time: 2026-08-28T12:44:25.690643+00:00 · Source: reddit

A new open-source Python library called py-evoFE has arrived to tackle one of the most persistent bottlenecks in tabular machine learning: manual feature engineering. Released as version 0.3.0 under the MIT license, py-evoFE uses genetic programming — a biologically inspired search method — to automatically discover high-impact feature transformations, such as nested aggregations, nonlinear ratios, target encodings, and manifold projections. Unlike brute-force feature generators that flood pipelines with thousands of redundant or collinear features, py-evoFE evolves compact, interpretable recipes through iterative selection, crossover, and mutation — guided by model performance and built-in complexity penalties.

The library is built for speed and scalability. It leverages Polars and PyArrow for vectorized, memory-efficient computation and introduces several novel optimizations: matrix hashing and nearest-neighbor caching eliminate repeated expensive operations (e.g., UMAP embeddings or k-NN lookups) across cross-validation folds; multi-fidelity screening first evaluates candidates with fast, low-accuracy proxies before committing resources to full evaluations; and an island-model parallel search distributes evolution across multiple populations with structured migration (Ring, Torus, Grid, etc.). After evolution, it applies Caruana-style ensembling over out-of-fold predictions from top-performing islands — boosting robustness without adding inference latency.

Integration is seamless for practitioners already using scikit-learn. py-evoFE implements standard methods like fit, transform, predict, and predict_proba, and plugs directly into sklearn.pipeline.Pipeline and GridSearchCV. A standout usability feature is the interactive HTML replay viewer: calling view(evo.get_recipe()) generates a self-contained dashboard showing how the best feature recipe evolved over generations — no external dependencies required. The example on the breast cancer dataset demonstrates end-to-end usage in under 20 lines, from Polars DataFrame input to LightGBM-backed prediction.

What sets py-evoFE apart isn’t just automation — it’s principled automation. By combining hierarchical chaining (where evolved features serve as inputs to deeper transformations), 40+ domain-aware transformers (including MinHash string similarity, FAMD for mixed data, and Genie clustering), and tight coupling with modern tabular tooling, it bridges the gap between expressive feature synthesis and production-grade efficiency. For Kaggle competitors, MLOps engineers, and researchers tired of hand-crafting ratio features or debugging leakage-prone group-by logic, py-evoFE offers a rigorous, composable, and open alternative.
