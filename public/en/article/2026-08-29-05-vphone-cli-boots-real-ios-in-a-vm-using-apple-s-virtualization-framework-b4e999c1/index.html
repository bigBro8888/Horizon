vphone-cli boots real iOS in a VM using Apple's Virtualization.framework

News time: 2026-08-29T07:50:43.465524+00:00 · Source: hackernews

A new open-source command-line tool called vphone-cli lets developers boot a functional iOS environment directly on macOS—without relying on Xcode’s iOS Simulator. Unlike the simulator, which runs iOS apps compiled for macOS (via translation layers like UIKit for Mac), vphone-cli leverages Apple’s native Virtualization.framework to launch an actual iOS kernel and user-space stack inside a virtual machine. This means it boots real iOS firmware images—similar to how Corellium or commercial iOS virtualization platforms operate—but now built entirely on Apple’s officially supported, sandboxed virtualization APIs.

The tool targets Apple Silicon Macs and requires macOS Monterey or later. It uses pre-signed iOS restore images (typically downloaded from Apple’s servers during device setup) and configures them with minimal hardware emulation: CPU, memory, storage, network, and display via VIRTIO devices. Because it runs real iOS binaries—not macOS-hosted simulators—it supports features the Xcode simulator cannot, such as full WebKit rendering, native Safari behavior, system-level permissions prompts, and even some low-level hardware interactions.

However, this authenticity comes with constraints. As noted in community comments, users must avoid selecting regions like Japan or the EU during initial iOS setup—those locales trigger regulatory checks (e.g., IMEI validation, carrier lock enforcement, or regional firmware signing requirements) that the VM cannot satisfy. The tool also does not emulate a baseband processor, meaning cellular functionality—including phone calls, SMS, and carrier-specific settings—is absent. Still, for localhost web testing, browser compatibility validation, or inspecting iOS-specific UI rendering, vphone-cli offers a uniquely lightweight and Apple-sanctioned alternative.

Importantly, vphone-cli is not affiliated with Apple and operates within documented limits of the Virtualization.framework—meaning no kernel patches, no code signing bypasses, and no jailbreaks. Its existence highlights how Apple’s own framework, originally designed for macOS and Linux VMs, can be extended toward iOS virtualization when combined with publicly available firmware and research-grade VM infrastructure (e.g., PCC’s iOS VM work). For developers tired of simulator quirks—or those needing true iOS runtime behavior—vphone-cli marks a meaningful step toward accessible, on-device-like testing on Mac.
