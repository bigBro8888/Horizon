LLM API performance varies up to 8.4 points between days

News time: 2026-08-30T06:36:53.244510+00:00 · Source: reddit

A groundbreaking empirical study has revealed that production LLM APIs exhibit substantial temporal instability—far beyond what most developers assume. By continuously running 31,352 hourly benchmark tests across 49 model identifiers from six major providers, the researcher quantified how much model performance actually shifts over time. Unlike traditional one-off evaluations—such as those seen on Hugging Face or LMSYS leaderboards—this work treats LLMs like live services: measuring them repeatedly, under identical conditions, with executable coding tasks, tool-calling workflows in isolated Docker containers, and deep reasoning challenges.

The results are striking: within a single day, scores fluctuated by just 2.8 points on average—a range attributable largely to inherent stochasticity in LLM generation. But between days, variation ballooned to 8.4 points, roughly three times larger. This suggests that short-term dips or spikes are often noise, while sustained daily shifts reflect real, operationally meaningful drift—whether due to backend updates, load balancing, routing changes, or silent model swaps. To separate signal from noise, the pipeline aggregates five repeated runs per task, computes daily medians, and applies statistical change-point detection with minimum-effect thresholds.

This analysis forms the core of AIStupidLevel, an open-source, MIT-licensed continuous monitoring system now tracking 22 active models across 7 providers. Its dashboard classifies models in real time as stable, volatile, degraded, or recovering—across dimensions including coding accuracy, tool-use reliability, latency, and cost. For example, it recently flagged a 32% sustained decline in Gemini 3.1 Flash Lite as a critical incident. Beyond alerting, the same dataset powers an OpenAI-compatible router that dynamically selects the best-performing model for each task—not just based on speed or price, but on current, verified capability.

The implications extend well beyond benchmarking culture. Most production AI observability tools track uptime, error rates, latency, and token costs—but rarely whether the model still works correctly. AIStupidLevel closes that gap, treating model intelligence as a measurable, time-series metric. As LLMs power increasingly critical applications—from medical triage to financial automation—knowing when capability degrades matters more than ever. This work doesn’t just measure stupidity; it makes AI reliability observable, actionable, and open.
