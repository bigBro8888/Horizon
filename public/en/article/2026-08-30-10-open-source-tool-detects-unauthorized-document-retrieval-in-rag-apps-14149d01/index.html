Open-source tool detects unauthorized document retrieval in RAG apps

News time: 2026-08-30T06:36:53.244345+00:00 · Source: reddit

A new open-source tool called rag-access-check aims to solve a subtle but serious security gap in Retrieval-Augmented Generation (RAG) systems: access control violations during the retrieval step. Unlike traditional web applications where authorization is enforced at the API or database layer, many RAG deployments silently retrieve documents without verifying whether the current user has permission to view them — especially when vector databases or search indexes lack native access controls. This tool bridges that gap by acting as an external auditor: it tests whether a RAG application retrieves documents that fall outside a user’s authorized scope.

The tool supports two main testing modes. First, offline test cases let developers define mock users, permissions, and expected retrieval behavior — for example, 'User A (role: analyst) should never retrieve documents tagged "HR-confidential".' Second, it can perform live HTTP API testing against real RAG endpoints, injecting authenticated requests using bearer tokens or API keys and analyzing responses for policy violations. It doesn’t require modifying the RAG application itself — instead, it observes inputs and outputs, making it compatible with most existing architectures.

What makes rag-access-check distinct from other RAG auditing tools is its narrow, security-specific focus. While projects like rag-retrieval-auditor measure retrieval quality (e.g., recall@k or MRR), this tool measures retrieval compliance. It asks not 'Did the system find relevant documents?' but 'Did it find only documents the user was allowed to see?' That distinction matters deeply in regulated industries — healthcare, finance, government — where leaking even one unauthorized record could trigger audits, fines, or reputational damage.

The developer, who goes by /u/Lostboy_journey on Reddit, explicitly invites early adopters to test the tool in non-sensitive environments and share feedback. The GitHub repository includes basic documentation, sample test configurations, and a CLI interface — but no production-grade integrations yet (e.g., CI/CD hooks or enterprise SSO support). As noted in industry guides like Vertex Frontier’s RAG Security Framework, enforcing access control before retrieval (pre-filtering) remains ideal — yet many teams rely on post-hoc filtering or none at all. Tools like this help expose those gaps before they become incidents.
