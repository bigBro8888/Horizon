Developer builds walkable ASCII cyberpunk city in a single HTML file

News time: 2026-09-01T06:13:45.551982+00:00 · Source: hackernews

A solo developer has created an astonishingly rich, interactive cyberpunk city rendered entirely in ASCII art — and it runs in a web browser using just one HTML file. No external libraries, no build step, no server: everything — from procedural skyscraper generation and animated traffic to multi-level interiors and elevation-aware walking — is packed into a single, self-contained document. The project, showcased across multiple YouTube updates, invites users to navigate its rain-slicked streets with keyboard controls, peek into neon-lit lobbies, and watch stylized vehicles glide past towering monoliths — all built from characters like #, @, +, and █.

This isn’t static ASCII art; it’s a dynamic world simulation. The city uses JavaScript to generate neighborhoods on the fly, assign building heights and façades procedurally, and animate moving elements with frame-accurate timing. Elevation is conveyed through layered character density and perspective tricks — stairs, ramps, and rooftop access are all navigable. Interiors aren’t just decorative: entering a building triggers a seamless transition to a new ASCII layout representing hallways, elevators, or offices — all calculated and rendered in real time.

What makes the project especially notable is its technical discipline. It avoids canvas or WebGL, relying instead on carefully styled <pre> and <span> elements with monospace fonts, fixed dimensions, and CSS transforms for smooth scrolling and parallax effects. Performance is tuned for responsiveness even on modest hardware — a rare feat for ASCII-based rendering at this scale. The developer has iterated publicly: early versions focused on street-level traversal, while later updates added verticality, interior spaces, and synchronized traffic systems that respect lane logic and intersection timing.

The community response reflects deep appreciation for both creativity and craft. Commenters praise the browser-first approach over terminal-based alternatives, citing precise font control, mouse support, and debugging tools as decisive advantages. Others note discrepancies between video demos and local execution — likely due to font rendering differences or missing CSS resets — highlighting how tightly coupled the experience is to specific browser environments. A paywall concern also surfaced: while Prototype 1 is available via Ko-fi, the more advanced v2 shown in recent videos remains unreleased, underscoring the tension between open experimentation and sustainable development.
