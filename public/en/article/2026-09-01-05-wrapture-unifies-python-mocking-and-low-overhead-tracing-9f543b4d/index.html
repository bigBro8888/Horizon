Wrapture unifies Python mocking and low-overhead tracing

News time: 2026-09-01T06:13:45.276152+00:00 · Source: rss

Graham Dumpleton — the seasoned Python infrastructure engineer behind wrapt, mod_wsgi, and New Relic’s Python agent — has released Wrapture, a new library that bridges two critical but traditionally separate developer concerns: testing mocks and production observability. Unlike ad-hoc monkeypatching or heavyweight tracing agents, Wrapture builds directly on wrapt’s battle-tested, introspection-preserving function wrapping foundation to offer a single, coherent API for both controlled test-time overrides and non-intrusive runtime observation.

The core idea is elegant in its restraint: wrap any function or method once, then decide at runtime whether it should be mocked (e.g., returning stubbed values in tests), traced (e.g., logging call timing and arguments), or both. This eliminates the need to maintain parallel mocking logic (like unittest.mock.patch) and tracing instrumentation (e.g., OpenTelemetry manual decorators), reducing duplication and cognitive load. As Dumpleton puts it, Wrapture targets the long-standing challenge of "attaching observation to code you do not control, recording what flows through it, and doing so without disturbing the program being watched."

Practically, Wrapture supports declarative configuration — a TOML file can enable tracing across entire modules or specific methods without touching source code. It ships with built-in OpenTelemetry exporters and multiple output sinks (e.g., JSON Lines files). On the testing side, its context-manager-based binding API lets developers stub methods with fine-grained control: for example, replacing Gateway.charge() with a fixed dictionary return value only during a single test block. The syntax is clean, explicit, and avoids global state leaks common in traditional mocking.

Notably, Wrapture is also an experiment in AI-augmented development: every line of code and documentation was written by an AI assistant under Dumpleton’s rigorous direction — not as ‘vibe coding’, but as a precision tool guided by deep domain expertise. Though still weeks old, the project already includes full documentation, working examples, and integration patterns for both unit testing and observability workflows. For Python teams juggling flaky mocks, brittle patching, and fragmented tracing setups, Wrapture offers a refreshingly unified starting point.
