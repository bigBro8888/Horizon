Paint.NET ships clean-room Direct2D rewrite for Linux via WINE

News time: 2026-09-03T05:45:02.104147+00:00 · Source: rss

Paint.NET — the long-standing, Windows-native image editor beloved by hobbyists and professionals alike — has taken a radical step toward cross-platform viability: it now runs on Linux through WINE, powered by an internal, clean-room reverse-engineered implementation of Microsoft’s Direct2D graphics API. This isn’t a wrapper or partial shim; it’s a full, from-scratch managed .NET library named PaintDotNet.Windows.Direct2D1.Managed.dll, activated only when launched with the /wine flag. The move solves what its creator Rick Brewster called "the biggest hurdle" for Linux compatibility — Direct2D’s deep integration into Paint.NET’s rendering pipeline, which couldn’t be simply disabled or stubbed out without breaking core functionality.

The technical ambition is staggering. Direct2D is a complex, low-level Windows graphics API tightly coupled with COM, GPU acceleration, and intricate effect pipelines — including blur, shadow, and color matrix operations. To replicate it legally and safely, Brewster’s team employed clean-room reverse engineering: one group studied Direct2D’s public behavior (API contracts, error codes, pixel outputs) while another, isolated group wrote new code based solely on those observations — no disassembly or copying of Microsoft’s binaries. The result spans roughly 180,000 lines of C# code, nearly a quarter of Paint.NET’s entire 700,000-line codebase.

Notably, Brewster credits the AI assistant Claude as the primary author — though with heavy human oversight. He describes much of the code as "vibe coded": written rapidly with high confidence but minimal formal review. Brewster admits he couldn’t audit all 180,000 lines himself, instead focusing on critical areas like COM reference counting and memory safety. Early missteps — such as forgetting AddRef() calls — were caught and corrected manually. Yet he also praises Claude’s tenacity in reverse-engineering mathematical formulas behind built-in Direct2D effects, work that would have taken months for humans alone.

This isn’t production-ready Linux support — Brewster labels it "extremely experimental" — but it’s a watershed moment. It demonstrates that large-scale, interoperable graphics APIs can be reimplemented ethically and effectively using modern tooling and AI-augmented engineering. For developers wrestling with Windows legacy apps on Linux, or open-source projects needing GPU-accelerated 2D rendering, Paint.NET’s approach offers both inspiration and a concrete, working blueprint.
