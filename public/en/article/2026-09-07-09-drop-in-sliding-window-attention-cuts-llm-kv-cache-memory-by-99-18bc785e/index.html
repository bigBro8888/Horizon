Drop-in sliding window attention cuts LLM KV-cache memory by 99%

News time: 2026-09-07T06:04:01.720790+00:00 · Source: reddit

A new open-source implementation enables sliding window attention (SWA) for existing Hugging Face causal LLMs—without retraining or model modification. Developed by researcher /u/ahsaor8, the tool wraps pretrained models with a lightweight inference layer that replaces full-history key-value (KV) caching with a bounded, circular-buffer cache. This cache combines two ideas: attention sinks (tokens that consistently attract disproportionate attention, often early in context) and a recent sliding window (e.g., last 64 tokens). The result is dramatically smaller memory footprints and faster token generation—while preserving the original model architecture and weights.

In benchmarks using Qwen2.5-7B, the SWA-64 variant reduced KV-cache memory from ~1.84 GB to just ~3.5 MB at 32K context length—a 99.8% reduction. Even at 16K context, memory dropped from ~923 MB to ~3.5 MB, and token-per-output-time (TPOT) improved from ~38.4 ms to ~30.5 ms. Crucially, this gain comes without changing the model’s weights or training pipeline—making it compatible with any HF-compatible decoder-only LLM out of the box.

The implementation includes streaming prefill, chunked attention masking, autoregressive decoding support, and built-in metrics for TTFT (time-to-first-token), TPOT, throughput, and real-time KV-cache memory usage. It also supports attention sinks—leveraging known empirical behavior in LLMs where early tokens (e.g., BOS or system prompts) act as stable attention anchors—even when they carry little semantic content. By retaining these sinks alongside the most recent tokens, SWA preserves some long-range coherence while discarding older, less attended positions.

However, the trade-off is real: tasks requiring precise recall or reasoning across distances longer than the window size (e.g., referencing a detail from token #1000 in a 32K-sequence) may degrade. The author explicitly invites scrutiny on failure modes—asking which architectures, benchmarks, or edge cases deserve priority. This openness reflects a broader need in the LLM inference community: practical, composable optimizations that don’t force model retraining or vendor lock-in.
