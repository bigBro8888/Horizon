Abusive web crawlers consume more CPU than legitimate users on git.kernel.org

News time: 2026-09-08T05:55:48.592596+00:00 · Source: rss

A stark infrastructure alert has emerged from the Linux kernel’s official Git hosting service: abusive web crawlers are now consuming more server CPU resources than all legitimate user activity combined—including Git clones. Konstantin Ryabitsev, a key infrastructure maintainer at kernel.org, revealed that across five geographically distributed nodes, 14 CPU cores run continuously—solely to render HTML versions of Git commit pages for scrapers. This isn’t occasional traffic; it’s sustained, unrelenting load that dwarfs demand from developers fetching code or browsing repositories through standard tools.

The problem highlights a growing asymmetry in modern web infrastructure: services designed for human readability and API-like exploration (like git.kernel.org’s commit viewer or Datasette’s data browsers) unintentionally invite aggressive, poorly behaved crawlers. Unlike Git protocol access—which is efficient and authenticated—HTML rendering is computationally expensive, requiring full page generation, syntax highlighting, diff parsing, and template execution for every request. And because these pages are publicly accessible and lack strict rate limits or bot challenges, they become low-hanging fruit for bulk scrapers, AI training harvesters, and SEO farms.

Simon Willison, creator of Datasette—a lightweight, open-source tool for publishing structured data as interactive websites and APIs—expressed deep concern about the implications. Datasette serves thousands of crawlable HTML and JSON endpoints by design, making it similarly vulnerable. If even the highly optimized, high-traffic infrastructure behind the Linux kernel struggles with this load, smaller projects running on modest hardware face real sustainability risks: higher hosting costs, slower response times, and potential service degradation during crawler surges.

This isn’t just about performance—it’s about operational fairness and ethical infrastructure stewardship. There’s no universal standard for crawler behavior beyond voluntary adherence to robots.txt, and many scrapers ignore it entirely. Mitigations like rate limiting, IP reputation scoring, or selective JavaScript rendering remain under-deployed, especially in open-source hosting environments where simplicity and transparency are prioritized over defensive complexity. As AI data harvesting accelerates, the burden falls increasingly on maintainers—not the crawlers’ operators—to absorb the cost of scale.
