Simon Willison builds client-side video compressor with WebAssembly FFmpeg

News time: 2026-09-08T05:55:48.592656+00:00 · Source: rss

Simon Willison, a well-known web developer and co-creator of Django, has released a lightweight, fully client-side video compression tool that runs entirely in the browser. The tool—available at tools.simonwillison.net/video-compressor—lets users upload a video file and instantly generate multiple optimized versions using FFmpeg compiled to WebAssembly. Unlike traditional server-based compressors, this tool processes videos locally: no files leave the user’s device, preserving privacy and eliminating upload delays or backend infrastructure costs.

Willison built the tool after recording a short animation demo on his phone and needing a quick way to shrink it for blog publishing. Rather than writing the code from scratch, he used Claude Code (specifically Claude Mythos Fable 5.1) to generate the implementation. The AI assisted with integrating ffmpeg.wasm—the popular Emscripten-compiled port of FFmpeg—and structuring the UI around practical encoding options like CRF (Constant Rate Factor), H.264 profiles, audio bitrate control, and metadata stripping.

The interface offers five preset configurations labeled Largest through Smallest, each with distinct trade-offs: resolution (e.g., 854×370 vs. 640×276), CRF values (22–28), audio bitrates (128–64 kbps), encoder speed, and optional features like dropping audio or limiting output to the first 10 seconds. After clicking “Generate versions,” the tool reports completion in under 12 seconds—even on modest hardware—and displays results sorted by size, with download links and expandable FFmpeg command lines for transparency and reproducibility.

This isn’t just a demo—it reflects a maturing ecosystem where WebAssembly enables powerful desktop-grade tools directly in browsers. By combining ffmpeg.wasm with AI-assisted development, Willison demonstrates how developers can rapidly prototype and ship robust, privacy-respecting utilities without backend dependencies. While not revolutionary in scope, the tool exemplifies pragmatic innovation: solving a real workflow problem with accessible, open, and well-documented technology.
