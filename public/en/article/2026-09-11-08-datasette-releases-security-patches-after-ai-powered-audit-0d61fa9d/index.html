Datasette releases security patches after AI-powered audit

News time: 2026-09-11T05:55:50.998394+00:00 · Source: rss

Datasette, the open-source tool for exploring and publishing SQLite databases as interactive websites and APIs, has issued two critical security patch versions: 1.0a39 (for its alpha branch) and 0.65.4 (for the stable 0.65.x series). These updates address subtle but high-impact vulnerabilities that could affect publicly exposed Datasette instances—especially those serving both public and private database tables on the same deployment.

The bugs were uncovered not through conventional penetration testing, but via an intensive, collaborative security audit leveraging three cutting-edge large language models: Claude Fable 5.1, GPT-5.6 Sol, and GPT-6 Astra. Security researchers Sevban Dönmez, Alex Garcia, and Datasette’s creator Simon Willison jointly conducted the audit in a private shared repository. Their workflow was deliberately structured: one person wrote automated tests to reproduce each vulnerability, while the other implemented the fix—ensuring dual human review alongside AI-generated insights.

What makes this release notable is not just the fixes themselves, but the methodology. Anthropic’s Claude Fable 5.1—a ‘Mythos-class’ model with ~5 trillion parameters—was explicitly designed for security research and released publicly in September 2026 with built-in safeguards. Similarly, OpenAI’s GPT-6 Astra outperforms GPT-5.6 Sol on computer-use benchmarks like OSWorld 2.0 (72.6% vs. 65.7%) and delivers stronger long-context reasoning at lower API cost. Their combined use signals a shift toward agentic engineering: LLMs acting as persistent, task-oriented collaborators rather than one-off assistants.

The team emphasized that these findings were unusually subtle—requiring deep inspection of Datasette’s permission logic, query parsing, and table-scoping behavior. As a result, Datasette will now integrate frontier-model security audits into all future development cycles. This isn’t just about patching bugs—it’s about redefining how open-source projects proactively harden themselves against increasingly sophisticated threats.
