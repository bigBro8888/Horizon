wrapture launches as dual-purpose Python monkey patching library

News time: 2026-09-12T05:44:44.087365+00:00 · Source: rss

Graham Dumpleton — the seasoned Python developer behind the widely used wrapt library — has unveiled wrapture, a new open-source tool designed to unify two traditionally separate use cases: unit testing and production observability. Unlike conventional mocking libraries such as unittest.mock, which are scoped to test environments, or tracing tools like OpenTelemetry auto-instrumentation, which focus on runtime telemetry, wrapture bridges both worlds using a single, consistent monkey patching mechanism. Its core idea is simple but powerful: attach lightweight, composable behaviors to arbitrary call sites — functions, methods, attributes, even generators — without altering the original source code.

Since its August 31, 2026 release, Dumpleton has published ten detailed, hands-on tutorials — one nearly every day — covering everything from basic unit testing and phased mock behavior to live application tracing and zero-code configuration via TOML files. Notably, wrapture supports rich call recording (with tree-based visualization), timing analysis for performance bottlenecks, and seamless export of traces to OpenTelemetry backends. A companion package, wrapture-instrumentation, provides prebuilt integrations for over 20 popular Python frameworks and libraries, including Flask, FastAPI, Django, SQLAlchemy, HTTPX, and gRPC.

What sets wrapture apart is its architectural clarity: it builds directly on wrapt (Dumpleton’s own high-performance, low-overhead monkey patching foundation), ensuring reliability and minimal runtime impact. Crucially, it decouples instrumentation logic from application code — you can enable full tracing by dropping a config file into your environment, no code changes required. This makes it uniquely suited for debugging legacy systems, validating third-party integrations, or adding observability to applications where modifying source isn’t feasible.

Though still in alpha, wrapture is already production-ready for many scenarios. Its interactive JupyterLab workshops lower the learning curve, and its design avoids common pitfalls of ad-hoc monkey patching — such as global state leakage or fragile patch ordering — by enforcing explicit scope and lifecycle management. As Simon Willison observed, it feels less like a niche utility and more like a long-term foundational toolkit: a ‘Swiss Army Knife’ for Python developers who need precise, non-invasive control over how their code behaves — whether under test or under load.
