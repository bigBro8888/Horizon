825k-parameter transformer generates verified drawing bytecode for RP2040

News time: 2026-09-14T06:13:36.997825+00:00 · Source: reddit

A researcher has built a remarkably compact autoregressive transformer—just 825,000 parameters—to generate executable drawing programs in the form of compact bytecode, not pixels. The model runs on a standard host computer and outputs roughly 100-byte programs that encode geometric instructions like lines, curves, and fills. These programs are then sent to a Raspberry Pi Pico (powered by the RP2040 microcontroller), where a tiny fixed-point virtual machine executes them precisely—no floating-point unit, no tensor library, no dynamic memory allocation required.

The execution fidelity is rigorously validated: every single one of the 12,670 generated programs matched the reference Python interpreter’s output byte-for-byte. The RP2040 interpreter fits in just 1,862 bytes of flash, uses zero static RAM, and peaks at only 492 bytes of stack space. At 12 MHz, it renders QuickDraw-style sketches in about 0.61 milliseconds—fast enough for real-time feedback over UART. This isn’t AI running on the microcontroller; it’s AI generating code for it—a clean separation of generation and execution.

The project explores multiple low-level representations—bit-level, byte-level, typed tokens, delta coordinates—and finds representation choice matters significantly depending on data source. On synthetic data, bit-level encoding performed nearly as well as byte-level; but on real QuickDraw sketches, it incurred an 11.6-bit penalty per drawing. The author also tested hierarchical stroke planning and relational context modeling: while explicit planning improved termination behavior and output length control, it didn’t boost log-likelihood. Teacher-forced models learned strong relational preferences—but struggled to reproduce exact continuations during free sampling.

Ongoing work focuses on augmenting the model with explicit copy-or-emit actions and affine relation tracking, aiming to improve generalization to unseen shape combinations. The open-source repository includes full demo instructions, captured RP2040 traces, visual comparisons, and experiment logs. The creator explicitly invites community input on three open challenges: better distinguishing novelty from memorization, moving beyond teacher-forced likelihood to evaluate exact program correctness, and designing experiments that deepen the hardware-aware significance of the RP2040 results.
