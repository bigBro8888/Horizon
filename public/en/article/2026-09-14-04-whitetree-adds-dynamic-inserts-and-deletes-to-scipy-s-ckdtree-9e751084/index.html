whitetree adds dynamic inserts and deletes to scipy's cKDTree

News time: 2026-09-14T06:13:36.997973+00:00 · Source: reddit

A developer has created whitetree, a lightweight, pure numpy/scipy library that enables efficient dynamic nearest-neighbor search using Mahalanobis distance — something scipy’s cKDTree was never designed to do. Unlike the standard cKDTree, which is strictly static (requiring full rebuilds for any data change), whitetree maintains multiple cKDTree instances in parallel, each holding a subset of points. It achieves exact Mahalanobis search by first whitening input data — applying a linear transformation using the Cholesky factor of the estimated covariance matrix — so Mahalanobis distance reduces to standard Euclidean distance in the transformed space.

The core insight lies in how updates are handled: instead of rebuilding one large tree, whitetree uses a geometric decomposition strategy — inspired by but distinct from the classic Bentley–Saxe method — where new points are inserted into small trees, and trees are merged or rebuilt only when size ratios exceed a threshold (e.g., 32×). This keeps the number of active trees low (just 3–4 at one million points) and ensures query time scales with the number of trees visited (typically 20–30% of static throughput), not their individual sizes. Deletions use tombstones rather than physical removal, preserving tree integrity while allowing exact results.

Benchmarks show dramatic speedups: whitetree is 40–300× faster than sklearn’s BallTree with Mahalanobis metric and 7–60× faster than FAISS Flat on 500k points — all while delivering exact results (distance error = 0.0) matching a static cKDTree. Crucially, it’s the only exact method tested that sustains high throughput under interleaved workloads — ~1,100 insert/delete/query cycles per second on a 200k-point sliding window — outperforming FAISS IDMap2 (~20/s), naive numpy brute force (~35/s), and rebuilding cKDTree per query (~8/s). The library is thread-safe for single-writer/multi-reader use and relies only on float64 covariance estimation with Ledoit-Wolf shrinkage and scale-relative ridge regularization.

Still, whitetree isn’t universally faster: when updates arrive in large batches (e.g., 20k points), rebuilding a single cKDTree once per batch (2.2 s total) beats whitetree’s incremental overhead (14.9 s). Its advantage emerges precisely where streaming matters most — fine-grained, real-time interleaving of updates and queries. The author openly invites comparison against other exact dynamic indexes, noting gaps in the current benchmark landscape. Full code, tests, benchmarks, and design rationale are publicly available on GitHub.
