commit-rewriter 0.1 launches as web-based Git commit editor

News time: 2026-09-14T06:13:36.465011+00:00 · Source: rss

Simon Willison has released commit-rewriter 0.1 — a lightweight, Python-powered tool that lets developers interactively edit Git commit messages through a local web interface before pushing changes publicly. Designed to solve a very real but often overlooked problem, it targets cases where internal development history contains sensitive references, AI-generated boilerplate, or private issue IDs that shouldn’t appear in open-source repositories. Willison built it specifically for the Datasette September 2026 security releases, where initial commits included agent-assisted cruft and internal tracking numbers unfit for public disclosure.

The tool runs entirely locally: no data leaves your machine. You launch it with a single command — uvx commit-rewriter path/to/repo — and it spins up a minimal web server (using Starlette and HTMX) on http://localhost:8000. The UI displays recent commits in a collapsible sidebar, with each commit rendered as an editable card showing author, timestamp, short hash, and full message. A search bar filters by message text, author name, or hash; an 'Edited only' toggle helps focus on modified entries. Crucially, edits are non-destructive until you click 'Rewrite commit messages'.

When you apply changes, commit-rewriter first creates a timestamped backup branch — say, rewriter-backup-20260914-1523 — preserving the original state. Then it performs an interactive rebase under the hood, rewriting only the commits you’ve edited, from the oldest modified one to HEAD. This avoids unnecessary churn while ensuring clean, intentional history. The process respects Git’s integrity: signatures remain intact if commits were signed, and no force-push is required unless you’re updating a remote branch later.

What makes commit-rewriter stand out isn’t technical novelty — Git already supports git rebase -i — but usability and safety. It removes the cognitive load of remembering rebase syntax, avoids editing raw TODO lists in vim, and eliminates accidental history corruption. For maintainers preparing private-to-public transitions — especially in security-sensitive contexts — it adds guardrails without sacrificing control. As AI-assisted coding proliferates, tools like this quietly fill a growing gap: cleaning up the output of automation before it becomes part of the permanent record.
