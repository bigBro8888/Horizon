shot-scraper 1.12 adds WebP screenshot support with quality control

News time: 2026-09-14T06:13:36.465055+00:00 · Source: rss

Simon Willison has released shot-scraper 1.12, a notable update to his widely used command-line tool for automating web page screenshots. The headline feature is native WebP image format support — a modern, efficient alternative to JPEG and PNG that delivers smaller file sizes without sacrificing visual fidelity. Developers can now generate WebP screenshots directly from the terminal using a simple command like shot-scraper https://simonwillison.net -o screenshot.webp --quality 80, where the --quality flag lets users tune compression between lossless (default) and lossy modes.

This isn’t just a format swap: WebP’s design — developed by Google and supported in all major browsers since 2013 — enables both lossy and lossless compression, alpha transparency, and animation, making it especially well-suited for documentation, CI/CD pipelines, and static site generation. For teams generating hundreds or thousands of screenshots regularly — such as for changelogs, UI regression testing, or automated documentation — even modest per-file size reductions compound into meaningful bandwidth, storage, and load-time savings.

The implementation builds on Playwright, the robust browser automation library that powers shot-scraper’s rendering engine. Unlike earlier versions that only exported PNG or JPEG, 1.12 leverages Playwright’s underlying Chromium support for WebP encoding, adding minimal overhead while expanding output flexibility. Willison notes in his release post that he shipped this feature specifically to support his new commit-rewriter tool, which relies on lightweight, high-fidelity screenshots for visual diffs — a real-world use case that underscores the practical value of the change.

What makes this update especially useful is its simplicity and backward compatibility. No configuration files or complex setup are required — just add --quality and an output filename ending in .webp. And because WebP is now universally supported across browsers and tools (including GitHub, most CMSs, and static site generators), adoption requires no downstream changes. For developers already using shot-scraper in documentation workflows or testing scripts, upgrading to 1.12 means immediate gains in efficiency — with zero trade-offs in reliability or integration effort.
