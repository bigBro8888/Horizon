Strix AI finds leaked GitHub token granting admin access to Baseten’s production repos

News time: 2026-09-16T05:58:30.208511+00:00 · Source: hackernews

Security research firm Strix AI recently uncovered a critical misconfiguration in Baseten’s infrastructure that granted full administrative access to its core GitHub repositories. The vulnerability stemmed from two interconnected issues: a publicly exposed Harbor container registry and a leaked GitHub personal access token (PAT) embedded in Docker build history — specifically tied to the basetenbot automation account. Using an AI-powered security agent, Strix discovered the token while scanning publicly available container images hosted on Baseten’s Harbor instance, which had been left open to unauthenticated access.

Once extracted, the PAT was found to possess unusually broad permissions: admin and push access to Baseten’s main product repository, its GitOps cluster management repo, and its Homebrew tap — plus read/write access to additional private repositories, including customer-specific ones. This level of access would have allowed an attacker to modify production code, inject malicious dependencies, or exfiltrate internal tooling and configurations. Crucially, Strix followed responsible disclosure practices, reporting the issue directly to Baseten’s security team without public exposure or exploitation.

Baseten responded swiftly and transparently. Within hours, they made the public Harbor project private and rotated the compromised token. According to official confirmation from Philip Kiely of Baseten, logs showed no evidence of misuse, and no customer data was accessed or exposed. Anton from Baseten’s security team acknowledged the severity on July 14 and coordinated securely with Strix to delete any pulled images. The entire remediation was completed before the vulnerability could be weaponized.

This incident highlights how seemingly minor oversights — like leaving a container registry public or embedding credentials in Docker layers — can cascade into high-severity risks when combined with modern automation. It also underscores the growing role of AI agents not as replacements for human analysts, but as force multipliers: capable of rapidly scanning vast surfaces (e.g., image registries, CI logs, package metadata) where humans rarely look. As one commenter noted, the real advantage isn’t that AI finds what’s impossible for humans — it’s that it finds what’s impractical at scale. For DevSecOps teams, this serves as a timely reminder to treat container build artifacts and registry permissions with the same rigor as source code repositories.
