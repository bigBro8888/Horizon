Bend launches as a dependently typed language for provably safe AI on CPU and GPU

News time: 2026-09-18T05:53:30.336389+00:00 · Source: hackernews

Bend is a new open-source programming language designed from the ground up to prevent AI-related errors—not through testing or heuristics, but via formal, machine-checked mathematical proofs. Its core innovation lies in combining dependent types with GPU-aware compilation and compile-time higher-order reasoning. Unlike traditional languages where types describe only data shapes (e.g., 'this is an integer'), Bend’s types can encode precise behavioral guarantees—such as 'this neural network layer never outputs NaN' or 'this gradient computation preserves numerical stability under all valid inputs'. These properties are checked at compile time using a quantifier-based type theory (QTT), extended with affinity annotations that guide memory layout and parallelism for GPU execution.

The language targets both CPU and GPU backends without requiring separate kernels or unsafe FFI calls. Its compiler emits optimized CUDA-like code while preserving proof obligations—meaning verification doesn’t stop at the CPU boundary. This bridges a longstanding gap: most verified systems (like seL4 or CompCert) run only on CPUs, while high-performance AI workloads demand GPU acceleration. Bend instead treats the GPU not as a black-box accelerator, but as a first-class, verifiable execution target.

Bend’s author, known online as LightMachine, spent nearly a year developing it full-time and released it freely under an MIT license. The project has already attracted over 16,000 GitHub stars in just four months—a pace exceeding many established systems languages. Though still pre-alpha, its design draws from cutting-edge research: it shares conceptual roots with Andras Kovacs’ two-level type theory (2LTT) and incorporates affinity-based scheduling inspired by recent GPU memory models—not interaction combinators or prior projects named 'Bend', as some early commenters mistakenly assumed.

Critically, Bend does not aim to replace Python or PyTorch for rapid prototyping. Instead, it targets safety-critical AI infrastructure: verified inference servers, certified training loops, or runtime monitors embedded in production ML pipelines. As formal verification gains traction in AI—spurred by growing concerns about hallucination, bias, and adversarial fragility—tools like Bend represent a shift from detecting failures after deployment to preventing them before compilation.
