uv 0.12.17 adds libc version constraints and lockfile integrity checks

News time: 2026-09-19T05:49:42.185309+00:00 · Source: github

The Rust-based Python package manager uv has released version 0.12.17, a stable patch update that strengthens reliability, security, and cross-platform compatibility. Released on September 18, 2026, this version avoids panics during frozen exports by rejecting malformed Git archive paths in lockfiles — a change that replaces silent crashes with actionable error messages. It also introduces two preview features aimed at improving reproducibility: one enforces strict matching between wheel filenames and declared package names/versions in pylock.toml, while the other lets users specify minimum glibc or musl versions required for universal dependency resolution.

Performance gains are another highlight. Builds involving many exclusion patterns now avoid quadratic-time deduplication, significantly speeding up large or complex projects. Resolver memory usage is reduced too, thanks to more efficient handling of duplicate package and distribution requests. A subtle but important bug fix ensures macOS environments won’t accidentally select wheels built for newer Darwin versions than the project’s configured baseline — preventing runtime incompatibilities.

The release also tightens workspace metadata handling: uv workspace metadata is now read-only by default unless explicitly invoked with --sync, and uv check lock modes are now applied consistently when retrieving that metadata. Documentation improvements clarify earlier releases (0.12.14 and 0.12.15), helping users understand incremental changes across the patch series.

As a fast, drop-in alternative to pip and pip-tools, uv continues to evolve toward enterprise-grade robustness. These updates reflect growing attention to deterministic builds, platform-specific constraints, and developer ergonomics — especially as Python teams adopt lockfiles more widely under PEP 751. With prebuilt binaries available for Apple Silicon, x86 and ARM64 Windows, multiple Linux architectures (including PPC64LE), and comprehensive checksums provided, adoption remains frictionless across diverse development and CI environments.
