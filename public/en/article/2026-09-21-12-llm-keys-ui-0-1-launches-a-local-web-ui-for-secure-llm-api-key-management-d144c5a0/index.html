llm-keys-ui 0.1 launches a local web UI for secure LLM API key management

News time: 2026-09-21T06:17:03.036585+00:00 · Source: rss

Simon Willison has released llm-keys-ui 0.1 — a lightweight, CLI-first tool that provides a local web interface for securely storing and retrieving LLM API keys. Designed specifically for remote coding agent workflows, it solves a subtle but growing pain point: how to inject sensitive credentials into headless or mobile-controlled environments without exposing them in chat logs, terminal history, or agent memory.

The tool emerged from Willison’s hands-on use of Codex Remote — OpenAI’s feature that lets users control coding agents on remote machines via the ChatGPT mobile app. When developing LLM-related projects across those machines, he needed a way to configure API keys without pasting them directly into the ChatGPT interface — a practice that risks leakage, accidental logging, or credential sprawl. Instead of manual copy-paste, llm-keys-ui spins up a minimal local HTTP server (default port 8010) accessible over the local network or via Tailscale — a zero-config mesh networking tool that assigns stable 100.x.y.z IPs to devices.

Once launched with uvx --with llm-keys-ui llm keys-ui --all, the tool prints one or more URLs (e.g., http://192.168.1.20:8010 or http://<tailscale-device>.beta.tailscale.net:8010) where users can open a clean web form to save keys by name — such as 'anthropic' or 'openrouter'. Crucially, the interface never displays stored key values, even to the user, reducing exposure surface. Later, remote agents or shell scripts retrieve keys programmatically using llm keys get <name>, which outputs the value to stdout — ready for use in environment variables or command substitution.

Under the hood, keys are stored in a local SQLite database with filesystem-level permissions (not encrypted at rest), prioritizing simplicity and transparency over enterprise-grade cryptography. The tool integrates cleanly with uvx — Astral’s ultra-fast Python package runner — enabling one-off execution without installing dependencies globally. While not intended for production secrets management, it fills a pragmatic gap for developers iterating quickly across distributed, agent-driven setups. As LLM-powered automation moves beyond laptops into heterogeneous remote environments, tools like this help keep credential hygiene within reach — without requiring infrastructure overhead.
