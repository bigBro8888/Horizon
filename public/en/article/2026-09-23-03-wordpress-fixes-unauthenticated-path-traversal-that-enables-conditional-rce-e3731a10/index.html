WordPress fixes unauthenticated path traversal that enables conditional RCE

News time: 2026-09-23T05:56:01.492113+00:00 · Source: hackernews

WordPress has released version 7.1.2 to patch a critical security vulnerability—tracked as CVE-2026-87902 and GHSA-7hp8-65ch-5whp—that allows unauthenticated attackers to traverse file paths and load arbitrary local PHP files outside the theme directory. The flaw resides in the get_page_template() function, which handles page-template resolution. When improperly sanitized, user-supplied input can manipulate the template lookup logic to point to files like /etc/passwd or /var/www/html/wp-config.php, provided those files are readable by the web server.

What makes this especially dangerous is its conditional path to remote code execution (RCE). While the vulnerability itself is a local file inclusion (LFI), it becomes exploitable for RCE only when certain preconditions are met—such as the presence of attacker-controlled data in included files (e.g., serialized objects in cache files) or when combined with other weaknesses like insecure deserialization or plugin-specific behaviors. This isn’t universal RCE out of the box—but in real-world deployments where caching plugins, custom themes, or legacy extensions are active, the risk escalates significantly.

The fix, committed in 9c4e85, introduces strict validation on template paths: it now enforces that resolved templates must reside within the expected theme or parent-theme directories and rejects any path containing .. or absolute path components. As a courtesy to users still running older versions, WordPress backported the patch to all supported branches dating back to 4.7—a notable effort given that roughly one-third of active WordPress installations remain on pre-7.x versions, according to community estimates.

This vulnerability arrives amid a broader wave of high-severity path traversal flaws—including GitLab’s CVE-2026-85706, patched just days earlier. Experts point to systemic issues: most programming language standard libraries lack safe-by-default abstractions for scoped filesystem access. As one developer noted, tools like libpathrs aim to replace global-path string manipulation with file-descriptor–based path resolution—a paradigm shift needed to prevent recurrence. For site owners, immediate upgrading remains the only reliable mitigation; static site generators like Hugo are gaining traction precisely because they eliminate such dynamic server-side risks altogether.
