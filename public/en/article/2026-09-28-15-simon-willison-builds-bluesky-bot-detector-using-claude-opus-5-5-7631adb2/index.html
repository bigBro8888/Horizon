Simon Willison builds Bluesky bot detector using Claude Opus 5.5

News time: 2026-09-28T06:48:34.514525+00:00 · Source: rss

Simon Willison, a well-known developer and technical blogger, has released a new open tool called the Bluesky reply bot checker — a lightweight but effective utility designed to flag accounts on Bluesky that behave like automated reply bots. The tool is live at tools.simonwillison.net/bluesky-bot-check and works by analyzing public profile data via Bluesky’s open API. Unlike Twitter — where API access has been severely restricted since 2023 — Bluesky still offers developers full, documented, and rate-limited but usable API endpoints, making behavioral analysis feasible without scraping or workarounds.

Willison built the tool in response to a growing nuisance: the rapid emergence of low-effort, AI-powered reply bots on Bluesky. These accounts don’t post original content; instead, they rapidly reply — often within seconds — to popular posts, especially those from users with large followings. Many insert generic questions (marked by question marks) or vague prompts, mimicking engagement while contributing nothing meaningful. As Willison notes, this isn’t just spam — it’s a deliberate attempt to hijack attention and inflate visibility through algorithmic noise.

The detection logic combines simple heuristics with thoughtful design: it checks for clusters of replies posted in rapid succession, absence of original posts (text-only or media), lack of links or images, disproportionate reply-to-follow ratio, and overuse of question marks. Crucially, Willison didn’t write the code manually from scratch. He used Claude Opus 5.5 — Anthropic’s latest high-efficiency model — in what he calls “vibe coding”: prompting the AI with natural-language goals and iteratively refining outputs until the tool worked reliably. The result is a minimal Python script deployed as a fast, serverless web interface.

This project sits at an important intersection: decentralized social infrastructure, rising AI misuse, and pragmatic developer tooling. Bluesky’s AT Protocol was built to support transparency and user agency — including algorithmic choice and self-hosted moderation — yet its openness also lowers the barrier for bad actors. Willison’s tool doesn’t block bots or enforce policy; it empowers users and moderators to spot suspicious behavior quickly. It’s a reminder that effective platform health tools don’t always require massive infrastructure — sometimes, a sharp-eyed developer and a capable LLM are enough.
