uv 0.12.20 improves lockfile reuse and adds preview features for pylock.toml

News time: 2026-09-29T06:51:53.370522+00:00 · Source: github

Astral, the team behind the high-performance Python package manager uv, has released version 0.12.20 — a focused maintenance update that refines reliability, consistency, and ergonomics for teams adopting uv in production workflows. Released on September 28, 2026, this patch builds on uv’s reputation as a Rust-powered, drop-in replacement for pip, pip-tools, and virtualenv — delivering 10–100× speedups while maintaining strict compatibility with existing Python packaging standards.

The most impactful change is smarter lockfile reuse: uv now detects when dependency declarations are semantically equivalent, even if written differently (e.g., requests>=2.28 vs requests>=2.28.0), and reuses cached lockfiles instead of re-resolving. This avoids redundant network calls and computation, especially valuable in CI environments where lockfiles are regenerated frequently. Another subtle but critical fix addresses CRLF line endings in wheel script shebangs: uv now correctly preserves second-line encoding declarations (like # -*- coding: utf-8 -*-) when installing scripts on Windows or mixed-line-ending systems — preventing silent encoding errors during execution.

Several preview features signal uv’s alignment with PEP 751, the newly standardized pylock.toml lock file format. These include normalized requirement output (to reduce spurious diffs), support for synthetic default groups (enabling cleaner workspace-level installs), and resolving local paths relative to the lock file — all aimed at making lockfiles more portable and deterministic. A notable optimization ensures packages are installed only once even when listed multiple times across different tool-install-locks, improving both speed and reproducibility.

Under the hood, uv also restores HTTP cache-write scheduling to avoid severe stalls on ext4 filesystems — a real-world performance regression previously observed in enterprise CI runners. Bug fixes span robustness improvements: stricter hash enforcement under --require-hashes, graceful handling of malformed UTF-16 requirements files, safer Python interpreter discovery, and prevention of panics on whitespace-only inputs or invalid constraints. Together, these changes reflect uv’s maturing philosophy: prioritize correctness and predictability first, then optimize — without sacrificing developer experience.
