Build a lightweight local decision model instead of using LLMs

News time: 2026-10-11T07:08:28.652133+00:00 · Source: hackernews

What if you didn’t need a billion-parameter LLM to classify customer intents, generate quiz questions, or decide between three structured outputs? A new practical guide shows how to build a focused 'decision model' — a small, fast, locally runnable system designed for narrow, repeatable tasks. Unlike general-purpose LLMs, these models skip open-ended text generation and instead map inputs directly to discrete decisions: yes/no, category A/B/C, or one of several templated responses.

The approach centers on simplicity and control. The author walks through training a tiny classifier (e.g., using scikit-learn or ONNX) on domain-specific examples, embedding it with lightweight vector lookups (like SQLite-vec), and deploying it entirely in the browser — no API calls, no cloud dependencies. It’s not about replacing reasoning; it’s about avoiding overengineering when a 50KB model suffices.

Real-world experiments reflect this pragmatism. One commenter adapted 'Laya', a pure decision model, to run in-browser with sub-200ms latency — faster and more reliable than trying to run Qwen locally on mobile. Another built 'Trebek', a Jeopardy-style generator that classifies input as category/question/answer, then fills the missing piece using SQLite-vec embeddings trained on English text — all without touching an LLM decoder.

Critics rightly point out that this isn’t architectural revolution: decision models are classifiers or constrained generators dressed in new terminology. But the value lies in framing and accessibility — lowering the barrier for developers to choose the right tool, not the trendiest one. As one HN user put it: 'I saw Jev and without understanding it said to myself, “I can build that!”' That spark of doability — grounded in SQLite, TypeScript, and browser APIs — is where real adoption begins.
