Anthropic built Scion to handle 30,000 daily merges in AI-driven monorepo

News time: 2026-10-14T06:06:19.192391+00:00 · Source: rss

Anthropic has replaced Git with a custom-built source control system called Scion — not as an experiment, but as an operational necessity. Over just five months, a team of seven engineers designed, built, and fully migrated Anthropic’s massive monorepo to Scion after code merge volume surged from roughly 2,500 per day in May 2026 to over 30,000 per day by early September. This tenfold acceleration wasn’t gradual: the chart accompanying the announcement shows a sharp inflection point in late May, followed by exponential growth — especially after the internal rollout of Fable and Mythos-class models, which appear tightly correlated with the spike in development velocity.

The scale driving this change is staggering. The main branch’s history alone approaches 100 GB; a compressed working copy exceeds 25 GB. With around 25 million automated code checkouts per day — just for CI, excluding developer workspaces, agent sandboxes, and research jobs — naive Git usage would generate over 600 petabytes of network traffic daily. That’s not merely inefficient — it’s operationally unsustainable. Scion addresses this by abandoning Git’s distributed model in favor of a centralized, server-first architecture inspired by Subversion, optimized for high-throughput, low-latency operations within Anthropic’s tightly controlled, always-online infrastructure.

Crucially, Scion was built for Claude — not just by Anthropic engineers. As one engineer noted on Hacker News, offline support wasn’t implemented because Claude, Scion’s heaviest user, is inherently online. The system also integrates tightly with Anthropic’s internal code review workflow, dubbed “Antique,” which replaced traditional pull requests. By mid-July, Antique-based change requests had almost entirely supplanted PRs — reflecting a shift toward lightweight, AI-assisted, asynchronous review cycles.

Still, speed hasn’t eliminated human judgment. The post candidly acknowledges that adversarial review — where Claude critiques its own or others’ code — is powerful but prone to over-engineering hypothetical edge cases. Engineers often find themselves saying “no” to Claude, acting as essential filters and strategic guides. That dynamic raises deeper questions about how engineering roles evolve when AI becomes both the primary author and reviewer — and whether velocity must trade off against long-term maintainability. For now, Anthropic’s answer is clear: when existing tools break at AI-native scale, build what you need — even if it means reinventing version control.
