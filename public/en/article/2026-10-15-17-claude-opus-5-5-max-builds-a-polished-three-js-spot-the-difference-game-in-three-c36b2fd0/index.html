Claude Opus 5.5 Max builds a polished Three.js spot-the-difference game in three hours

News time: 2026-10-15T05:52:01.636122+00:00 · Source: rss

Simon Willison, a well-known developer and AI commentator, has unveiled 'Tree Appreciator' — a fully playable, aesthetically refined web game built entirely by Claude Opus 5.5 Max using only a single natural-language prompt. Unlike typical code-generation demos that produce stubs or broken prototypes, this output is a cohesive, interactive experience: two algorithmically generated 3D maple trees rendered with Three.js, subtle falling-leaf animations, ambient background music, achievement tracking, and responsive UI elements including sound toggle, hints, and reset functionality.

The prompt was deceptively simple: "Build a three js game called 'Tree appreciator' — it shows you two algorithmically generated trees and the game mechanics is about appreciating the differences between them. Think hard about how to make sure it is both fun and beautiful." Willison used the standard Claude iPhone app (not the specialized Claude Code interface), and the model ran autonomously for over three hours before delivering the final result — a rare demonstration of extended, self-directed reasoning in an LLM.

What stands out isn’t just the technical execution — generating valid WebGL code, managing state, handling user input, and integrating audio — but the aesthetic intentionality. The game features warm color palettes, soft lighting, gentle motion, and thoughtful micro-interactions (e.g., leaf particles, golden grass textures, hazy pine-silhouette hills). Willison notes with mild irony that his recent talk on LLM limitations had emphasized how hard it is to elicit ‘fun’ from models — yet here, explicitly asking Claude to “make sure it is fun” yielded precisely that.

While the game is mobile-optimized and visually soothing, it’s also technically ambitious: each tree is procedurally generated with unique branching patterns, leaf distribution, and seasonal coloring. Players identify four differences across pairs — like a missing red mushroom at the base or a patch of green leaves turned red — with scoring, hint usage, and progressive difficulty. It’s not just functional code; it’s code that vibes, as Willison’s tag 'vibe-coding' suggests — a term capturing the emergent ability of top-tier LLMs to infer and embody subjective design values without explicit specification.
