Rust framework DenseCore matches PyTorch bit for bit on nanoGPT

News time: 2026-10-17T05:33:28.244895+00:00 · Source: reddit

A computer science student has built DenseCore — a tiny, experimental deep learning framework in Rust — that achieves exact bit-for-bit numerical equivalence with PyTorch when training nanoGPT. That means identical initial weights (down to the last bit), identical loss values, gradients, and updated parameters across all 50 training steps — even with stochastic components like dropout enabled. This isn’t approximate reproducibility; it’s bitwise identity, verified by comparing raw binary outputs.

Reaching this level of fidelity turned out to be an intense forensic exercise. The developer uncovered subtle but consequential implementation choices buried deep in PyTorch: its CPU attention kernel isn’t textbook softmax-based attention but a Flash Attention variant that changes behavior when dropout is active; its Adam optimizer applies rounding inconsistently at thread boundaries due to compiler loop-fusion artifacts; and clip_grad_norm_ computes norms using reciprocal multiplication instead of division — a seemingly minor detail that alters floating-point outcomes. These aren’t bugs per se, but low-level engineering trade-offs that accumulate into observable numerical divergence.

Even more strikingly, the project revealed that PyTorch itself isn’t cross-platform deterministic: the same version running on macOS (Apple Silicon) versus Linux (x86-64) produced identical results in only 1 out of 26 tested operations. DenseCore therefore only guarantees bit-exact matching on Apple Silicon — not because it’s inherently tied to that hardware, but because it deliberately replicates PyTorch’s observed macOS behavior as ground truth. At just 2 MB, DenseCore is dramatically smaller than PyTorch’s ~580 MB distribution — highlighting how much bloat accumulates in production frameworks.

The creator openly questions whether this effort has practical utility beyond being a rigorous learning exercise. Potential paths forward include expanding DenseCore into a full PyTorch-compatible drop-in for lightweight CPU-only use cases (e.g., CI pipelines or serverless inference), or pivoting it into a debugging tool that pinpoints why two PyTorch runs diverge — essentially turning numerical mismatch into a diagnosable signal. For researchers and engineers who treat reproducibility as non-negotiable, DenseCore isn’t just a curiosity — it’s a microscope for the hidden numerics underpinning modern deep learning.
