A lightweight inline templating trick using document.currentScript

News time: 2026-10-18T05:50:46.328958+00:00 · Source: rss

A clever, dependency-free JavaScript pattern has surfaced for rendering dynamic content directly inside HTML — without frameworks, build steps, or external templates. The technique hinges on document.currentScript, a long-standing but often overlooked DOM API that returns the <script> element currently being executed. Because this property is only available during script execution (and only for classic scripts, not modules), it enables a uniquely simple form of self-replacement: an inline script can locate itself in the DOM and swap out its own node with computed content.

The core idea is deceptively minimal. Consider this snippet embedded directly in HTML:

The year is <script>
document.currentScript.replaceWith(new Date().getFullYear())
</script>

When parsed and run, the script replaces its own <script> tag with the current year as plain text — no wrapper divs, no event listeners, no hydration. It’s synchronous, zero-config, and works even before DOMContentLoaded.

To make it more ergonomic, developers can define a one-liner helper — like $=(...n)=>document.currentScript.replaceWith(...n) — turning the pattern into a tiny, expressive template language. Now the same example becomes <script>$(new Date().getFullYear())</script>. You can embed expressions, function calls, or even small conditional logic — all evaluated at parse time and replaced in-place.

This isn’t a replacement for full-featured templating engines or modern component models. It’s intentionally narrow: best suited for static pages with light dynamic needs — copyright years, environment-aware labels, or debug-mode annotations. Its elegance lies in what it avoids: no bundler, no CSP violations if used carefully, and no runtime overhead beyond a single DOM mutation. Still, it’s worth noting that strict Content Security Policies (CSP) often block inline scripts entirely — so real-world adoption depends on whether your site permits 'unsafe-inline' or uses nonces.

Ultimately, this pattern shines as a teaching tool and micro-optimization. It demonstrates how deeply the platform already supports declarative, lightweight interactivity — if you know where to look.
