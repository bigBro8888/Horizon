Proof before reuse prevents procedural memory poisoning in coding agents

News time: 2026-10-19T06:08:52.621605+00:00 · Source: reddit

A new safety technique called 'proof before reuse' has demonstrated complete prevention of procedural memory poisoning in LLM-based coding agents. In a tightly controlled case study, researchers injected a subtle poison—a single unrelated line of code—into one learning session. While baseline methods like naive memory retention or replaying past edits consistently reintroduced the poison into subsequent agent behavior (30/30 and 3/30 exposures respectively), proof before reuse required two independent later sessions to reproduce the exact same code change and pass its test before that skill could be stored and served. Crucially, the agent was shown only the lines common across those two clean reproductions, filtering out any divergent or suspicious additions—even when the poisoned line passed step-level validation.

The experiment used Claude Haiku 5.5 and Sonnet 5.5 across five scored sessions per condition, with a hidden verifier running 187 behavioral checks to detect exposure. All data—including per-session records, prompts, and evaluation logic—is publicly available on GitHub. Unlike many AI safety proposals, this isn’t theoretical: it’s empirically validated, reproducible, and built into an open implementation named MuscleMemory. The method targets a concrete failure mode: when agents learn from their own past successes, they risk amplifying errors or malicious edits that happen to pass surface-level tests.

Still, the approach has clear boundaries. It only guards against poisoning introduced during agent learning sessions, not against malicious code already present in the repository itself—a limitation explicitly acknowledged in the paper. The evaluation also focused on a single coding task, used small sample sizes (n=5 per arm), and tuned filtering rules on the same task, meaning generalizability remains to be tested. Importantly, the metric measured exposure (did the agent see the poison?) not harm (did it execute or propagate it?)—though no model applied a poison it merely observed.

This work reframes memory integrity as a verification problem rather than a retrieval problem. Instead of asking "What did we learn before?", it asks "What have we reliably reconstructed more than once?" That shift—from recollection to reproducibility—offers a promising, lightweight, and empirically grounded defense for agentic systems where procedural memory is both essential and vulnerable.
