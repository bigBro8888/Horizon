llm-echo 0.5 adds realistic token simulation for system prompts and tool calls

News time: 2026-10-19T06:08:52.095851+00:00 · Source: rss

Simon Willison has released llm-echo 0.5, a refined version of his lightweight debugging plugin for LLM developers. Unlike real language models, llm-echo doesn’t generate responses or call APIs — it simply echoes back the full request structure as JSON, making it ideal for local testing and CI workflows where you need to verify prompt formatting, parameter handling, or integration logic without incurring API costs or latency.

This update significantly improves fidelity by simulating token usage more realistically. Earlier versions reported only basic input/output token counts based on raw text. Now, llm-echo 0.5 accounts for three previously ignored components: system prompts (even empty ones), structured tool call definitions (e.g., function schemas), and reasoning tokens — such as those generated when using the --thinking flag to simulate chain-of-thought behavior. The result is a token count that closely mirrors what a real model like GPT-4 or Claude would report for the same request.

For example, running uvx --with llm-echo llm -m echo 'hi there' -o thinking 1 --usage now outputs not just the echoed prompt but also a breakdown like Token usage: 2 input, 24 output, where those 24 output tokens include simulated reasoning steps and metadata overhead. This granularity helps developers catch token budget overruns early — especially critical when building agents that make multiple tool calls or use verbose system instructions.

The change reflects a broader shift in LLM tooling: from treating models as black boxes to modeling their operational constraints — like token limits, context windows, and cost-per-call — even during local development. Because llm-echo integrates seamlessly with the llm CLI ecosystem (a popular open-source toolkit for managing LLMs locally), this update benefits anyone using llm plugins for prototyping, testing, or teaching. It’s not flashy, but it removes guesswork from one of the most tedious parts of LLM engineering: estimating usage before deployment.
