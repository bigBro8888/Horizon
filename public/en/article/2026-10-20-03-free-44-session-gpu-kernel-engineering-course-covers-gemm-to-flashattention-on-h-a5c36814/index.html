Free 44-session GPU kernel engineering course covers GEMM to FlashAttention on H100 and Blackwell

News time: 2026-10-20T05:59:16.344811+00:00 · Source: reddit

A new open educational series is filling a critical gap in systems-aware machine learning training: practical, code-first GPU kernel engineering. Created by an independent instructor (Reddit user /u/Winter_Mistake_3185), the series launches with a clear pedagogical thesis — for most ML kernels, performance bottlenecks are rooted in data movement, not raw compute. Rather than diving straight into low-level assembly or vendor-specific APIs, the course anchors every optimization decision in the roofline model: a visual framework that plots achievable performance as the minimum of peak compute throughput and memory bandwidth multiplied by arithmetic intensity (FLOPs per byte moved). This lets learners instantly diagnose whether a kernel is memory-bound or compute-bound — and thus where to focus their tuning efforts.

The curriculum unfolds across 44 structured sessions, progressing deliberately from fundamentals to frontier techniques. It begins with CPU parallelism and GPU architecture basics, then builds up to handwritten CUDA kernels for matrix multiplication (GEMM), profiling each iteration to quantify speedups. Later modules introduce tensor cores, PyTorch-CUDA interop, and Triton — before culminating in a live, step-by-step implementation of FlashAttention. Crucially, FlashAttention isn’t presented as magic: the course explains how its tiling strategy avoids materializing the full N×N attention score matrix in high-bandwidth memory (HBM), slashing memory traffic by keeping intermediate values in fast on-chip SRAM.

The series extends beyond legacy hardware, dedicating significant time to NVIDIA’s latest architectures: Hopper (H100) and Blackwell. Topics include Tensor Memory Accelerator (TMA), WGMMA instructions, FP8 and NVFP4 quantization, multi-GPU scaling, and even experimental features like AI-assisted kernel generation. Each session follows the same rhythm: concept → live coding → profiling → validation against a baseline. Prerequisites are modest — C/C++, basic linear algebra, and PyTorch familiarity — making it accessible to ML engineers and researchers eager to move beyond black-box frameworks.

What sets this apart is its unflinching commitment to transparency and execution. The code is public, the reasoning is explicit, and the roadmap is shared openly — including caveats that later Blackwell-focused sessions may evolve as tooling matures. For practitioners tired of fragmented tutorials or opaque vendor documentation, this series offers a rare, coherent, and deeply technical path from first principles to production-grade GPU optimization.
