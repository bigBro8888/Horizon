uv 0.13.3 fixes severe export slowdown with extras

News time: 2026-10-20T05:59:17.059789+00:00 · Source: github

The Rust-based Python package manager uv has released version 0.13.3, a targeted patch addressing a serious performance regression in the uv export command. Users working with complex dependency graphs that include optional features—known as "extras" in Python packaging—had recently experienced dramatic slowdowns when generating lock files or exporting dependencies. This issue, tracked as PR #22750, caused uv export to take orders of magnitude longer than expected in certain real-world projects, undermining one of uv’s core value propositions: speed.

uv is widely adopted as a high-performance alternative to pip and pip-tools, often touted as 10–100× faster for dependency resolution and installation. It’s designed as a drop-in replacement for common Python tooling—including pip, pip-compile, virtualenv, and pipx—and is built by Astral, the team behind the popular Ruff linter. Its resolver uses PubGrub, and it relies on aggressive caching and native Rust performance to achieve its speed advantage. The uv export command specifically converts resolved dependency graphs (e.g., from uv lock) into formats like requirements.txt, often used for CI, deployment, or reproducible environments.

The regression affected workflows where packages declared extras—such as requests[security] or django[argon2]—and those extras triggered deep or overlapping transitive dependencies. In such cases, the resolver’s export logic previously re-evaluated dependency constraints repeatedly, leading to exponential time complexity in worst-case scenarios. The fix in 0.13.3 optimizes how extras are traversed and deduplicated during export, restoring linear or near-linear performance across large graphs.

This release does not introduce new features or change uv’s interface—it’s strictly a correctness-and-performance patch. Prebuilt binaries are available for 13 platforms, including Apple Silicon, x86_64 and ARM64 Windows, multiple Linux architectures (x86, ARM64, RISC-V, s390x, PPC64LE), and musl-based systems. Installation remains frictionless via curl or PowerShell scripts, reinforcing uv’s goal of being a zero-dependency, single-binary tool. For developers relying on uv export in automation pipelines or monorepo setups, upgrading to 0.13.3 delivers immediate, tangible relief without requiring workflow changes.
