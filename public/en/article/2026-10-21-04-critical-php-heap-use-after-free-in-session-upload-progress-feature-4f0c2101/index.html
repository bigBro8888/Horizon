Critical PHP heap use-after-free in session upload progress feature

News time: 2026-10-21T05:59:49.235106+00:00 · Source: hackernews

A critical heap use-after-free (UAF) vulnerability has been disclosed in PHP’s session.upload_progress functionality, tracked as CVE-2026-109618 and CVE-2026-109619. The flaw resides in how PHP handles multipart/form-data POST requests when the upload progress tracking feature is enabled — specifically during memory reallocation and cleanup of internal upload state structures. Attackers who can trigger specially crafted file uploads may exploit this UAF to achieve remote code execution on affected servers, making it especially dangerous for shared hosting environments or applications that accept file uploads without strict input validation.

The vulnerability is not theoretical: multiple security practitioners report active investigation and mitigation efforts. One researcher confirmed they are mirroring live HTTP traffic to detect exploitation attempts, while others emphasize that the issue is not related to an embargoed vulnerability recently discussed by PHP core developers — clarifying confusion in early reports. According to a PHP maintainer’s public post, this is a distinct, independently discovered flaw requiring immediate attention.

Mitigation strategies vary in practicality and scope. Disabling the feature entirely via session.upload_progress.enabled = Off in php.ini is the most direct fix — but only viable if the application does not rely on upload progress feedback. For sites that must retain uploads, enforcing strict SELinux or AppArmor policies has emerged as a widely recommended stopgap, limiting the damage potential of any successful exploitation. Some administrators also ask whether multipart handling itself can be disabled at the web server level (e.g., via Nginx or Apache configuration), though PHP’s parser still processes the request headers before rejecting the body — meaning full prevention requires coordination across layers.

What makes this vulnerability particularly urgent is its placement in a default-enabled, low-overhead feature used by many frameworks and CMSes. Unlike obscure extensions, session.upload_progress is part of PHP’s core session subsystem and often left enabled without review. With no official patch yet released (as of the latest public update), defenders are relying on configuration hardening, runtime protections, and behavioral detection — underscoring how deeply embedded features can become attack surfaces when memory safety isn’t rigorously enforced.
