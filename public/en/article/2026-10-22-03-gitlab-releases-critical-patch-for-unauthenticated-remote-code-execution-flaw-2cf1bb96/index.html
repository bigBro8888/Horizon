GitLab releases critical patch for unauthenticated remote code execution flaw

News time: 2026-10-22T06:05:39.885640+00:00 · Source: hackernews

GitLab has issued an urgent security patch—version 19.5.1—to address a critical unauthenticated remote code execution (RCE) vulnerability. The flaw, rooted in a regex-related parsing issue, allows attackers to execute arbitrary code on affected GitLab instances without requiring any authentication. This means threat actors could compromise servers simply by sending a maliciously crafted HTTP request to exposed endpoints—a particularly dangerous scenario for self-hosted GitLab deployments exposed to the internet.

The vulnerability was responsibly disclosed via HackerOne by researcher joaxcar, who identified how specially constructed input could trigger unsafe behavior during regex processing within GitLab’s web interface. Unlike many RCE flaws that require login or privilege escalation, this one sits at the outermost layer of the application stack—making it both highly exploitable and broadly impactful. GitLab’s advisory confirms the issue affects all versions prior to 19.5.1 and recommends immediate upgrading, especially for installations with public network exposure.

What makes this patch especially notable is its context: it’s at least the second regex-related CVE in GitLab within recent weeks. Past incidents—including the infamous CVE-2021-22205, which also involved image metadata parsing and regex engine abuse—highlight recurring risks in how GitLab handles untrusted input during pattern matching. While Ruby’s built-in Regexp engine is generally robust, custom regex compilation logic or third-party libraries integrated into GitLab may introduce edge cases where catastrophic backtracking or stack exhaustion occurs.

GitLab has provided operational guidance to help administrators detect potential exploitation attempts—including log patterns to search for in nginx or GitLab Rails logs—and confirmed that mitigation via configuration alone is not possible; patching remains the only reliable fix. For large-scale deployments, community members have shared pragmatic tips like using gitlab-rake gitlab:env:info to quickly verify version numbers across nodes before rolling out updates. Given the severity and ease of exploitation, security teams are urged to treat this as high-priority remediation—not just another routine update.
