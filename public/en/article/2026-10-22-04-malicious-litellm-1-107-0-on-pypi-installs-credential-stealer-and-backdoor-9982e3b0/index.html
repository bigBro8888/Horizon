Malicious LiteLLM 1.107.0 on PyPI installs credential stealer and backdoor

News time: 2026-10-22T06:05:39.885674+00:00 · Source: hackernews

A compromised version of LiteLLM — specifically package version 1.107.0 uploaded to PyPI — has been confirmed to install a credential-stealing payload and establish a persistent backdoor on infected systems. Security researchers at SafeDep.io discovered the malicious package on October 21, 2026, and quickly alerted the maintainers. The package appeared legitimate: it matched LiteLLM’s usual release cadence, used correct naming conventions, and passed basic signature checks — making it especially dangerous in automated CI/CD pipelines and developer workflows where packages are pulled without manual inspection.

LiteLLM is a widely adopted open-source LLM orchestration tool developed by BerriAI. It serves as both a Python SDK and an API gateway, enabling developers to route prompts across over 100 LLM providers (like OpenAI, Anthropic, and Groq) using a unified OpenAI-compatible interface. With more than 55,000 commits in three years and heavy usage in production AI applications, its compromise represents one of the most consequential supply-chain attacks targeting the LLM ecosystem this year.

The malicious version executed stealthy post-install behavior: it fetched and ran obfuscated shell scripts from external domains, harvested environment variables (including API keys), exfiltrated credentials via HTTP POST requests, and spawned a reverse shell for remote command execution. Notably, the payload avoided common detection heuristics — such as sleeping before execution or checking for sandboxed environments — suggesting deliberate evasion engineering. The incident was contained within hours, and PyPI administrators yanked the package; official LiteLLM maintainers issued a security advisory and urged users to upgrade to 1.107.1 or later.

This attack follows at least one prior supply-chain incident involving LiteLLM earlier in 2026, underscoring systemic risks in fast-moving AI infrastructure projects. Community discussion highlighted fatigue around permission prompts, normalization of excessive dependencies, and gaps in automated dependency hygiene. Experts stress that signing packages with twine --sign, enforcing two-factor authentication on PyPI accounts, and adopting lockfiles with hash verification are essential — but still insufficient without human-in-the-loop review for high-impact libraries.
