uv 0.13.5 removes compromised eMudhra root certificate from Python builds

News time: 2026-10-22T06:05:40.662294+00:00 · Source: github

The uv team has released version 0.13.5, a security-critical maintenance update that proactively removes the compromised eMudhra/emSign root certificate from all managed Python interpreter builds and bundled tooling. Released on October 21, 2026, this version updates uv’s prebuilt CPython distributions — including newly patched versions 3.13.17, 3.14.9, and 3.15.1 — to use python-build-standalone 20261021, which incorporates pip 26.2.2 and certifi 2026.10.19. Both the embedded pip and the one installed via python -m venv now rely on this updated certifi bundle, ensuring SSL/TLS verification no longer trusts the revoked eMudhra intermediates.

This release follows uv 0.13.4, which had already purged the problematic root from uv’s own internal certificate store. Now, the fix extends deeper into the Python runtime layer: every new virtual environment created with uv python install or uv venv will inherit the secure configuration by default. Users are explicitly advised to run uv python upgrade after updating uv to pull in the latest patched interpreters. Importantly, existing virtual environments remain unchanged — they retain their original Python binaries and certificate bundles unless manually upgraded.

Beyond security, uv 0.13.5 delivers measurable performance improvements: reduced peak memory during multi-environment dependency resolution, faster exports with complex optional dependencies (extras), and a smaller binary size thanks to optimized error formatting. A new preview feature — wheel-variants — begins supporting PEP 850 static providers for more precise wheel selection in platform-specific contexts. Several bug fixes also land, including correct handling of Android-only wheels and improved export logic for transitive extras activated across incompatible environment paths.

The release also signals a firm end-of-life stance: uv will no longer publish Docker images based on Python 3.9 or 3.10, both of which remain vulnerable due to upstream pip versions that still bundle the compromised certificate. The team urges users to migrate to supported Python versions. For operators relying on uv’s speed and reliability, this update is not just recommended — it’s essential for maintaining trust in HTTPS-based package installation and index communication.
