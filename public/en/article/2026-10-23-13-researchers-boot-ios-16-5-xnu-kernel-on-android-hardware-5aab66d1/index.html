Researchers boot iOS 16.5 XNU kernel on Android hardware

News time: 2026-10-23T06:00:37.664710+00:00 · Source: hackernews

A team of reverse-engineering researchers has achieved a notable technical milestone: running the iOS 16.5 XNU kernel — the core of Apple’s operating system — directly on off-the-shelf Android devices, including the POCO X5 Pro 5G and several Xiaomi models. This is not emulation in a virtual machine nor a user-facing ROM replacement; instead, it’s a low-level port that boots the actual XNU kernel binary using custom UEFI loaders and QEMU-based test environments. The project, named hackios-xnu-kernel, focuses exclusively on kernel initialization and early-stage execution — no iOS user interface, apps, or drivers are present.

The approach relies on device tree spoofing: the researchers generate a fake iPhone X device tree that tricks the iOS kernel into believing it’s running on genuine Apple hardware. This bypasses early hardware checks baked into XNU, allowing the kernel to proceed past boot-time validation. The system runs for a fixed duration (e.g., 30 seconds), logs its execution state, then cleanly hands control back to the bootloader — reinforcing its role as a research benchmark rather than a functional OS.

This effort sits squarely in the domain of kernel portability research. Unlike traditional Android custom ROMs — which replace the Linux kernel with another Linux kernel — hackios-xnu-kernel replaces Android’s Linux kernel with Apple’s hybrid XNU kernel (Mach + BSD + I/O Kit). That requires deep understanding of both kernel ABIs, memory management, interrupt handling, and platform firmware interfaces. The GitHub repository includes patched XNU source, UEFI loader code, QEMU launch scripts, and prebuilt binaries — all open for inspection and extension.

Security researchers have taken particular interest. Because XNU was never designed to run outside Apple’s tightly controlled silicon ecosystem, unexpected behaviors — such as unhandled exceptions, memory corruption vectors, or firmware interaction flaws — could reveal latent vulnerabilities. As one commenter noted, this isn’t about building an iOS phone clone; it’s about stress-testing assumptions in Apple’s kernel hardening and exposing where market-driven restrictions (e.g., feature gating via software) diverge from real hardware limits. For developers and academics, it’s a rare window into how far cross-platform kernel reuse can go — and where it inevitably breaks down.
